**Status as reviewed 16 November 2026, approximately 12:16 UTC: no academically established strong-obfuscation or hostile-runtime tamper-resistance result.** This directory is reserved for independently reproducible, defensible results that materially establish the project objective. No candidate has yet met that standard. See the [project implementation and explicit operational limits](../README.md) and [threat-model boundaries](../docs/SECURITY.md).

## What is actually supported

The repository provides runnable COO (client-only), SNO (server-only, no live obfuscator control), and SCO (server-controlled) entry points. Its bounded compiler-safety regressions, cross-platform native/generated comparisons, and Chromium integration demonstrate **tested behavior preservation for selected programs**. They do not establish general observational equivalence, strong deobfuscation resistance, or a universal **2.5×** runtime guarantee.

- **COO:** The client receives the full executable output. Independent source-only attacks have reconstructed tested numeric, property-label, control-flow, Wasm, and string transformations. See the [comparative decision matrix](../im-results/decision-matrix-2026-11-15.md), [public static string recovery](../im-results/jsdeobsbench-public-static-recovery-2026-11-16.md), and [transformed polyvariant application attacker](../im-results/polyvariant-app-attack-cost-2026-11-16.md). Conservative proof guards sometimes refuse the entire source group. The [six-module frozen original](../im-results/application-challenge-refusal-2026-11-16.md) must remain distinct from any modified positive-control application.
- **SNO:** The owner has the deployed files, loader and memory. [A genuinely transformed application](../im-results/polyvariant-app-sno-attack-cost-2026-11-16.md) retained source-only reconstruction and successful integrity bypass, including an ESM runtime hook. Local manifest checks are useful for incidental corruption, not an owner-proof authorization boundary.
- **SCO:** A trusted server can withhold source and cryptographic material from clients. An attacker with unlimited legitimate requests can still relay tested services without recovering the key; see the [frozen-application relay](../im-results/application-challenge-sco-source-relay-2026-11-16.md) and [account-scoped relay evidence](../im-results/sco-audience-bound-relay-2026-11-16.md). Remote calls pass **2.5×** only for some measured operation granularities. Genuine source withholding and functional anti-cloning require separate claims.

These are scoped engineering and adversarial observations preserved in **[intermediate results](../im-results/)**. Counts of tests, changed identifiers, emitted bytes, seed variants or CI runs are not themselves measures of protection. An attack not attempted is unmeasured rather than defeated.

## Evidence required before promotion

A proposed result should link to immutable native and actually emitted multi-file code, an explicit contract for external APIs/reflection, measurable fraction of **original protected behavior transformed or kept server-side**, real native/emitted differential tests, reproducible **independent** static and runtime attackers with identical budgets against native/minified controls, and short/sustained whole-session **2.5×** measurements. COO startup counts; SCO client-side authorization, network and latency count; only eligible SCO/SNO server initialization may be amortized. Document the exact SHA, runners and unresolved threat capabilities. Keep a positive transformed-work control alongside every fail-closed semantic regression.
