# Established research results

No peer-review-level or independently reproduced obfuscation-security result has yet been established. This directory remains intentionally empty of asserted discoveries. The Node.js SCO, COO, and SNO prototype and its limits are described in [the root README](../README.md) and [the threat-model boundaries](../docs/SECURITY.md). Experimental software behavior, counterexamples, and measurements belong in `im-results/` until evidence supports promotion.

## Current intermediate decision evidence

The [architecture decision matrix](../im-results/decision-matrix-2026-11-15.md) is the principal comparative entry point. It records pinned source, executable attackers, compatible transformations, protected-work and application overhead, and decisions for the main AST compiler, the independent checker compiler, the experimental public postfix VM, and SCO server-private RPC. Its [three-file ESM comparison](../im-results/decision-attack-grid-2026-11-15.md) supplies a controlled cross-platform challenge with native behavior and attack scripts. The [historical mode threat scorecard](../im-results/mode-threat-scorecard-2026-11-15.md) remains useful context, but its 205-test and five-Chrome-fixture snapshot has been superseded by later validation. It should not be treated as the newest release status.

Subsequent experiments sharpen the decision. [Runtime decoder extraction](../im-results/runtime-decoder-extraction-2026-11-15.md) demonstrates native Node and Chromium interception of the eager XOR decoder, including a dormant string literal. [Source-observer regression and coverage evidence](../im-results/source-observer-proof-coverage-2026-11-15.md) documents a passing cross-platform repair and the coverage sacrificed by a whole-group refusal guard. The [typed numeric WebAssembly candidate](../im-results/wasm-numeric-candidate-2026-11-15.md) reports exact numeric differential checks, executable copying from distributed Wasm bytes, a hot-work result within the budget, and cold-start cases exceeding 2.5×. It remains an isolated experimental backend, as its report states. [SCO polynomial-oracle reconstruction](../im-results/sco-polynomial-oracle-2026-11-15.md) independently measures chosen-input functional reconstruction despite keeping implementation source server-private.


## Frozen application-scale attack/cost comparison (16 November)

The [six-module frozen application challenge](../examples/application-challenge/README.md)
supplies exact native and compiler-delivered COO source pairs, a reproducible
cross-module source-observer refusal with 0/2 private fields renamed,
and a genuine SCO server-private async boundary that distributes a
515-byte facade in place of five private implementation modules.
The [comparative decision matrix](../im-results/decision-matrix-2026-11-15.md)
now includes the full attack and cost table. The [COO application report](../im-results/application-challenge-refusal-2026-11-16.md)
and [SCO loopback relay report](../im-results/application-challenge-sco-source-relay-2026-11-16.md)
retain pinned Ubuntu/Windows source SHAs, executable held-out
functional attacks, code-withholding checks, and separate hot,
client-cold and thin-operation overhead. The SCO source stays private
but an unlimited legitimate client can reproduce outputs by relaying
calls to the real server. None of these intermediate observations
establishes a general obfuscation-security theorem or full-mode
performance guarantee.

The [SNO six-module counterpart](../im-results/application-challenge-sno-owner-attack-2026-11-16.md)
uses the frozen application under an actual single-entry CommonJS launcher;
all 85/85 cases matched, although the compiler's source-observer proof
left its 2,786 original application bytes unchanged. The independently
executed public-files attacker copied and ran all distributed modules,
then rewrote its own public SHA-256 manifest to execute changed code.
The [transformed three-module SNO comparison](../im-results/polyvariant-app-sno-attack-cost-2026-11-16.md)
improves on this no-transform control: three arithmetic functions were
genuinely lowered into six public paths and emitted 7,495 bytes from
2,467 original source bytes. All 96 application cases matched on
Ubuntu and Windows at [exact pinned gate 43814631907](https://github.com/FlareZ123/obfs/actions/runs/43814631907).
Independent source-only recovery reconstructed all three affine leaves
and passed 12,288 typed checks; an independent full-file copy and
manifest-bypass attack also succeeded. A separate Node 22 ESM load-hook
attacker changed the computation to a chosen value after successful
on-disk digest checks with **zero changed published files**. Eight tested whole-process
medians met 2.5x, but this is **negative attacker-cost evidence** for
a narrow transformed island, not protection against a filesystem owner.
Both SNO studies remain intermediate engineering research.

## Newly reproduced evidence and unresolved coverage

The [external JsDeObsBench differential study](../im-results/jsdeobsbench-adapter-2026-11-15.md) compiled a pinned corpus of **1,301** public CodeNet-style JavaScript programs in COO script, SNO script, and SNO CommonJS modes. Pinned [three-lane run 43704598450](https://github.com/FlareZ123/obfs/actions/runs/43704598450) matched the **2,199 executable original cases** in each lane out of 2,200 selected official cases; the complete upstream corpus offers 2,984 cases, so 784 published inputs were untested. The same experiment counted **zero renamed private-property keys** in all three modes, despite nonzero identifier changes and SNO literal encodings. This is valuable independent compatibility evidence, with minimal coverage of the project's central cross-file property-flow requirement and no measured reconstruction resistance. A later seeded [run 43706326751](https://github.com/FlareZ123/obfs/actions/runs/43706326751) passed all three lanes after a Math.random-dependent comparison had exposed a nondeterministic baseline confounder. These results must not be treated as a hot-path performance bound or full JavaScript semantic proof.

A [paired original-source asset disclosure attack](../im-results/asset-source-disclosure-2026-11-15.md) demonstrated that an older output pipeline copied source maps, inline HTML and disguised transpiler inputs, exposing the original canary without attacking the obfuscated program. The updated policy rejects those tested cases in all three modes, with a [green paired Linux/Windows attack run 43706739931](https://github.com/FlareZ123/obfs/actions/runs/43706739931). It is a bounded build/serve refusal improvement; it says nothing about hostile-runtime integrity or recovering the remaining delivered JavaScript. Later SVG and encoding changes require their own integration validation.

The [held-out multi-file object-flow attack](../im-results/heldout-object-flow-attack-2026-11-15.md) measures a different dimension from CodeNet compatibility: a pinned 30-graph, 96-file ESM experiment produced 18 private-property renames out of 60 candidate fields, with 21 deliberately refused graphs. Its independent source-only normalizer erased all **18/18** generated hashed labels while preserving all 30 observed native outputs. This is measured coverage and a negative static-resistance result, not a protected algorithm reconstruction benchmark or a measured 2.5x application result. The [stateful SCO oracle study](../im-results/sco-stateful-oracle-2026-11-15.md) learned four restricted four-state private machines through their actual authenticated RPC facades using permitted calls and exactly matched 8,184 held-out binary sequences. This extends the scope of black-box learning counterexamples while leaving high-entropy, unbounded, nonresettable and cryptographic cases untested. Both studies belong in intermediate evidence, and neither improves the project's current security release claim. The [diversified step-only SCO oracle study](../im-results/sco-diversified-sync-observability-2026-11-15.md) extends the stateful attack to a genuine Chromium-generated facade, independent behavioral partition-refinement validation, four 1,000-machine corpora, and 4/6/8/12-state and query-depth sweeps. It includes an explicit unreachable-state identification impossibility witness and retained false-positive counterexamples. The latest [focused Ubuntu/Windows run 43758355428](https://github.com/FlareZ123/obfs/actions/runs/43758355428) passed at exact source `dceeff7e78a85e88e8864b8861c0e5e9bc14b2cd`. These are finite attacker-coverage measurements; they establish no general authentication or tamper-resistance guarantee.

## Current interprocedural field-flow coverage and limits

The latest [local-reader and nested ESM proof study](../im-results/local-reader-interprocedural-2026-11-15.md) and [forwarded-destructuring study](../im-results/forwarded-destructuring-2026-11-15.md) extend conservative property ownership across immutable local readers, nested direct identity returns, and immediately destructured proven returns. Both include actual compiler-generated source pairs, negative escape/reflection tests, native Node graphs, live browser contracts, and measured hot-work loops. A deterministic 36-graph ESM grid transformed **24 private fields across 12 eligible graphs**, declined **24 unproved graphs**, and matched original native outputs in every case. The independent seedless static label-normalizer removed all **24/24** public key labels in that grid. The [full Linux/Windows validation 43729620903](https://github.com/FlareZ123/obfs/actions/runs/43729620903) at source commit `2c8d52af0eccb07810659e8279a4eb28e40de805` passed **866/867 tests (one skip), strict type checks, sampled benchmarks, and real Ubuntu Chromium**. The forwarded-pattern hot-loop cost was **1.000× Ubuntu / 0.983× Windows** on that run. These are intermediate evidence of greater safe transformation coverage and measured budget compliance **for a specific workload**, with an explicit failed reconstruction-resistance negative control. They are not a new publishable security result or proof for arbitrary JavaScript.

For new architecture claims, update the comparative evidence with exact commit, workload, native semantic contract, transformed coverage, independent attacker success, setup/runtime separation, and measured 2.5× compliance. Keep negative controls and counterexamples. Reserve cross-platform full-suite manual CI for coherent integration gates, preserving the repository rule against per-commit workflows.
