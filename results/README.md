## Selected arithmetic hot-work budget counterexample, 18 November 2026

An explicitly isolated SNO repeated-compute experiment showed that application-level medians can conceal a severe cost in the selected source functions. The [exact-source Node22 Linux/Windows resident hot-path gate 44208868147](https://github.com/FlareZ123/obfs/actions/runs/44208868147), with the real manifest-checked startup and identical native/protected output digests, measured **52/52 strict CPU pairs over 2.5×** for the original full affine/polyvariant lowerer. Selected-leaf CPU median ratios ranged from **17.6× to 31.2×**; the same runner's full stateful application groups showed substantially lower overhead. The source-only attack already reconstructs all selected arithmetic functions. [Reproducible intermediate evidence](../im-results/polyvariant-selected-hotpath-budget-veto-2026-11-18.md).

A separate compact case encoding reduced typical measured arithmetic overhead while retaining trivial public recovery. The [longer Ubuntu/Windows gate 44210744630](https://github.com/FlareZ123/obfs/actions/runs/44210744630) observed **11/13 strict Windows CPU breaches and a 2.759× median** at 400 million selected-chain iterations, with two additional strict Ubuntu breaches. A [second exact-source Linux/Windows run 44212698981](https://github.com/FlareZ123/obfs/actions/runs/44212698981) measured **1.857× Windows median** on the corresponding hot path and **1/52 Ubuntu selected-hot strict breaches**, plus **2 Windows complete-application strict breaches**. This variability prevents claiming a stable Windows median violation, while the strict observed budget and static-recovery stoplines remain. The original full-affine 52/52 selected-hot overbudget observation replicated on both platforms. The compiler then passed a [384-source, 49,920-observation deterministic cross-platform semantic fuzz](https://github.com/FlareZ123/obfs/actions/runs/44211601578), confirming bounded arithmetic correctness while leaving the strict budget and static-security failures intact. [Scoped compact evidence](../im-results/polyvariant-compact-critical-path-2026-11-18.md).

**Candidate-selection consequence:** Both experimental polyvariant representations remain unsuitable as general strong protections under the requested 2.5× hard compute ceiling. Whole-application, cold Node startup and warmed selected-critical-path CPU each require explicit measurement boundaries. This is reproducible negative evaluation and compiler-safety context, without an academically established strong-obfuscation construction. The overall COO/SNO/SCO release verdict remains blocked.

## What is actually supported

The repository provides runnable COO (client-only), SNO (server-only, no live obfuscator control), and SCO (server-controlled) entry points. Its bounded compiler-safety regressions, cross-platform native/generated comparisons, and Chromium integration demonstrate **tested behavior preservation for selected programs**. They do not establish general observational equivalence, strong deobfuscation resistance, or a universal **2.5×** runtime guarantee.

- **COO:** The client receives the full executable output. Independent source-only attacks have reconstructed tested numeric, property-label, control-flow, Wasm, and string transformations. See the [comparative decision matrix](../im-results/decision-matrix-2026-11-15.md), [public static string recovery](../im-results/jsdeobsbench-public-static-recovery-2026-11-16.md), and [transformed polyvariant application attacker](../im-results/polyvariant-app-attack-cost-2026-11-16.md). Conservative proof guards sometimes refuse the entire source group. The [six-module frozen original](../im-results/application-challenge-refusal-2026-11-16.md) must remain distinct from any modified positive-control application.
- **SNO:** The owner has the deployed files, loader and memory. [A genuinely transformed application](../im-results/polyvariant-app-sno-attack-cost-2026-11-16.md) retained source-only reconstruction and successful integrity bypass, including an ESM runtime hook. Local manifest checks are useful for incidental corruption, not an owner-proof authorization boundary.
- **SCO:** A trusted server can withhold source and cryptographic material from clients. An attacker with unlimited legitimate requests can still relay tested services without recovering the key; see the [frozen-application relay](../im-results/application-challenge-sco-source-relay-2026-11-16.md) and [account-scoped relay evidence](../im-results/sco-audience-bound-relay-2026-11-16.md). An [initialized, real authenticated private-graph CPU profile](../im-results/sco-resident-process-cpu-2026-11-18.md) independently demonstrated **13/13 strict >2.5× CPU pairs on both OSes** at 12,288 separate 1,000-iteration calls, and no strict breaches at 120,000 iterations per call. An [explicit 1,024-call batch candidate](../im-results/sco-bounded-real-batch-cpu-2026-11-18.md) amortized the same private operation over 24,576 calls with **0/51 sampled 2.5× CPU breaches on each OS** in the latest source-pinned run, subject to authenticated per-batch work admission. This opt-in optimization neither proves a worst-case bound nor automatically preserves arbitrary async scheduling or JavaScript object identity: the tested JSON RPC loses an own `undefined` field relative to its raw native object. [Actual negative control](../test/sco-json-shape-contract.test.js). Genuine source withholding, environment authorization, and resistance to legitimate online functional relay remain independent security claims.

These are scoped engineering and adversarial observations preserved in **[intermediate results](../im-results/)**. Counts of tests, changed identifiers, emitted bytes, seed variants or CI runs are not themselves measures of protection. An attack not attempted is unmeasured rather than defeated.

## Evidence required before promotion

A proposed result should link to immutable native and actually emitted multi-file code, an explicit contract for external APIs/reflection, measurable fraction of **original protected behavior transformed or kept server-side**, real native/emitted differential tests, reproducible **independent** static and runtime attackers with identical budgets against native/minified controls, and short/sustained whole-session **2.5×** measurements. COO startup counts; SCO client-side authorization, network and latency count; only eligible SCO/SNO server initialization may be amortized. Document the exact SHA, runners and unresolved threat capabilities. Keep a positive transformed-work control alongside every fail-closed semantic regression.
