# Research decision index

**Assessment: 18 November 2026. No academically established strong-obfuscation, universal environment-locking, or hostile-runtime tamper-resistance result has been demonstrated.** The repository implements a testable Node.js/modern-browser obfuscator with three modes. Its substantial compatibility evidence is a real engineering achievement, but it does not satisfy the primary adversarial objective. This directory contains only this decision index until a reproducible result meets the [promotion standard](#promotion-standard).

## Present release decision

**RELEASE-BLOCKED for the primary strong-protection objective.** A source-pinned, two-platform [12-population adversarial release run 44224382333](https://github.com/FlareZ123/obfs/actions/runs/44224382333) at `6fb49c7a8bf78f66317264593dfbe1753525d5b1` observed **35 strict compute-overhead breaches of 2.5× on each OS**, with tested maxima of 31.72× on Ubuntu and 44.84× on Windows. Its executable attackers recovered selected COO/SNO functions and relayed authorized SCO behavior. This is a bounded negative decision for its actual artifacts and workloads; it is not a theorem about all JavaScript programs. The [12-population gate implementation](../sims/release-evidence-gate.js) and [underlying cross-mode report](../im-results/strict-overbudget-tail-bound-2026-11-17.md) preserve independent security and runtime axes.

The **latest complete correctness integration cited here**, [run 44223494622](https://github.com/FlareZ123/obfs/actions/runs/44223494622), passed at `ef6ddded098807bb1576a73b65028f3972b6cb37`: each of Ubuntu and Windows executed 2,714 Node tests (Ubuntu 2,713 passed/one skipped; Windows 2,711 passed/three skipped), two strict JSDoc gates passed, and Ubuntu completed the three prescribed Chromium integrations. This evidence is **only for that immutable source**, and does not certify a later moving branch or independent security.

The strong-security release decision is unchanged.

## What could change the decision

A prospective candidate must freeze a meaningful, genuinely transformed **multi-file application** and its exact published bytes, with an ordinary esbuild/minified control under the **same trust boundary**. An independent attacker should receive the declared client/filesystem/runtime access and equal, precommitted effort against each control. Report source reconstruction, held-out functional cloning, dynamic extraction, integrity bypass and environment admission **separately**. Measure actually executed protected work, external callbacks, and input/output parity. Demonstrate a material attacker-cost advantage over the control before calling the candidate a security advance.

Runtime admission requires source-coincident real Node/Chromium measurements of repeated hot selected functions, short and sustained whole sessions, and genuine SCO client-side network/authorization costs. Every observed strict **over-2.5×** pair is a veto for the supported workload, regardless of passing medians or confidence intervals. Only eligible trusted-server SCO/SNO initialization can be amortized; COO startup is included. The same source pin must back the security and performance decision.

When a property guard or backend adds correctness without demonstrated protection, keep its report in [intermediate evidence](../im-results/) or [workplace](../workplace/). Do not relabel it a security result. The three-mode trust assumptions and conditional code-lifting/relay boundaries are discussed in [SECURITY.md](../docs/SECURITY.md) and [white-box execution boundaries](../workplace/whitebox-execution-boundary-2026-11-18.md).
