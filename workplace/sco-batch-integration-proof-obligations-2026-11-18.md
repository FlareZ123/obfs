# SCO batching integration gate: next hard questions (18 November 2026)

**Status: design proposal, not an implemented compiler correctness proof.** Written after [two-platform actual batch CPU evidence](../im-results/sco-bounded-real-batch-cpu-2026-11-18.md) and [source-pinned twelve-population release veto](https://github.com/FlareZ123/obfs/actions/runs/44224382333).

## What the current opt-in experiment establishes

`sims/sco-batch-resident-cpu.js` uses the existing `partitionScoAsyncModule({batch:true,maxBatchCalls:1024})` and `createScoBatchMethod` to keep the original six-file application server-private. It serves its real public facade under token authorization and performs all original method invocations sequentially. The 51-pair, 24,576-call count1000 experiment has reproducible, retained raw process-CPU samples and zero observed >2.5x trials per OS in its latest pinned run. The single-call experiment has 13/13 violating samples per OS at the same per-call work. A client running this program must **explicitly choose the batch public method**; the compiler does not transparently regroup arbitrary calls.

## Nontrivial proof obligations for automatic batching

1. **Call reordering and observability.** Automatically collecting `await service(a)` calls into one wire request can change the microtask queue, exception propagation and timing of host callbacks, source observers, pending Promises and interleaved public state. In the fixed sample, each original server computation is deterministic and independent; a general build must either prove the necessary contextual equivalence or reject all unproved call sites. Do not count an explicit opt-in batch API as transparent source-preserving compilation.
2. **Transport domain.** The public stub uses `JSON.stringify` and `response.json()`. The [real native-versus-served shape regression](../test/sco-json-shape-contract.test.js) demonstrates deletion of own `undefined` fields. The API may be limited to validated JSON-value inputs/outputs, or a separate typed transport could preserve a specified larger domain; neither would establish general alias/function/prototype semantics automatically. Admit externally observable property enumeration, symbols, BigInt, NaN, -0, cyclic references, getters, cross-realm identity and exceptions as independent test dimensions.
3. **Work-budget and service fairness.** Per-item authentication and `maxCalls` do not bound total requested server work. The experiment now rejects an authenticated 1,024×150k-iteration batch via a per-request work-sum cap of 1,024,000, retaining nested per-item validation. A production policy must add principal quotas and potentially a backpressure or isolated-worker scheduler; the threat model allows unlimited legitimate attacker requests. Quantify queue delays for an unrelated valid principal before claiming resource safety.
4. **True SCO 2.5× scope.** The current CPU profiles measure whole-process recurring work *after* both client import and server initialization. Only eligible trusted-server initialization can be amortized under the objective. A compliant admission needs a separate end-to-end client-initialization-inclusive compute comparison with a matching original app, cold and warm Node plus real browser, native/minified and actually emitted code, plus input sizes that include the 1-iteration veto. Runtime CPU must be separated from wall/network delay, and large requests cannot substitute for mixed-operation workloads.
5. **Security and dynamic hostile client.** The server-private graph and cryptographic material remain undistributed, but a credential-bearing client can relay authorized batch outputs. Direct authorized source reconstruction, same-token replay, browser DevTools instrumentation, endpoint replacement, request/order replay and attempted aggregate-work bypasses need independent adversarial code; batching's performance alone does not strengthen the anti-relay property.

## Concrete experiment with a meaningful outcome

Build one frozen multi-file app with two externally observable users and a stateful module: one performs a sequence of independent expensive calls, while the other awaits host callbacks between tiny calls. Produce three precisely declared variants: native original, ordinary minifier, and actually generated token-authorized SCO batch. First, prove identical values, property ownership, rejection behavior, callback order, module-state transitions and HTTP denials at every exposed boundary; reject call-site patterns that fail. Second, evaluate isolated and concurrent principal loads, client-inclusive cold sessions, warmed whole-process CPU, direct selected-private compute and real-browser results; retain exact raw pairs and request counts. Third, give a separate attacker only the distributed file(s), a legitimate test token and original public API contract, then measure online-relay/copy behavior and static extraction relative to ordinary service and minification controls.

**Release decision rule:** a performance-positive batch with changed externally observable semantics or an unbounded hostile-principal oracle is a *different application contract* and cannot be advertised as general code obfuscation. If any predeclared meaningful compute workload has a strict observed >2.5x pair, the hard budget remains unverified. A clean median with 0/51 observed breaches still leaves a nonzero conditional upper tail probability (approximately 6.98% per OS at 95% simultaneous two-OS coverage); preserve the assumptions and continue adversarial testing rather than presenting it as worst-case safety.
