# Root-keyed SQLite buckets: preregistered black-box authenticated collision-discovery attack

**Agent 41, 18 November 2026.** The [fixed eight-bucket SCO state experiment](../im-results/sco-ratchet-bucket-shards-2026-11-18.md) explicitly does not promise that an attacker with many authenticated accounts cannot discover which identities share a writer. This follow-up tests the weaker conditional attacker: the attacker controls **16 distinct legitimately verified probe accounts** and can observe their own authenticated HTTP response times. The attacker does not receive the trusted HMAC root, schema, bucket IDs or access to the trusted test-control endpoint.

## Fixture and frozen evaluation

One trusted server process holds the SQLite WAL writer for account A for **1500ms** under a test-control endpoint. A second independent trusted Node HTTP server process shares the same eight preinitialized root-keyed SQLite WAL files and handles 16 authenticated probe identities. For each candidate probe, the harness starts a *new* controlled A hold, then an independent attacker child receives only the public HTTP endpoint, its own verified token, and an unused challenge. The attacker measures its own RPC response wall latency and predicts "same A bucket" if latency **>800ms**, else "different". Parent waits until the A hold expires before the next candidate to avoid contamination.

The root is sampled independently and the 16 account identifiers are fixed (`verified-probe-00..15`); select a new independent root only if zero of the 16 test identities collide with A, with bounded attempts and every selection count reported. This conditional fixture selection must **not** be turned into an empirical frequency estimate. All legitimate RPC results and 200 statuses must be compared with original 8 MiB/event private HMAC. The client source is the exact generated 539-byte `batch.mjs`, SHA unchanged, with no private root. The independent attacker child must never receive the root or call the trusted helper `bucketOf`; only the trusted harness verifies its 16 guesses *after all samples* against actual keyed HMAC assignments.

Run Linux/Windows Node22 in targeted workflow, record all 16 raw wall values, predicted and true pairwise bucket-collision labels, confusion matrix, and stdout source pins. Exact root selection, statuses, file count, and native outputs are mandatory.

## Stop conditions and scope

Reject if the attacker is passed root or bucket assignment, any legitimate probe denied, no verified output parity, A hold expires before probe starts, or the fixed threshold fails to distinguish expected collisions in the scoped local test. A timed response distinguishes contention in the *test’s artificially held writer*; it is **not** a general remote timing guarantee, source extraction, proof of unauthorized B access, direct anti-cloning bypass, or an elevation of A token to another account's token. Holding a real writer may involve different network, queue, CPU or transaction duration profiles. The additional capability of controlling 16 verified accounts is **not** implied by one unlimited legitimate A session; state it explicitly. Conventional server hash partitioning has the same operational leakage. Server-side rate limiting, worker isolation, constant-time timing defenses and genuine authorization remain separate.
