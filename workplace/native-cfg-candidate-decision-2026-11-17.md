# Candidate decision: native CFG switch flattening on an 80-diamond work contract

**Prepared:** 2026-11-17 by Agent 30. **Status:** Narrow falsification decision; the performance continuation is separately pending. This is a research choice about the specified program shape, not a universal runtime or secrecy theorem.

## Fixed work and controls

The frozen contract is the exported behavior of one signed Int32 function with **80 sequential independent if/else diamonds** generated by sims/statement-flow-attack-scaling.js. The original has 3,574 UTF-8 bytes. Its only public API is f(value) -> signed Int32 number; the evaluated witness set includes positive/negative numbers and per-candidate identity checks. This is a synthetic *branch-heavy kernel*, with no external hosts, reflection or inter-file state; broader app contracts are outside this decision.

The opt-in compiler emits:
- Native source: 3,574 bytes.
- Sparse seeded CFG: 242 measured blocks, 17,485 bytes (ordinary), 17,431 bytes (compact).
- Public-only static reconstruction of either: **3,654 bytes**, preserving the tested native outputs.

At pinned source SHA 4e2f3db0901d2db89789cc4ead4500b7bc06dd5c, [run 44033197513](https://github.com/FlareZ123/obfs/actions/runs/44033197513) passed on both Windows and Ubuntu, including 41 held-out native vs emitted vs recovered inputs at every branch size and both compaction modes. Extraction times for the 80-diamond variant were ~17.11 ms/12.64 ms on Ubuntu (sparse ordinary/compact) and ~7.95 ms/4.79 ms on Windows. This is a **known-emitter source-only adversary**, which receives the published file and export name, without seed, compiler private state or original function. Strong source secrecy for this shape is contradicted by a working static clone. Exact textual recovery is not claimed.

The architecture currently has **no** matched esbuild-minification baseline for this particular synthetic work contract. Agent 4's separate PR 49 measures a different three-file application and cannot substitute as a same-work minification comparator. Therefore no relative **extra adversary effort over a minifier** is established.

## Experimental density/performance controls

A proposed low-level denseStateIds:true experiment permutes contiguous 0..N labels instead of uniformly distributed uint32 state constants while preserving randomized case order. It is off by default. Seed, semantic parity, label uniqueness, early-refusal, and public-only reconstruction are independently tested in test/statement-flow-dense-state.test.js. Runtime profiles in sims/statement-flow-diamond-runtime-profile.js compare sparse ordinary, sparse compact, dense compact, and native on the same 80-diamond source across hot repeated calls and a cold vm.Script compile proxy, retaining paired samples. Their exact generated-code CI results are **pending** at this decision version.

A local *synthetic* switch-only proxy (not actual emitted source) found native 1.43 ms, sparse 32.39 ms (22.70x), and dense 19.30 ms (13.52x) over 30,000 warmed function calls, all single-process medians. Separately grouping eight consecutive native if/else diamonds within each dispatched case gave a synthetic hot 1.22x ratio. The latter largely removes the flattened branch-level control-flow hiding, so cannot be presented as stronger obfuscation. These observations are test-design inputs, not release evidence.

## Decision for this candidate

**Do not select sparse or dense native switch flattening as a strong COO/SNO confidentiality or tamper-resistance architecture for this workload.** The source-only static adversary reconstructs its public function; hostile runtime observation remains an independent, unaddressed problem. Dense switch labels may reduce execution cost but, even if the generated benchmark becomes faster, speed alone would not establish new attacker burden over an ordinary minifier. Under the hard **2.5x** rule, a demonstrated supported workload above budget also rules out deployment there.

This does not mean the compiler is defective. It passed the admitted semantic tests and remains an opt-in structural transformation for workloads with separately measured budgets and honest security claims. A stronger future candidate should begin with a frozen native/minified/published/reconstructed app, enforce complete output and external-contract parity, put independent attackers on equal public-information and effort budgets, and carry short/full-session runtime evidence at the exact tested SHA. SCO private-code partitioning has a different threat boundary and must be evaluated with authenticated same-account relays and network cost.

See im-results/statement-flow-join-recovery-2026-11-17.md and im-results/statement-flow-dense-state-2026-11-17.md for procedures, pinned CI, and uncertainty. The baseline release audit sims/release-evidence-gate.js should remain a negative control, not an unconditional approval oracle.


## Final candidate veto at pinned emitted-source profile

The generated-code candidate profile is now **completed and green**: run 44036667080 at SHA 8abe4c2ac2b238a21ca14a747ebb7904914ab837 passed 40/40 unit tests across Ubuntu/Windows, JSDoc, and the Chromium ESM fixture. Its 80-diamond hot work consumed **ordinary sparse 21.88x Windows / 152.22x Ubuntu**, **compact sparse 21.94x / 158.32x**, and **compact dense 23.94x / 9.66x** the native compute in median paired ratios. Every paired one-sided lower median bound exceeded 2.5 on both platforms. Dense dispatch is faster than sparse on this Ubuntu runner, slower on Windows, and in neither platform can it satisfy the work's hard hot ceiling. The 2.5x veto therefore holds **even before** a same-work ordinary-minifier candidate-versus-control test is performed.

Dense output at the pinned profile seed was 13,388 bytes (versus source 3,574); the same independent source-only parser emitted a 3,654-byte runnable clone. This is a **second, independent reason** to reject high-branch full-switch CFG as a meaningful secrecy architecture for the selected work. Keep direct native or ordinary minified code as the performance control until a different candidate actually demonstrates attacker burden and supported budgets. Other workloads and trusted-server SCO remain unmeasured by this decision. See im-results/statement-flow-dense-state-2026-11-17.md for bounded statistics and raw log pointers.
