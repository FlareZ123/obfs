# Candidate admission screen: nonlinear rank, algebraic degree, and word-level source families

**Agent 2, 23 November 2026. Classification: research-process decision memo, not a security theorem or release candidate.** The strong three-mode release remains **RELEASE-BLOCKED**. This note operationalizes existing and recently source-pinned negative results; it does not claim originality for the underlying Boolean ANF, multiplicative-complexity, affine-rank, or word-level interpolation facts.

## Purpose

When a proposed COO, SNO or SCO protected component is a fixed-width deterministic permutation or pseudorandom-looking mixing function, a plausible evaluator can be misled by visible nonlinear gates, high polynomial degree, opaque independent affine wrappers or transformed byte length. Before expensive engineering, distinguish **two independent functional attack promises**:

1. **Small global nonlinear output displacement rank** `r` of a permutation. This means the function differs from some *invertible* affine baseline by outputs contained in a fixed r-dimensional vector subspace. It is intrinsically equivalent to the span of all affine-additivity defects (or to the rank of nonlinear vectorial Boolean ANF coefficient vectors) by [Agent 50's characterized equality](../im-results/affine-residual-minimal-rank-characterization-2026-11-21.md). Given a *globally valid, source-proved* rank bound r, the established [deterministic target-inversion theorem](../im-results/affine-low-rank-deterministic-completion-2026-11-21.md) inverts any announced target using at most `n+1+2^min(n,2r)` chosen forward calls. This is **target inversion**, not full-function cloning. In particular a single rank-one hidden affine-wrapped nonlinear shear needs at most `n+3` calls by the sharper [rank-one theorem](../results/rank-one-nonlinear-perturbation-inversion.md).
2. **Small Boolean ANF algebraic degree** `d` of the *entire vectorial output*, independently of its residual output rank. Given a globally valid degree≤d promise, a forward oracle can be queried at all binary masks with Hamming weight≤d, and the **complete function** is recovered by Möbius inversion after `Q(n,d)=Σ_(j=0)^d binom(n,j)` distinct requests. A bounded number of two-input AND gates is one *sufficient* source certificate: Boolean multiplicative complexity≥degree−1. This is **whole-function extraction**, not recovery of original source text or a proof of the extract's matching speed.

3. **Word-level source/API-family promises**, which can make generic Boolean-ANF or unconstrained black-box query budgets unnecessarily large:
   - A k-input **pointwise bit-slice-local 32-bit Boolean function** has one independent k-bit truth table per output bit. Querying the `2^k` input corners in `{0,-1}^k` exposes every truth-table row for all 32 output bits simultaneously, so the entire function is cloned in `2^k` calls.
   - A k-input **affine function over the ring `Z/(2^32)`** has form `c + Σ a_i x_i (mod 2^32)`. The zero vector and k unit vectors recover the constant and every coefficient in `k+1` calls, including functions whose ordinary JavaScript arithmetic has nontrivial carries.

   These are grammar/contract-specific promises, not another scalar invariant and not a membership test. They can overlap with rank or Boolean-degree classes, but exploit word-level structure that those generic screens do not fully capture. For k=2, bit-slice locality reduces the general 64-input-bit degree-2 interpolation budget of 2,081 chosen inputs to four; two-input modular-affine interpolation takes three. The exact query lower bounds are for deterministic, zero-error, value-only 32-bit-output oracles: the bit-slice class has `2^(32·2^k)` functions and each query returns at most 32 bits, while the modular-affine class has `2^(32(k+1))` coefficient tuples. The corner and zero/unit queries attain those bounds. Timing, errors, metadata and other side channels are outside this counting model.

   **Never infer these promises from a few samples.** The source or externally enforced operation contract must establish pointwise bit locality, fixed signed-Int32 semantics, modular arithmetic, arity, determinism and absence of hidden state. The learners do not certify those assumptions; arithmetic carries, shifts, cross-bit mixing, additional live inputs, floating coercion, mutable state and host effects can invalidate the corresponding model.

A function may be low-rank and high-degree (e.g. one high-degree rare top-bit toggle), or high-rank and low-degree (e.g. a quadratic vector function whose nonlinear coefficient vectors span many output coordinates). **Do not infer either property from the other.** At least one proven small bound or a proven word-level source-family promise can suffice to defeat an associated claim of black-box functional resistance; large values on the rank/degree axes **do not prove protection**. Examples include other source-family-specific arithmetic, reversible structure, white-box dynamic extraction, and source copy/relay under adversary control.

## Executable decision protocol for a candidate owner

**Before acceptance to a costly multi-mode release evaluation**, record the actual protected operation, widths/domains, complete source grammar or symbolic constraints, server-private state, threat-mode authority, and whether arbitrary chosen-forward inputs are available. Provide an executable **source-transparent** bound/counterexample for rank and degree, not merely dozens of sampled residuals. A low rank in samples gives only a *lower* bound on true rank: an unqueried two-point transposition can preserve nearly every probe response while raising the full nonlinear rank, as already established in [the min-rank analysis](../im-results/affine-residual-minimal-rank-characterization-2026-11-21.md). Likewise, degree≤d must be source-proven or established by exhaustive full-domain evaluation; a low-weight ANF transcript alone cannot certify absence of a rare higher-degree gate.

If rank or degree is proven small, **execute the existing source-independent attacker** on a held-out set whose initial secret inputs are not visible to the attacker. The attack receives only the claimed bound and the chosen-forward oracle, not hidden layers, matrices, seeds or output source. Preserve complete query transcripts, oracle-call counts, trace of failed cases, source SHA, deterministic seeds and an explicit high-rank/high-degree negative control to prevent false promises.

For fixed-width word APIs, also ask whether the source/contract proves either word-level class above. If it does, run the matching bit-slice or modular-affine learner against held-out values and a stateful/cross-bit negative control. The 23 November SCO experiment exercised both classes through the production `createScoHandler`: two private Int32 methods were cloned in exactly four and three authorized calls, respectively, then matched 3,000 held-out pairs per seed without further RPC. A conventional private HTTP service held the same closures, authentication and two-argument operation policy and was cloned with the same transcript. Unauthorized requests remained 403; this is an authorized functional-cloning result, not an authorization bypass. The focused [Ubuntu/Windows run 45127575750](https://github.com/FlareZ123/obfs/actions/runs/45127575750) passed at exact source `3c095bb945614115e574ba4d34a49e01caee141e`; the helper and test blobs are byte-identical at current main. The full Node/Chromium job was skipped, so this is not a full integration receipt. The seven-call example does not improve on the already documented two-query attack against a much narrower two-rotation-plus-offset family; it adds two distinct word-level families and a live same-trust service control. Neither the source/API promise nor absence of side channels is inferred by the learner.

For SCO compare **the same private function and policy** behind an ordinary matched-trust service as well as the obfuscator facade, so an offline clone is not misrepresented as added security unique to the obfuscation. Successful original/compiled behavior equivalence and one exact attack do not by themselves prove output secrecy in all settings.

If both tests fail or source proof says rank/degree too high for those strategies, proceed to **independent** source-aware algebra, static code reconstruction, actual attacker runtime instrumentation, tamper and authorization bypass, and realistic CPU benchmarking. For COO/SNO, attacker authority is stronger than the selected forward-oracle model, so passing these two narrowly scoped filters carries **no positive security weight**. On SNO, an adversary already controls the Node runtime, memory and filesystem; local-only integrity manifests lack an external verification root. On SCO, an authorized requestor may relay account-owned outputs without extracting keys; a private service's source secrecy is not an incremental obfuscator advantage unless matched against a conventional private API.

**Performance remains a separate blocking requirement.** The research objective's strict 2.5× compute budget applies to actually executed application work, except explicitly eligible SCO/SNO trusted-server initialization. It is not satisfied by a small attacker-query count, passing unit tests, median timings, output byte overhead, a zero-rewrite compiler, or a hypothetical startup amortization on COO. Retain native vs compiled **same-source**, equal-trust ordinary-minified controls and every strict >2.5× pair; see [the three-mode candidate convergence charter](three-mode-candidate-convergence-2026-11-22.md).

**Disposition:** this is a no-new-backend **early rejection protocol** for deceptively complex Boolean and fixed-width word code. The new word-level cases are folded into this existing memo rather than published as a separate candidate catalogue. The screen should reduce duplicated research and prevent promotion of candidate disguises that already admit cheap inversion/cloning. It does not update release status, contain a claim that all JavaScript obfuscation is broken, nor replace a controlled source-pin full browser/Node integration.
