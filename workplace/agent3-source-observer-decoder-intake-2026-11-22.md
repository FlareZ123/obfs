## Current-main implementation boundary

The source-observer implementation is still primarily a boolean refusal system:

- In src/ast.js, isGlobal recognizes only the spellings globalThis, window, self and global. It does not resolve each reference to a lexical binding. The Window error-handler predicate consumes this spelling-only test.
- `renameLocalIdentifiers` and `encodeStrings` return the entire original file when `observesFunctionSource` is true; `proveLocalObject` refuses the whole local owner proof. `cross-properties.js` also returns the original file group when any module observes source. The same boolean disables targeted work in `register-vm.js`, `expression-vm.js`, `branch-blocks.js`, `statement-flow.js`, `affine-native.js` (both lowering entry points), and `wasm-i32.js`. SCO's `varyLiteralSpellings` also returns unchanged source for a source observer, while `interfileSourceObserver` suppresses per-request spelling variation for the whole published group. This is a pipeline-wide, three-mode veto, not only an identifier/string/property issue.
- Experimental sourceObserverIslands is not the missing general solution: it requires closedWorld, rejects experimental Symbol lowering, and selectively permits only a narrow primitive-leaf local property transform. It does not selectively enable identifier or string rewrites.
- Agent 1's review found that collectBindingScopes in src/properties.js is only a partial inventory: it omits catch, class, named function-expression and destructuring bindings, and does not distinguish var hoisting from let/const block scope. It is not a sound general host-global resolver.
- Agent 1 also verified that applyEdits returns only rewritten source text. The pipeline reparses after property, identifier and string passes. Original-AST UTF-16 source offsets cannot be reused blindly after earlier edits; a selective plan must be recomputed with proof or transported with a UTF-16 edit map.

The source-observer carrier/effect contract in workplace/source-observer-carrier-effect-contract-2026-11-23.md is a **proposal**, not an accepted implementation. Its useful separation is ExactSource, SourceBytes, FramePosition, CallableMetadata and UnknownHostEffect. DynamicFrame is an activation/call-stack context, not another ordinary heap value. Preserve that separation in future code and reporting.

## Required architecture and acceptance contract

1. **Binding identity, not spelling.** Resolve each host/global root and each catch, Promise, imported, returned or aliased callable by lexical BindingId and value provenance. Unsupported declarations, ambiguous scope, dynamic scope, unresolved imports, patched intrinsics or unknown host effects must remain Unknown. A single same-spelled identifier anywhere in a file cannot establish or suppress a host root elsewhere.
2. **Value-flow and activation-flow are separate.** Track assignments, parameters, returns, destructuring, module edges, catch/throw and Promise rejection edges. Add a DynamicFrame reverse edge from a running callable to any invoked opaque callback/getter that can inspect its active caller. Do not require the callable to escape as a heap value before protecting its source/coordinates.
3. **Conversion is receiver × callable × value dispatch.** A proven native Storage/Web IDL/Array.join sink is not enough by itself. Prove the receiver and actual method identity, then prove whether that particular function value's ToPrimitive path reaches native Function#toString. Own toString / Symbol.toPrimitive, bound functions, patched Function.prototype.toString, method aliases, proxies and prototype replacement require explicit controls or Unknown.
4. **Protect the complete observable closure.** ExactSource spans alone are insufficient if a free binding declaration or owner property outside the callable is renamed while its reference remains in the protected source. Preserve the callable's exact source and every source-reachable binding/property spelling, while retaining unrelated private yield where the closure is proven.
5. **Make protection survive the transform pipeline.** Either recompute the plan at each pass and prove earlier edits did not touch protected source/aliases, or carry stable identities and a UTF-16 edit map. Reject edits inside protected spans; adjust spans after edits before them; after every pass compare each protected source slice byte-for-byte/code-unit-for-code-unit with its original.
6. **Keep effects distinct.** ExactSource, SourceBytes, FramePosition, CallableMetadata and UnknownHostEffect are not interchangeable. Equal-width edits may preserve one tested column while changing Function#toString bytes. SourceBytes/SRI/self-fetch may still require whole-artifact refusal; a known exact-source callable should not automatically veto every unrelated function in its file.
7. **Require positive transformed work.** Every negative sink fixture needs native-versus-emitted parity and a paired unrelated private-owner/property/binding positive. Also include own conversion hooks, override controls, patched builtins, cross-file and classic-script cases as appropriate. A suite that passes only because all transformations are refused is fail-closed compatibility, not successful selective obfuscation.
8. **One comprehensive acceptance owner and one frozen source.** Agent 10 owns the next exact current-main full gate after the minimum candidate is composed: Node 22 Ubuntu/Windows, real Chromium, strict project/external JSDoc, full failure/skip inventory, actual transformed-work yield and relevant runtime profiles. ## Integration decision (23 November 2026, 17:40 UTC): NO-GO for compiler port

**Decision:** Do not port or merge a source-observer/decoder compiler change from the currently available donor set, and do not dispatch the comprehensive acceptance gate yet. There is no accepted, coherent current-main candidate at this snapshot. This is a bounded integration no-go, not a claim that further research is futile or a new security theorem.

The blockers are concrete:

1. **The production representation cannot express the evidence.** The current scanner exposes a boolean `observesFunctionSource`; `isGlobal` is spelling-based rather than per-reference lexical binding resolution. Identifier, string, property, cross-file, register/expression VM, branch/statement-flow, affine, WebAssembly and SCO request-spelling passes all use file/graph-wide or target-wide refusal. The opt-in source-observer-islands exception only admits a narrow primitive-leaf local property transform. The current shape cannot represent a callable's exact source span and reachable closure separately from unrelated private owners, nor can it distinguish ExactSource, SourceBytes, FramePosition, CallableMetadata and UnknownHostEffect. `src/ast.js:62`'s shared `applyEdits` returns only the rewritten string (no UTF-16 edit map or stable node identity), so sequential parse-after-edit passes have no shared source-span continuity mechanism. A tested reference helper now exists at `sims/utf16-edit-map-reference.js`, but it is not wired into any compiler pass and carries no binding or closure identity.
2. **The dispatch boundary is not one sink name.** The evidence now distinguishes native inherited method calls, captured native aliases, own/prototype JavaScript overrides, own `toString`, `Symbol.toPrimitive`, patched `Function#toString`, Storage's internal named-property setter, computed-key `ToPropertyKey`, and unrelated browser/Node source-observation paths. A `.setItem` denylist would both miss the named setter and suppress safe overridden-call paths. The carrier/effect graph remains a proposal, not an implementation.
3. **The donor evidence is not a composed implementation.** The latest Storage additions are test-only; PR #299's historical composition was closed by Agent 3 as superseded on 23 November, with its branch, commits, tests and review evidence preserved (no wholesale port). PR #338, #332 and the decoder drafts remain separate donor lines with their own unresolved source/yield/validation obligations. The new named-setter and COO/SCO/host-lock witnesses add required acceptance controls but no compiler source change.
