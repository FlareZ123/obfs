# Predeclared SCO equal-trust worker whole-process CPU control (18 Nov 2026)

**Hypothesis and scope:** A conventional authenticated Node HTTP server executing the same original private HMAC in prestarted resident per-principal workers may consume essentially the same process-wide user+system CPU as the generated SCO server. The existing CPU gate compares generated synchronous and generated worker arms against native original. It does not yet include a conventional server that is equally trusted and uses exactly the same worker topology.

**Comparison:** Extend the existing `sims/sco-ratchet-worker-process-cpu.js` 80-event original (64 Account A, 16 Account B) source-paired CPU gate with `ordinary-worker`, using the already validated `makeWorkerServer(root,()=>null,true)`. All three arms must receive an identical fresh 256-bit private root per trial, exactly the same typed 64A/16B challenges, original private HMAC and account cookie. Execute seven trials with alternating/permuted arm order to mitigate scheduling and JIT confounds. Measure `process.cpuUsage()` user+system of original 80-event direct HMAC and protected 80-event real HTTP/fetch/worker path, *after* worker startup. Capture each pair's normalized CPU ratio and generated-worker/ordinary-worker incremental CPU. Both workers must return the exact independently computed original output and 200 responses. Keep the synchronous generated arm as a positive load control.

**Stop line:** Any mismatch in output, status or work count invalidates the comparison. Every measured strict original-normalized CPU ratio exceeding 2.5 is a veto for that workload, regardless of medians. If generated and ordinary worker ratios are close within observed noise, this is negative evidence against attributing server-resident worker CPU performance to obfuscation. A material unexpected difference would require source-pinned repeat and root-cause assessment before a security claim. CPU accounting includes the hosting process's worker threads and client fetch in one Node process; it excludes browser/TLS/WAN, independent external client CPU, worker startup and concurrent adversarial A/B fairness. This neither proves protection against legal relays nor establishes universal runtime bounds.

The experiment is distinct from the separately verified seven-pair independent-child B service-latency study in [im-results/sco-worker-equal-trust-transport-2026-11-18.md](../im-results/sco-worker-equal-trust-transport-2026-11-18.md). Both are intermediate evaluations under the same `RELEASE-BLOCKED` decision.
