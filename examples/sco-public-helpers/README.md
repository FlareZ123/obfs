# Selective SCO with explicitly public and private local helpers

[Original source](before/mixed.mjs) has two unexported local helpers,
`normalizeInput` and `formatCount`, used by its public exports. It also
has an unexported `privateFold` helper that reads a private literal
`PRIVATE_KEY` and is called by the protected async export `secret`.

The compiler is invoked with `privateNames:['secret']` and
`publicHelperNames:['normalizeInput','formatCount']`. The actual
[generated facade](after/mixed.mjs) preserves public exports and the
two explicitly selected public helpers as ordinary JavaScript. The private
helper body, private key literal, and original `secret` implementation are
omitted. `secret` becomes a same-origin JSON RPC facade requiring the server
to register its original implementation with `bindScoModuleExports` and
separately enforce `authorizeRead`, `authorizeRpc`, and `authorizeOperation`.

Regenerate the golden facade using `node examples/sco-public-helpers/build.cjs`.
`test/sco-public-helpers.test.js` compares the exact generated bytes,
executes the original and generated modules, and tests refusals for split
cross-boundary dependencies and state. The original source must remain only
on the trusted SCO server. This is an explicit, conservative module-author
declaration of the public helper set, not automatic security classification.

Only source withheld by the trusted server benefits from this separation.
A client with a valid session can inspect generated request IDs and relay
authorized operations to another user. Thin RPC calls may violate the 2.5x
runtime target, and output equivalence is bounded to the JSON RPC contract.
The developer must benchmark real sessions and deploy actual authentication
and server-side authorization policies.
