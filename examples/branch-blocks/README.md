# Native branch superblocks: reproducible before and after

This example tests an opt-in control-flow flattening pass for Node CommonJS
and browser-compatible ESM functions. The [original](before/gate.cjs) has two
nested ternaries. The [actual compiler output](after/gate.cjs) contains five
state-dispatched basic blocks, randomized case identities and reversible
XOR-spelled numeric immediates. The after file was generated by the real
`flattenBranchBlocks` compiler under the fixed seed in
[build.cjs](build.cjs), then checked into the repository. The associated test
compares the generated bytes against this file.

The compiler only accepts explicit, single-parameter, return-only functions
with pure chains of operators and unsigned-byte right operands. It preserves
selected-branch evaluation, repeated coercion of the argument and native JS
binary operator semantics by resetting the scratch register on each block.
It declines dynamic scope, known function-source observation, unsupported
expressions and ambiguous candidates. Callers must establish that source
spelling and stack-frame observations are outside their external API contract.

Programmatic use:

```js
const {obfuscateFiles}=require('../../src');
const output=obfuscateFiles([{
  path:'gate.cjs',sourceType:'commonjs',code:originalSource
}],{
  mode:'sno',seed:'reproducible-seed',
  experimentalBranchBlocks:{'gate.cjs':['gate']}
});
```

The option is experimental and requires separate performance measurement for
each real workload. It is deliberately absent from the production CLI defaults.

## Independent attacker control

[The source-only recovery script](../../sims/branch-block-reconstruction.js)
uses Acorn to parse only the public generated file. It recovers all five block
states, both conditional edges and seven masked immediate operations without
the compiler seed, then rebuilds a behaviorally equivalent expression. This
limits the protection claim to superficial control-flow restructuring, even
when a runtime benchmark fits the project's 2.5x budget.

## Verification

[The focused tests](../../test/branch-blocks.test.js),
[the before/after and recovery tests](../../test/branch-block-reconstruction.test.js),
[the performance profiler](../../sims/branch-block-profile.js), and
[the manual validation workflow](../../.github/workflows/manual-branch-blocks.yml)
provide reproducibility. See the
[dated experiment report](../../im-results/branch-superblocks-2026-11-15.md)
for scope, performance results and remaining constraints.


A separate [real Chromium COO ESM regression](../../test/branch-block-browser.js)
compares the transformed export to the original over 4,109 heterogeneous
inputs. The pinned [focus run](https://github.com/FlareZ123/obfs/actions/runs/43735256344)
passed and measured 1.872× numeric hot-loop slowdown in Chrome; the experiment
report gives the scope and limitations.


The generated [operand-masked variant](after/gate-masked.cjs) is a second
actual output of the same compiler. It is enabled only through
`experimentalBranchStateBlinding:true` and ties switch
state to the previous numeric test result. The independent
[seedless static attacker](../../sims/branch-block-reconstruction.js) can
symbolically cancel the masks and recover this variant too. An additional
[held-out corpus](../../sims/branch-block-recovery-corpus.js) recovered
210 generated variants covering 8,234 blocks on Windows and Linux, providing
stronger evidence that this mask adds no effective confidentiality.
