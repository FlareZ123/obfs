# Frozen three-module COO application and attacker-cost challenge

**Research status:** actual compiler-generated, deterministic three-file JavaScript ESM application, with reproduced reference behavior and a complete attacker-only functional clone. This is intermediate security and performance evidence.

| Public app file | Original | Distributed |
| --- | ---: | ---: |
| math.mjs | 832 bytes | 5,883 bytes |
| state.mjs | 950 bytes | 950 bytes, deliberately unchanged |
| entry.mjs | 685 bytes | 685 bytes, deliberately unchanged |
| Total | **2,467 bytes** | **7,518 bytes** |

The generated [math.mjs](generated/math.mjs) includes three two-path native polyvariant affine functions, with 30 arithmetic steps. Their **310 original source bytes (12.6% of three-file source)** are selected for transformation; the math module itself is 33.7% of original source bytes. These percentages describe source coverage. The protected runtime-work fraction is input dependent and must be measured independently.

The [native app](native/) has an iterative digest with three protected arithmetic leaves, a stateful session, dynamic input conversion, externally supplied host emit callbacks, and reflective own-key and descriptor checks.

## Soundness boundary

Processing **all three modules together** with this experimental backend triggers a conservative source/reflection observation refusal. The deterministic [builder](build.cjs) confines obfuscation to the independently analyzed math module and packages the reflective state and entry modules unchanged. This selective source exposure is intentional and tested.

The [differential harness](../../test/polyvariant-app.test.js) compares 96 seeded held-out stateful application scenarios, verifies external host callbacks, checks reflective Object.keys/Object.getOwnPropertyDescriptor behavior, and reconstructs each published ESM arithmetic leaf using the seedless [AST attacker](../../sims/polyvariant-affine-static-recover.js). It also asserts the full-graph policy refuses to modify this source.

## Adversary and whole-session cost

The [attacker-only clone](../../sims/polyvariant-app-functional-clone.js) imports **only the generated distributed files**, supplies a locally emulated host emit callback, and runs the protected application on chosen inputs. This is an offline functional clone using the public API. It needs no source-code build seed, server compromise or native files.

The [whole-application budget harness](../../sims/polyvariant-app-budget.js) measures seven alternating fresh ESM module-graph import and stateful processing sessions, including external callback effects and JSON serialization, at 1, 50, 1,000 and 10,000 events. Every measured output is cross-checked. These ratios include startup and full execution for that specific application workload.

The builder verifies the committed output by default. Its write option regenerates all three files with atomic locked writes. Its JSON emission option exposes the exact generated bytes. The executable tests and attacker use the committed public files without any private service.

**Security conclusion:** source-only attackers recover the masked leaves, and a fully controlled COO client can execute a functional clone of the entire application from shipped bytes. Syntax and trace complexity do not establish a host authorization boundary under the stipulated threat model.

## SNO single-entry deployment of the same transformed algorithm

The [SNO experimental builder](../../sims/polyvariant-app-sno.js) uses the
identical frozen three-module original, compiles only the independently
analyzed math module in actual SNO mode with three two-path polyvariant
functions, retains host/reflection modules unchanged, and adds a CommonJS
bridge plus generated SHA-256-checking launcher. Only the public launcher
is executed as the server's entry point in normal use.

At [pinned Linux/Windows run 43813786492](https://github.com/FlareZ123/obfs/actions/runs/43813786492),
96/96 stateful scenarios matched native behavior on both OSs. Source
normalization produced byte-for-byte identical compiled graph and launcher
SHA-256 digests across the runners. One of the three original app modules
was genuinely transformed, expanding 2,467 original bytes into 7,495
distributed graph bytes. The source-only, seedless independent attacker
recovered all 3/3 obfuscated arithmetic functions and matched 12,288
held-out typed comparisons. A separate public-only executable attacker
cloned the whole distributed SNO program, bypassed the entry-point
manifest by direct ESM import, and successfully updated its local manifest
to run modified code.

Seven-trial complete-process measurements across 1/50/1,000/10,000 event
loads met 2.5x in all eight sampled Linux and Windows scenarios, with
transformed SNO/native medians ranging from 0.766x to 1.172x. A single
short Windows 0.766x reading is subject to runner noise; it does not
establish a speedup. These results measure conditional arithmetic
transformation and SNO launcher overhead without establishing runtime
authorization or reconstruction resistance. The full scope, attack scripts
and exact metrics are in the [SNO comparison report](../../im-results/polyvariant-app-sno-attack-cost-2026-11-16.md)
and [cross-platform test](../../test/polyvariant-app-sno.test.js).
