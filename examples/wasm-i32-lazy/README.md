# Cost-aware asymmetric WebAssembly conditional lowering

This is an **actual four-argument native source → compiler-emitted JS/Wasm pair** for `lowerWasmI32Functions` with seed `agent38-wasm-lazy-sample-v1`. The emitted `after.cjs` has **859 JavaScript bytes** embedding a **185-byte WebAssembly module**, including a structured i32-result `if (0x04 0x7f) ... else (0x05) ... end (0x0b)`. It preserves the native conditional's semantics for primitive signed-Int32 Number arguments.

The previously introduced **Wasm select** executes both ternary branches eagerly. A new bounded emitted-bytecode heuristic chooses a structured, lazy Wasm `if/else` when one branch is much more expensive than the other: combined output arm bytes at least 48, largest branch at least three times the smaller. This example has a complex true arm and the single variable `d` as its false arm. Hot calls with mostly false predicates avoid work on the dormant arm. For small balanced branches, default `auto` retains the existing select encoding.

Run `node examples/wasm-i32-lazy/build.cjs` to assert the **exact checked-in generated bytes**, 20,000 native/lazy/eager/reconstructed typed comparisons, and alternating warm benchmarks against the same source compiled with the direct research option `conditionalStrategy:'select'`. The option is `auto` by default and can be explicitly set to `'if'` or `'select'` when invoking `lowerWasmI32Functions` directly. The public COO/SNO `experimentalWasmI32` pipeline retains automatic selection.

The independent bytecode-only attacker in `sims/wasm-i32-static-recover.js` now follows nested WebAssembly structured `if/else` operand stacks and rebuilds the original conditional expression tree. This entire source program remains reconstructable and executable without the compiler, original source, seed, or privileged server. The technique improves *some* workload performance while expanding control-flow syntax coverage, with no observed encryption, tamper barrier or environment authorization.

The 2.5× budget is a workload property. No fixed static branch-cost rule can guarantee it for every program or cold-start.
