# Closed-world classic script private-property renaming

The [before.js](before.js) and [after.js](after.js) files are a real, deterministic before/after pair generated by the normal COO compiler. Run `node examples/classic-private/build-sample.cjs` to verify exact bytes, or pass `--write` to regenerate the sample atomically.

The seed is `classic-private-example-v1`, mode is `coo`, `sourceType:'script'`, `closedWorld:true`, and the independent string and identifier passes are disabled to isolate the property proof. A block-owned object with `secretField` and `bonusField` becomes an object with two seed-specific private key labels. All matching local member references are rewritten, and `globalThis.result` remains an unchanged external interface.

Only objects whose declaration is inside a lexical block and whose complete uses pass the existing alias, reflection, dynamic-access, and error-source guards are transformed. Top-level classic-script globals remain unmodified because independent scripts can reference them. The caller must genuinely close the group of browser scripts, and code that exposes function or distributed source bytes triggers a broader refusal.

This is a restricted coverage increase, with no claim of increased security against an attacker who can read or modify served JavaScript. The repository's existing public-token normalizer eliminates the hashed key labels while preserving the computed result. See [the intermediate report](../../im-results/classic-private-2026-11-16.md) and [differential tests](../../test/classic-private-properties.test.js).
