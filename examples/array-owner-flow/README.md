# Private object through a confined one-slot array

This COO CommonJS fixture demonstrates an intentionally narrow cross-reference
proof. The original [before file](before.cjs) creates the inert private object
`owner`, stores it in `const holder=[owner]`, and reads `holder[0]` into two
local aliases. The holder never escapes or changes. The compiler's locally
conservative reference analysis admits this shape, renaming two private keys
consistently in the [exact generated after file](after.cjs).

The [build-sample.cjs](build-sample.cjs) script generates the public after
bytes using the programmatic COO API and fixed seed. Its verification mode
checks byte-identical canonical-LF output on Windows and Linux and compares
2,001 native and transformed values. The generated bytes are 452 bytes. The
[automated test](../../test/array-owner-flow.test.js) additionally exercises
unproved holder mutations, exports, opaque calls, reflection and dynamic indices
to check that the entire owner remains unrenamed when safety cannot be proved.
The native [ESM graph test](../../test/array-owner-interfile.test.js) verifies
a private owner inside an ESM module called through another module and refuses
property renaming when an ESM holder or owner can be reflected externally.

This is an **engineering coverage improvement** rather than a confidentiality
boundary. The resulting CommonJS program contains the same arithmetic with
hashed property spellings. A [seedless normalizer](../../sims/offline-normalize.js)
can replace those labels without learning the compiler seed and reproduce the
observable numeric computation. It cannot recover the original descriptive
names from absent metadata, but the semantic equivalent is immediately
runnable. Hot-path performance is separately measured by the repository's
[benchmark suite](../../test/benchmark.js), and a sample ratio does not prove
the 2.5× budget for every workload.
