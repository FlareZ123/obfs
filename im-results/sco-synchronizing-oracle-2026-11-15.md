## Hypothesis

Withholding an explicit reset endpoint from an SCO server is insufficient to prevent small-state behavioral reconstruction when the allowed input alphabet contains a *known synchronizing word*. An attacker who knows such a word can play it through the legitimate state-transition interface, discarding its outputs, to obtain a logical reset without a reset method in the published API.

This is a **known-synchronizing-word** study, not a discovery algorithm for unknown reset sequences, a bypass of method authorization, a private-memory dump or a general solution for arbitrary stateful programs.

## Reproducible private fixture

The trusted private ES module has a binary step(symbol) API. It starts in hidden state 0 and has four states; its private transition/output table and canary are never deliberately sent to clients. Symbol 0 has transition next(state,0)=max(0,state-1). Therefore three zero symbols send *every* hidden state to state 0, a synchronizing word known to the attacker. Symbol 1 increments state modulo four, making every state reachable from the initial state. Input-zero outputs follow the pattern 0,0,1,1 over the four states; input-one outputs are varied by deterministic seeded fixture generation.

Only step(symbol) is exported in the original server module. The public ESM file is generated by the repository's production partitionScoAsyncModule and served over HTTP by createScoHandler. Captured server exports are wired using bindScoModuleExports. Requests must carry the example approved-session cookie and pass per-method/per-argument authorization. **Unauthenticated RPC returned HTTP 403**; the client source lacked the private canary and the private transition/output table accesses.

The attack's local wrapper exposes a reset method *to the learning algorithm only*: it sends three regular, authorized step(0) operations through the public proxy. Thus all training queries use the sole published server method. The learner never receives the private model, source, seed or state variable.

## Algorithm and measured outcome

The learning algorithm assumes an upper bound of four observable states, a binary input alphabet, deterministic transitions and the known synchronizing word 000. After each shimmed reset it performs suffix-signature queries of lengths up to three, gathers distinct observable states by breadth-first access sequences, then constructs a behaviorally equivalent transition/output table. The 14 distinct suffixes suffice for the four-state model; all reachable hidden states were distinguishable in these fixtures.

## Five independently considered dimensions

- **Static source reconstruction:** the generated client file did not include the private canary or table accesses. The attack does not rely on private-source recovery, and does not prove resistance to all alternative source leaks.
- **Dynamic observation:** authorized inputs and outputs were enough to build an equivalent observable finite-state machine. This is behavioral reconstruction, without client-side source instrumentation or access to server memory.
- **Tampering and authorization:** denied operations returned 403. The attacker could still send unlimited **legitimate** step requests, consistent with the stated SCO adversary. No authentication bypass was observed.
- **Environment locking:** the cookie hook is a deterministic test authorization policy. It is not a production identity, domain ownership or anti-replay claim. An approved session was explicitly available to the attacker.
- **Compatibility and performance:** the learned machine matched 8,184 binary sequences from the trusted fixture and used finite normal HTTP calls. The attack timing is neither a 2.5x protected application runtime measurement nor a general SCO deployment overhead guarantee.

## Decision and limitations

Removing a privileged reset operation does not eliminate all state-reset capabilities: a synchronizing word in the **ordinary authorized input alphabet** can suffice. SCO authorization and source withholding remain useful for hiding private implementation bytes and restricting unauthenticated users. They cannot, by themselves, promise secrecy of a small deterministic observable machine from unlimited legitimate queries.

The attack critically depends on the known synchronizing word, deterministic behavior, known binary alphabet, a four-state upper bound, state visibility through outputs, and unlimited allowed operations. It neither learns the synchronizing sequence nor addresses arbitrary large-state or non-synchronizable machines, cryptographic computations, key recovery, nondeterministic servers, concurrent multi-session state or quota-restricted deployments.

Future defenses should identify whether legitimate operations synchronize or reveal a tractably finite state model, and separately benchmark normal coarse server-side work against the 2.5x requirement. Stronger general security claims require independent hostile analysis and a harder target corpus.
