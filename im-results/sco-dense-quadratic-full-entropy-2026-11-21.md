# Dense full-entropy quadratic SCO chosen-query functional reconstruction

**21 November 2026. Independently executed, source-pinned Ubuntu/Windows intermediate engineering evidence. Existing release status: RELEASE-BLOCKED.**

## Hypothesis, control and original source

An SCO server retaining a secret, arbitrarily dense quadratic function may prevent the client from reading the original JavaScript text while still exposing enough chosen-query output to reconstruct the function. The previous two-rotation test in im-results/sco-quadratic-529-live-oracle-2026-11-21.md had a small 930-pair structural prior that a source-aware attacker could fit in only two requests. That was correct evidence for its narrow function family, and was not a realistic generic 529-query lower-bound sample.

This follow-up samples **529 independent cryptographically random unsigned 32-bit coefficient values**, 2,116 random bytes or **16,928 bits**. Its original Node ESM private async export evaluates the full 32-input/32-output Boolean degree-at-most-two ANF. A local array literal inside the private export holds the coefficients; a separate public identity export keeps the module partition genuine. The compiler uses partitionScoSelectedAsyncExports, bindScoModuleExports and a real createScoHandler HTTP server. The emitted public ESM must omit the private array identifier. An unauthenticated private RPC is denied 403. The learner receives an ordinary valid credential, the HTTP origin and the opaque route extracted from the actual served public ESM. It receives no array, original module object, private source, or trusted compiler metadata.

## Exact algebra and planned verification

There are C(32,0)+C(32,1)+C(32,2) = **529** independent Boolean monomials of total degree at most two in 32 inputs. Each monomial has an independently chosen 32-bit coefficient. All 2^(529×32) coefficient vectors define distinct input/output functions because ANF representation is unique. In the **ideal value-only oracle model**, each requested input produces one uint32 result with no additional information from timing, error variants, transport metadata or side channels. An adaptive q-query transcript therefore has at most 32q bits of function-dependent responses. Thus **q >= 529** is a worst-case information-theoretic requirement for complete identification of this unrestricted class in that model. The real HTTP test does not measure side-channel leakage, so the counting bound must not be asserted as an unqualified minimum for every instrumented network attacker. Interpolation on zero, 32 one-hot and 496 two-hot inputs attains this bound. **The same worst-case lower bound survives the full-rank quadratic-output restriction.** Treat the 496 quadratic 32-bit coefficient vectors as columns of a 32-by-496 matrix over GF(2). The exact count of rank-32 quadratic matrices is `product(i=0..31, (2^496 - 2^i))`; each matrix admits `2^(33*32)` independent constant and linear coefficient choices. Every factor in that product exceeds `2^495`, so the number of degree-at-most-two functions whose quadratic output span has rank 32 is **strictly larger than `2^(528*32)`**. Any adaptive transcript of at most 528 value-only uint32 queries has at most `2^(528*32)` possible response sequences, making an exact-identification guarantee impossible even for this full-rank subclass. This counts *all* full-rank quadratic source functions; it does not imply that each fixed source or each smaller parameterized family needs 529 queries. This statement concerns complete identification of every function in that class; it is not a minimum query claim for approximations, restricted function families, hidden-structure shortcuts, nonuniform priors, or cryptographic PRFs.

The actual HTTP learner must send exactly 529 authorized RPC requests. The trusted verifier compares **all 529 recovered ANF coefficients** to the original fresh random array, in the exact monomial order, then shuts the server. The offline model must match four fixed and 1,024 deterministic SHA-256-derived heldout inputs against the original, with zero additional protected server invocations. The 496 quadratic coefficients' GF(2) output span must have rank exactly **32**, so the observed nonlinear component has maximal minimum affine-residual output rank.

An explicit missing-query ambiguity checks one concrete restricted budget: if the 529th low-weight input is omitted, a second quadratic polynomial can be formed by flipping its private pair coefficient by one bit. The resulting polynomial matches the other 528 low-weight observations identically but differs on the omitted input. This check is separate from the generic counting proof, which covers all adaptive algorithms and coefficient choices.

## Independent-process adversarial reproduction

The original authenticated HTTP test ran its selected-query learner as a separately scoped JavaScript function inside the trusted Node test process. A stronger follow-up now executes an actual attacker **in a separate Node child process**, with no shared JavaScript heap or direct object references to the private randomly sampled coefficient array. The parent creates and retains those 529 private uint32 coefficients entirely in its own memory, generates the public SCO facade and hosts the real local HTTP service. The attacker child `sims/sco-dense-remote-client.cjs` receives only the service origin and its own legitimate credential. It fetches the public ESM over HTTP, extracts the protected method identifier from that served text and makes exactly 529 authorized calls, then emits its learned 529-coefficient model through stdout. After child termination, the parent verifies all 529 recovered coefficients and rank32, closes the HTTP server, and tests 1,028 offline heldout input/output pairs without another private RPC. Unauthenticated requests remain rejected with 403.

**Source-pinned full validation:** [GitHub Actions run 44957247961](https://github.com/FlareZ123/obfs/actions/runs/44957247961) at exact executable SHA `bdd9e6ecb51fcd7df666a6b65ec42b50f0a92f9c` **PASSED both Ubuntu and Windows** including this independent-process mode, full behavioral suite, strict JSDoc, and Ubuntu Chromium integrations. Merged through [PR #232](https://github.com/FlareZ123/obfs/pull/232) commit `196a089e317676feb60a6550e1a71bfbd1155d6a`. This is a distinct random sample per test/platform, with the same coefficient/heldout/authorization structural assertions.

The child and trusted server are two operating-system processes on **the same localhost machine** for reproducibility. This validates separation of their JavaScript heaps and rules out accidental in-process private-variable access by the actual learner. It is not a container, filesystem permission or operating-system sandbox proof, and it does not reproduce a remote internet attacker over TLS or a browser. The randomly generated private coefficients reside only in the parent process; the child never receives them through arguments, environment, source files or ordinary JS references. This remains a functional-cloning attack using permitted query responses, without compromising server authorization.

## Independent security dimensions

**Static source protection:** Private numeric coefficients remain on the SCO server; public ESM does not contain their declared array identifier. This checks the published source against one explicit leak marker and does not certify every possible source side channel.

**Dynamic functionality reconstruction:** Under legitimate unlimited RPC and the known degree-two class, the client can recover an exact functional model and all numeric coefficients. This is an authorized black-box oracle reconstruction. It does not recover arbitrary private program text, source order, variable names or unrelated state.

**Authentication, integrity and domain controls:** The unauthorized request remains 403. The attack does not bypass credential checks or protected code integrity and does not establish effectiveness of host locks.

**Performance and parity:** The private original deliberately reconstructs a dense array on each invocation; the test compares exact uint32 results, without a matched native-versus-transformed full-session CPU profile. The strict 2.5x runtime cap remains **unmeasured**. No claim is made for arbitrary JS values, dynamic reflection or compatibility beyond this numeric family.

**Decision:** Conditional on a passing source-pinned CI run, this would be a precise real-SCO transport witness of the known bounded-degree interpolation theorem with a full, independently randomized coefficient family. It does not by itself establish stronger practical obfuscation than an ordinary private authenticated service. Keep the primary strong-protection release blocked.
