# Error.stack carrier flow through catch and Promise handlers (2026-11-23)

**Status:** intermediate, source-pinned correctness evidence. Runtime: actual Node 22 ESM on Ubuntu and Windows. Compiler mode: COO, closedWorld, one file, properties on, identifier/string transforms off. **Global strong-protection release remains BLOCKED.**

## Behavioral mechanism

A private object owner is defined and read before a later `new Error` on the same source line. A later dynamic computed-key access, `error[['st','ack'].join('')]`, selects the native `Error.stack` string and extracts its producer frame. The compiler may rewrite the private field and change the **observable source column** while preserving an ordinary numeric return value (47). Local direct Error aliases are addressed by the separately documented [computed Error stack guard](https://github.com/FlareZ123/obfs/blob/agent39/dynamic-error-stack-source-20261123/im-results/dynamic-error-stack-computed-source-observer-2026-11-23.md), but a single direct constructor-to-member syntactic rule misses Error-carrier dataflow through additional language constructs.

### Catch binding

An ESM inline `try {throw new Error('source-location')} catch(caught) {frame=caught[key].split('\\n')[1]}` changes observed producer frame column **140→116** after actual COO obfuscation, while both programs export value 47. [Actual two-platform red 45152938428](https://github.com/FlareZ123/obfs/actions/runs/45152938428), test-only source `149f63813389e7299154880ba5ca74ee7083b830`. A bounded scanner patch collects `CatchClause` identifier bindings in the existing initial AST pass and treats them as potential Error carriers for **unknown computed** accesses; it covers their direct aliases by reusing the existing monotone Error alias flow. It also declines computed object-pattern extraction from a caught value. [Two-platform 5/5 focused green 45153347835](https://github.com/FlareZ123/obfs/actions/runs/45153347835), source `92a64795cd282e256c8861ca60d6e6a473d575e0`. The test explicitly retains private-field rewrite yield for a primitive catch and for a known `caught.message` access.

### Promise rejection callbacks

An ESM `Promise.reject(new Error('origin')).catch(caught => ({value,frame:caught[key].split('\\n')[1]}))` likewise exposes the rejected Error's producer frame. A checker that only labels a syntactic `catch` clause cannot see this callback value flow. The actual emitted source shifts column **163→139** with numeric 47 invariant; [two-platform red 45153653458](https://github.com/FlareZ123/obfs/actions/runs/45153653458), source `3fec8182cd1e376ca273805abe354802f79706f8`.

The scoped correction adds direct inline first parameters of `.catch(onRejected)` and second parameters of `.then(onFulfilled,onRejected)` to the potential Error-carrier set. [Focused two-platform green 45153871911](https://github.com/FlareZ123/obfs/actions/runs/45153871911), source `56a5d8986e5e2f5f066b7de86cdf1343b3bc7ba4`. A `Promise.resolve(primitive)` positive control still safely rewrites one unrelated owner field.

### Named callback definition

The callback may be named and passed by identifier: `function handler(caught){...} Promise.reject(new Error('origin')).catch(handler)`. The inline-only correction missed this case, changing column **236→212**; [two-platform red 45154095412](https://github.com/FlareZ123/obfs/actions/runs/45154095412), test-only SHA `efd83a8aac4d1c979d053817b2412fb98984e189`. A local pre-scan maps direct function declarations and const/variable-assigned function expressions to their first simple formal parameter. A following set intersection with direct `catch(handler)` or `then(...,handler)` identifiers marks only those formals as potential Error carriers. [Focused two-platform green 45154303839](https://github.com/FlareZ123/obfs/actions/runs/45154303839), executable SHA `f2e8bb0643ea501e74cbcd806bfa761d49c9e7b8`. **This is syntactic may-flow, not a full scope-sensitive or interprocedural alias proof.**

## Scope and decision implications

A direct AST name- or callback-pattern guard is deliberately conservative. It may refuse unrelated source edits when variables share names in different scopes. It does not prove safety of rejected Errors relayed through arbitrary function calls, `.catch` method aliases, callback variables with multiple assignments, destructured parameters, imported handlers, dynamic computed method names, Promise subclass behavior, asynchronous work queues, arbitrary host callbacks or custom stack formatters. The JavaScript value graph is open-ended; trusted-host provenance and a scope-aware may-flow are preferable to an indefinitely growing set of syntactic exceptions. A global source-observer veto is safe for exact stack preservation but sacrifices useful private-owner transformation yield, previously quantified in the [host source observer matched yield study](https://github.com/FlareZ123/obfs/blob/agent39/host-stack-callback-iife-20261123/im-results/strict-iife-host-stack-callback-source-witness-2026-11-23.md).
