## What this result does and does *not* establish

**Established under this narrow test:** an independent off-the-shelf deobfuscator can transform the self-contained published math bytes into **executable, standalone public-math clones** passing the same fixed typed-return and full-app trace oracles as ordinary minification. Source code remains public and includes its functional entry points. The deobfuscator result is not merely formatted text that crashes at runtime.

**Not established:** recovery of the *original source formulas* (explicitly reported `staticOriginalFormulaRecovered: "not measured"`), a security advantage or disadvantage **beyond** this fixed test, integrity or domain-lock bypass, resilience to instrumented browser analysis, context-sensitivity under arbitrary host callbacks or source observation, anti-LLM performance, binary/bytecode reconstruction, or CPU-budget compliance. A clone that passes tests is distinct from original source recovery. The comparison also does not infer equivalence for all possible inputs (finite corpus).

**Selection significance:** both published protected output and ordinary minification remain executable after **the same** offline third-party transform. This fixed behavioral clone test offers **no quantified incremental protection advantage** relative to the matched minifier; it does not measure original static formula recoverability. The repository's existing stronger source-only chosen-query/clone test and adversarial protocol tests independently reject strong-protection promotion; this test supplies a previously missing third-party reproducibility check and explicit full-graph oracle, not a new release verdict.

[Actions run 46116494133](https://github.com/FlareZ123/obfs/actions/runs/46116494133), exact audit branch source `7d4a0f32c5dcf788ea07a736e352152e9eef48ec`, **passed Ubuntu and Windows**; Ubuntu additionally completed the **real Chrome 158.0.8127.36** recovery control. The server counted **12 real .mjs fetches**. Both source-only recovered graph variants matched native exact returned application text and external `emit(item)` callback trace for *each* of 1, 17, 50, 1,000 and 10,000 stateful events with mixed Unicode payloads. The observed native callback count equaled the requested event count on every workload (nonvacuous source observation).

The **host-drop negative control** removes only the external `emit` effect while preserving every application's serialized return byte. The earlier number→string mutation control independently tests strict typed return comparison. **Crucial interpretation:** a public browser math module is executable *even before* this external deobfuscator transforms it; a literal copy of those published bytes already implements the same function. Therefore **behavioral cloning alone does not measure extra attack cost**, algorithm reconstruction, static formula readability, anti-instrumentation, stronger tamper resistance, URL-lock bypass, or superior security to identical-trust minification. This check verifies that a separate maintained third-party tool and real browser can preserve the prescribed observable behavior with exact negative controls. Static **original-source formula recovery remains unmeasured**. PR384 remains **RELEASE-BLOCKED** on separate compatibility/yield, adversarial resistance, and 2.5× performance grounds. This is supporting evidence in `im-results/`, not an academic security result or promotion recommendation.


**Methodology clarification (28 November):** The term *source-only* denotes the data supplied to the attacker tool—published JavaScript only, no original reference, target server or live browser oracle. It does **not** certify that Webcrack's implementation is pure static parsing; Webcrack's documented optional VM/sandbox capability may evaluate decoder code internally. This particular invocation did not supply a custom sandbox, but the absence of an explicit option is insufficient to assert no internal execution. Findings are consequently described as an **offline local source-input transformation**, not a proof of a static-only attack. Neither original-formula reconstruction nor differential attacker cost was measured.


## Denied-VM source-input control — exact-head two-OS success (28 Nov 2026)

The original `webcrack@2.16.0` no-custom-sandbox invocation (runs [46115860740](https://github.com/FlareZ123/obfs/actions/runs/46115860740) and [46116494133](https://github.com/FlareZ123/obfs/actions/runs/46116494133)) did not establish whether Webcrack internally **ran decoder snippets**. Upstream Webcrack documents a configurable sandbox for string-array decoding, so the absence of a user-supplied sandbox is **not** evidence of pure static transformation. To bound the claim, an isolated [explicit no-VM research branch](https://github.com/FlareZ123/obfs/tree/agent8/pr384-webcrack-no-vm-sandbox-20261128) forces `sandbox:async()=>{count++; throw Error(...)}` for **both** the offline Node and actual Chrome-source-recovery transformation phases, and strictly fails if **any** callback was invoked, even when the transform caught the thrown error. The production obfuscator/application sources remain identical to PR384 `a8a22f9a...`.

**Final exact-head [run 46118176507](https://github.com/FlareZ123/obfs/actions/runs/46118176507), audit source `0f7f0e83f38ffbe6d0ec63121761646c88718f29`: SUCCESS Ubuntu + Windows, including strict JSDoc and real Chrome 158.0.8127.36.** Webcrack's VM sandbox callback was invoked **zero times** for both ordinary-minified and protected-published public math in both OS Node transformations, and zero times for both recovered browser graph transformations on Ubuntu; the four emitted source hashes remained byte-for-byte identical to the previous offline audits (minified input `d783d9e9...` → `eca85c19...`; published input `90755340...` → `f613a394...`). Existing typed 12,288-per-variant returns, the fixed stateful Node trace, real-browser 12 ESM fetches and event workloads 1/17/50/1000/10000, plus strict typed and host-drop negative controls, also passed.

This **specific** successful transformation therefore **did not call Webcrack's configured VM evaluation callback**. This does **not** certify that all of Webcrack's other internals are non-executing, that deobfuscation rather than unminification generated the output, original formula recovery, or advantage against a browser attacker. The no-VM result is a tool-mechanism attribution/strengthening of the fixed behavioral-clone receipt, not a standalone novel cryptanalytic attack. A further `deobfuscate` versus `unminify` stage-ablation is in progress separately and must be reported only after its own source-pinned CI receipt.


## Decisive tool-stage attribution — **no specialized deobfuscation observed** (28 November 2026)

The word *deobfuscation* in the tool's product name and our initial audit is **not** a mechanistic result. A final [four-stage ablation branch](https://github.com/FlareZ123/obfs/tree/agent8/pr384-webcrack-stage-ablation-20261128) compares the **exact same frozen 377-byte minifier and 5,863-byte protected math public inputs** through `webcrack@2.16.0` with `{deobfuscate:true/false,unminify:true/false,unpack:false,jsx:false}`, while an explicitly injected VM sandbox counts and refuses every evaluation request. The exact-head [run 46118328396](https://github.com/FlareZ123/obfs/actions/runs/46118328396), source `197f1019db50be9b2d4221e4bde36badb79bd99d`, was **SUCCESS on Ubuntu and Windows** including strict JSDoc, and both OS report the **same stage digests**:

| Public input | `deobfuscate=true,unminify=true` | `deobfuscate=false,unminify=true` | `deobfuscate=true,unminify=false` | `deobfuscate=false,unminify=false` |
|---|---|---|---|---|
| Ordinary-minified math (377 B) | 550 B, SHA-256 `eca85c19f4abe82f...` | **identical 550 B** | **identical 550 B** | **identical 550 B** |
| Published-protected math (5,863 B) | 7,342 B, SHA-256 `f613a3944b04c212...` | **identical 7,342 B** | 7,343 B, SHA-256 `5e3aa3f2fed1de56...` | **identical 7,343 B** |

All eight source/option combinations used **zero Webcrack VM sandbox calls**. At fixed `unminify` value, **switching Webcrack's specialized `deobfuscate` stage on or off changes *zero bytes*** in either public input. The unminifier changes one byte of the protected module's parser-roundtrip output, whereas the minifier input gives exactly the same output for all four option sets. Thus the earlier output-size, behavioral-cloning, and real Chromium evidence **does not demonstrate that Webcrack applied any deobfuscation-specific transformation to PR384**. The transform observed was parser/generator round-trip plus an optional minimal formatting pass, and the same public executable program functionality was already available before transforming it.

**Security selection correction:** Do **not** cite the Webcrack behavior-clone audit as an independent recovery of obfuscation algorithms, original source formulas, hidden constants, or attack cost improvement. It is a valuable **tool compatibility, parser round-trip, full-application oracle quality, and negative-control** result; the project's separate, source-pinned chosen-query/static recovery controls remain the stronger adversarial evidence. This distinction materially limits the prior summary's implied 'deobfuscation' value but does not negate the behavior tests or the existing **RELEASE-BLOCKED** finding. All ablation JSON artifacts and actual Webcrack outputs are archived in the [run's artifacts](https://github.com/FlareZ123/obfs/actions/runs/46118328396).
