# SNO local-owner manifest bypass: behaviorally verified

Date: 2026-11-15. Agent 7. Intermediate adversarial result with a fully reproducible native Node attack.

## Attacker model

In SNO, the attacker owns the obfuscated server's filesystem and Node runtime. The launcher generated by `createSnoLauncher` stores a SHA-256 list of the protected output files and checks those hashes before requiring the entry. No remote signature verifier or independently trusted root of hash values participates.

The attack in `sims/sno-self-hash-bypass.js` uses the real public SNO transformation and launcher. The initial protected entry imports `policy.cjs` and prints `{"access":false}`. The attacker replaces the on-disk `entry.cjs` with a tiny script printing `{"access":true}`. With the original launcher, the integrity check correctly rejects the tampered entry. The attacker then computes SHA-256 of the modified entry and replaces the *public expected entry digest* in `sno-entry.cjs`. Running that patched launcher executes the attacker's modified entry successfully. The attacker does not forge a hash collision, defeat SHA-256 or need the original source.

## Native result and reproducibility

- Implementation: `sims/sno-self-hash-bypass.js` with fresh temporary files and `src/atomic.js` locked atomic writes.
- Regression: `test/sno-self-hash-bypass.test.js`.
- Manual-only Windows and Ubuntu workflow [43691613602](https://github.com/FlareZ123/obfs/actions/runs/43691613602) ran at commit `e94d5346c7f5efc1f56f73fbb70f2b916fda89f4`. Both platforms passed the native Node regression, the stand-alone attack, and strict JSDoc type checking.

## Interpretation

The manifest catches **incidental corruption or isolated file tampering when the manifest remains trusted**. Under the specified SNO owner-controls-filesystem adversary, the expected hashes live beside the checked files and are themselves mutable. Thus a matching local digest cannot authorize execution or establish that the executed code is original. The result is a concrete bypass of a *local policy assertion* under the stated model, not a cryptographic SHA-256 failure.

If a deployment requires anti-tamper guarantees against the machine owner, it needs an independent trust anchor, signed-policy enforcement outside that owner's control, or suitably specified hardware/remote attestation. This repository's SNO launcher does not provide those. The result supports SNO's existing conservative threat-model description and gives a repeatable negative control for future purported local-only integrity defenses.
