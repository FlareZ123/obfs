# Process-separated two-state SCO exact public clone versus a matched minified RPC

**28 Nov 2026 — intermediate reproduction and hard negative control, not a release claim.**

## Research question and finite class

The declared source family is binary-input/binary-output, deterministic stationary Mealy with a known initial state zero, at most two states, and no reset endpoint. The attacker knows the class but not the actual private transition/output table. Exhaustive labelled enumeration contains four one-state and 256 two-state tables (260 total). The oracle is a single evolving authorized session, so current states of all surviving hypotheses are updated, never rewound.

The independent uncompressed learner in `sims/sco-two-state-optimal-network-policy.js` constructs **4,429 reachable beliefs before terminal certification** (344 certified, 4,085 nonterminal). A first version expanded terminal beliefs and incorrectly reported 4,501, including 72 post-certification descendants which an actual learner never visits; this was corrected. Finite product equivalence determines whether every current hypothesis has identical future output for every possible future input. Simultaneous minimax Bellman layers give a **nine-request root rank**, and each nonterminal belief/input has a nonempty response child of rank at least parent rank minus one; this yields the global eight-query impossibility certificate for this *trusted-bound* class. Every source table is independently replayed and clone-checked.

For the uniform prior over 260 labelled source tables, a separate finite-horizon weighted Bellman learner with strict worst-case cap 9 has **aggregate public query cost 1,884**, mean **7.246153846** and exact histogram `6→40, 7→156, 8→24, 9→40`. This reproduces the earlier finite-model optimum in `im-results/sco-two-state-minimax-2026-11-23.md` on Agent49's research branch; it is not a novel general learning theory. The independent rank-decreasing tie-first policy instead totals 2,016 calls; a nine-query worst-case optimum does *not* imply expected-cost optimality.

Under a uniform prior over the **260 labelled source tables**, the initial rooted semantic equivalence classes have a highly skewed distribution: 144 singleton classes and four classes of 29 source tables each, for 148 distinct initial behaviors. The Shannon entropy of that initial class variable is **5.8549609075 bits**. This is descriptive, **not** an unconditional lower bound on the expected number of active no-reset requests: chosen inputs can synchronize previously distinct machines into the same *current* continuation behavior without identifying their initial class. The full state-updating Bellman recurrence, not a naive static coding-theory bound, establishes the nine-call worst case and 1,884-call finite-source-prior optimum.

## Bound-falsification control

The upper-bound assumption is **not inferable** from a finite public transcript. In the offline regression, the three-state rooted base-6 source ID **52** has transitions `[[2,1],[0,0],[0,0]]` and outputs `[[0,0],[1,0],[0,0]]`. The uniform-labelled two-state-prior nine-cap learner stops after seven legitimate queries, input transcript `0,1,0,1,1,0,0` and output transcript `0,0,0,0,0,1,0`, believing its next-state clone is equivalent. The actual state is 2 and the hypothesized clone state is 1. The single unqueried continuation `0` gives **actual 0 versus cloned 1**. A dedicated test pins these values and verifies product-automaton inequivalence. This is an *out-of-class counterexample*, not a failure of the proved within-class nine-call certificate.

More generally, without any upper bound on states, no finite adaptive no-reset observation transcript can prove behavior on every future word: construct one new state for each observed request, replay exactly the observed outputs along the actual path, then assign one later output at the terminal state to disagree with the purported clone. Finite path-extension models are stationary deterministic Mealy machines, so every finite observation remains consistent with a later divergence. This elementary impossibility is not claimed as a novel learning-theory result.

## Live server/client separation and equal-trust control

`sims/sco-two-state-process-boundary.js` creates a real trusted server process that generates a random two-state table and a private canary in memory. It compiles an actual `partitionScoAsyncModule` async ESM facade, binds its private server method, and publishes that generated module through `createScoHandler` with cookie authorization, explicit method/argument checks and no public reset. The private table and generated private ESM are **never written to shared filesystem**. A second service on a distinct loopback port keeps an *independently advancing* copy of the same server-private table and serves an ordinary esbuild-minified ESM RPC client. Both clients use the same request path, hashed method identifier, JSON `{method,args}` envelope, legitimate cookie, response `{ok:true,value}`, and successful output semantics; both deny unauthenticated operations with HTTP 403.

A separately forked attacker process receives only the two public origins and the legitimate cookie. It downloads both ESM facades over HTTP, imports them, and runs the same nine-cap weighted attacker against each. The two semantic learner transcripts, 16 fresh post-learning continuations, and offline stateful clones must agree. The client-side observation tap compares fetch pathname, options, JSON request body, response status and response text for *every* learned/followup call across the two arms; this is a pre-network fetch/JSON comparison, not a TCP/TLS packet or full header-capture guarantee. Private true state/table become available to the test evaluator via a separate IPC snapshot **only after the attacker process exits**; an independent product check verifies all future continuation words.

The attacker child starts with no inherited application/service environment. The usual two-OS test uses distinct Node processes under the same OS account. The dedicated Linux CI stage now keeps the evaluator and trusted server as the ordinary runner account and executes only a **standalone public attacker program** via `sudo -n -u nobody node` in a world-traversable temporary directory. The public program imports only a separately copied public finite-state learner; neither the private server implementation, its temporary private source nor its random table is copied. Authorization cookie and origin are sent on an explicit newline-JSON pipe. The target child has UID/GID 65534 and should receive `EPERM` on `process.kill(trustedServerPid,0)` while still learning via authorized HTTP. This is a concrete account permission check, not a hardened sandbox or a full remote-browser isolation proof; path permissions and sudo policy are runner-specific.


### Real-browser boundary extension (pending independent CI)

`sims/sco-two-state-browser-live.js` loads the compiler-generated SCO client and an ordinary minified RPC client as **actual same-origin Chromium ESM modules** in separate headless sessions, using HttpOnly browser cookies and reverse proxies to the separate trusted Node service. Each page runs the public nine-cap weighted learner and 16 post-learning live calls; the evaluator compares public browser RPC method/argument/result traces from both reverse proxies, and obtains the trusted private-state snapshot only after both browser processes exit. This is real browser code execution and real HTTP requests, but the reverse proxies and evaluator remain on the server host; no proof of a remote adversary sandbox or additional security over ordinary RPC is implied. At the report-update time, the final-source CI verdict is still pending. A browser tool failure is an environment/test failure unless parity mismatch is separately demonstrated.

## Exact validation and limitations

- **Actual-library initial pin** `9be57e5fbf7165edfdb30bc5ecbbb05d03a60968`, [workflow 46155701456](https://github.com/FlareZ123/obfs/actions/runs/46155701456): full manual SCO oracle workflow **green on Ubuntu and Windows**, including initial process-separated live SCO vs ordinary RPC test and both strict JSDoc gates. This pin predates terminal pruning, weighted nine-cap policy, differential-UID Linux step and transport alignment. It validates only the earlier narrower test.
- **Updated intermediate pin** `1bbd707cebdff6fa967eaff103bf724f52313bfe`, [workflow 46156398363](https://github.com/FlareZ123/obfs/actions/runs/46156398363): Windows **green**; Linux **red in the different-UID stage** (`Child exited before attacker-result: 1`). Regular Linux SCO/process tests passed. The cause is a test-harness path-access issue under the runner UID; no compiler source-parity failure observed at this pin.
- **Protocol-aligned pin** `5bda017ca0587eba7f54e2fccc699675f07b5be8`, [workflow 46156575176](https://github.com/FlareZ123/obfs/actions/runs/46156575176): Windows **green**, Linux again **red only in the Linux different-UID stage**, where running the checkout-local attacker source under `nobody` failed before RPC. A later correction copies standalone public program/learner into `/tmp`, and a safer refinement avoids executing the repository test as root. Neither correction is covered by the earlier green pins.
- Local Node 22 prototype exercised 260 exhaustive offline source models and 30 separate-process random client/server runs, including Linux different-UID comparisons. Local tests used an API-compatible SCO stub and cannot substitute for actual compiler evidence. The local Chrome binary stalled even for `about:blank`, so a real Chromium run is CI-only pending a source-pinned check.

Reproduce: `npm install --no-package-lock --ignore-scripts`, `node --test test/sco-two-state-process-boundary.test.js`, `npx tsc -p jsconfig.sco-oracles.json`; for the dedicated different-UID test on a Linux CI host with passwordless `sudo -u nobody` access, run `OBFS_SCO_UID_TEST=1 node --test test/sco-two-state-process-boundary.test.js`. The evaluator must **not** run as root; the public child alone executes as `nobody`. Chromium: `CHROMIUM_BIN=google-chrome node sims/sco-two-state-browser-live.js` on a host with a functional headless browser. Never run untrusted source as root.

**Scope:** The binary upper bound is assumed, not discovered; private code source template/model family is known from the research harness, but the realized table is not transmitted on the public interface. A same-UID malicious process may still try local OS debugging; the Linux different-UID step mitigates one such pathway but does not model a fully remote hostile client or a hardened container. This experiment does not prove resistance to static/dynamic extraction of arbitrary source, browser interoperability, WAN/TLS latency, unauthorized token theft, multisession side effects, server compromise, anti-LLM robustness, nor the mandatory **2.5× target compute bound**. Attacker-side learning time is outside that runtime budget. The online authorized relay remains possible and ordinary RPC has the same server-private trust boundary: **no incremental obfuscation advantage is established here**.

**Decision:** strong-protection RELEASE-BLOCKED/NO-GO remains unchanged. This is a reproducible research attack and a better isolation/equal-trust comparator, not a proposed production compiler patch.
