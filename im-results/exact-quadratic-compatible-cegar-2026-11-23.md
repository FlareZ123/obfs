# Exact 529-query cloning followed by deterministic CEGAR inversion

**Status:** Intermediate research result; reproducible implementation and tests, not an established universal result.

**Owner:** Agent 2  
**Date:** 2026-11-23

## Result

The repository's nonlinear triangular compatible-permutation generator is a vector-valued Boolean polynomial of algebraic degree at most two. Its degree remains at most two after arbitrary affine input/output wrappers and translations. Reusing the existing bounded-degree oracle learner, an attacker can therefore clone the entire 32-bit function with exactly

\[
N_2=\sum_{j=0}^{2}\binom{32}{j}=1+32+496=529
\]

chosen oracle queries.

The new contribution here is the deterministic inversion step applied to that clone. For a quadratic Boolean map, the second-difference defect is bilinear. The complete defect span for every current input subspace can consequently be computed from basis-pair evaluations of the local clone, rather than estimated using random anchors and probabilistic validation. An exact CEGAR peel then recovers a compatible input/output flag and inverts target outputs offline.

The clone primitive itself is not new: this work reuses `sims/bounded-degree-oracle-functional-clone.js` and the live-query machinery in `sims/sco-quadratic-529-live-clone.js`. The new result is the exact quadratic defect certification and its composition with the existing compatible-triangular CEGAR method.

## Source family and algebraic degree

The source is `makeTriangularCompatiblePermutation` in `sims/compatible-permutation-linear-sandwich-blackbox.js`. Its output bit has the form

\[
P_j(x)=x_j\oplus \ell_j(x_{<j})
       \oplus \bigl(a_j(x_{<j})b_j(x_{<j})\bigr)\oplus c_j,
\]

where each of \(\ell_j,a_j,b_j\) is a GF(2)-linear form. Thus every output coordinate has algebraic degree at most two. If

\[
F(x)=L_{out}\,P(L_{in}x\oplus b)\oplus a,
\]

with invertible linear maps and arbitrary translations, composition preserves the degree-two bound.

This is Boolean algebraic degree, not integer-polynomial degree. In particular, the repository's `makeRivestPermutation` integer-polynomial degree labels must not be substituted for a GF(2) algebraic-degree bound.

## Exact clone from 529 queries

Let \(e_i\) be the standard basis vectors. The 529 queried points are

\[
0,\quad e_i,\quad e_i\oplus e_j\quad (i<j).
\]

For the vector-valued ANF coefficients:

\[
\begin{aligned}
c_\emptyset &= F(0),\\
c_i &= F(e_i)\oplus F(0),\\
c_{ij} &= F(e_i\oplus e_j)\oplus F(e_i)\oplus F(e_j)\oplus F(0).
\end{aligned}
\]

The exact clone is

\[
\widehat F(x)=c_\emptyset
\oplus\bigoplus_{i:x_i=1}c_i
\oplus\bigoplus_{i<j:\,x_i=x_j=1}c_{ij}.
\]

These coefficients uniquely determine every degree-at-most-two Boolean map, so this is an algebraic identity over the entire 32-bit domain, not an extrapolation from the holdout set. The held-out evaluations below are implementation checks.

## Exact defect certification and inversion

Define the second-difference defect

\[
Z(x,v)=F(x)\oplus F(x\oplus v)\oplus F(0)\oplus F(v).
\]

For a degree-at-most-two Boolean map, each coordinate of \(Z\) is bilinear in \((x,v)\). Consequently, if \(U\) is the current input subspace with basis \(u_1,\ldots,u_k\), then the span of every defect

\[
\{Z(x,v):x\in\mathbb F_2^{32},\ v\in U\}
\]

is exactly generated by the finite set

\[
\{Z(e_i,u_j):0\le i<32,\ 1\le j\le k\}.
\]

The implementation computes this span from the local clone. Its orthogonal complement supplies output masks that annihilate every defect, not merely sampled defects. For each accepted mask, the scalar output difference is therefore independent of the base point on the current input subspace. The input and output kernels can be split and peeled recursively, as in the existing linear-sandwich CEGAR method.

After 32 peels, the resulting output masks and input toggles invert a target by starting at zero and applying the corresponding input toggle whenever the current output residual has odd parity under that level's output mask. A final equality check against the local clone is mandatory.

The exact peel performs 16,896 local basis-pair defect evaluations per instance:

\[
32\sum_{k=1}^{32}k=32\cdot528=16,896.
\]

These are evaluations of the reconstructed function, not additional server queries.

The bilinear defect certificate is exact under the degree-two promise. The tested compatible-triangular family also completed all 32 peel stages in every trial. We do not claim that this particular greedy candidate ordering is complete for every arbitrary degree-two permutation; the general candidate-selection question remains open.

### Live SCO and matched ordinary-service control

`runChallenge` starts both a real `createScoHandler` service and a conventional HTTP RPC service. They use the same private ESM module, hashed method identifier, credential, input validation, endpoint, and response envelope. The public SCO facade omits the private triangular parameters and affine matrices.

For the same seed:

- SCO: 529 authorized oracle calls and 529 private executions.
- Ordinary HTTP control: 529 authorized oracle calls and 529 private executions.
- The query transcripts matched exactly.
- Both services denied unauthenticated calls with HTTP 403.
- Both servers were closed before held-out comparison and target inversion.
- The two local clones matched 1,028/1,028 held-out inputs.
- The exact offline peel inverted 20/20 targets after shutdown.
- No additional private executions occurred after the 529 fitting calls.

This is an oracle-information result, not a transport-specific SCO protocol bypass: the matched ordinary service exposes the same function and leaks the same information.

### Relation to existing work

The existing sampled CEGAR report, `im-results/compatible-permutation-linear-sandwich-blackbox-2026-11-18.md`, measured 14,120–14,215 oracle queries across its 64 nonlinear-triangular cases. This pipeline uses 529 fitting queries for a full degree-two clone; all subsequent CEGAR work and target inversion are local. The ratio for the first target is approximately 26.7x fewer server oracle calls. The approaches are not otherwise identical: this pipeline relies on the explicit Boolean degree-two promise and exact ANF clone.

The existing `sims/quadratic-radical-target-inversion.js` is complementary. Its configured maximum radical codimension is 16, whereas these fixtures had observed codimensions 29–31. This exact CEGAR path does not enumerate radical cosets.

## Limitations and next work

1. The 529-query theorem applies to Boolean algebraic degree at most two. It does not automatically apply to arbitrary JavaScript, arbitrary permutations, or the repository's integer-polynomial Rivest family.
2. Exact defect certification depends on the degree-two promise. For higher Boolean degree, the defect is no longer bilinear; a higher-order certificate or a different exact interpolation strategy is required.
3. The inversion peel additionally relies on the compatible triangular/linear-sandwich structure. The 64-instance success is strong empirical evidence for the repository generator, not a universal theorem for every quadratic permutation.
4. The radical-codimension comparison is configuration-specific: the existing radical solver's current cap is 16, while these fixtures lie outside it.
5. The result rules out this low-degree oracle family as a confidentiality mechanism under chosen-query access. It does not establish a break of the general JavaScript obfuscator or resolve all SCO/COO/SNO threat models.

A separate rank-only flag-search experiment was not retained: it worked on a lazy-uniform random truth-table triangular model but failed on the repository's actual quadratic generator. The exact ANF-plus-bilinear-CEGAR path is the reproducible result.
