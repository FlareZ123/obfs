# CSSOM source observation across an ESM import boundary

**Intermediate browser/Node source-observation investigation, 23 November 2026, Agent 1.** The core finding is an independent, two-module executable counterexample. This report distinguishes native Node ESM execution with a modeled CSSOMString coercion from subsequently tested actual Chromium.

## Reproduction and source pin

`test/cssom-interfile-source.test.js` is on the isolated `agent1/cssom-setproperty-source-20261123` branch. Exact first corrected semantic source: `a6ecf1fee38947d8f9ff03c5a540925ebca96ae0`, [two-platform focused run 45099996312](https://github.com/FlareZ123/obfs/actions/runs/45099996312). The test creates temporary `logic.mjs` and `observer.mjs` files and imports them via Node's real native ESM loader. CSSOMString conversion is provided by a minimal test-owned `document.createElement(...).style` adapter outside the code being obfuscated. It is a behavior model, with actual Chrome checked independently in `test/cssom-interfile-source-browser.js`.

Producer `logic.mjs`:

```js
const externalOwner={observedSecret:31};
const independent={otherSecret:73};
export function inspect(){return externalOwner.observedSecret;}
export const independentValue=independent.otherSecret;
```

Consumer `observer.mjs`:

```js
import {inspect,independentValue} from "./logic.mjs";
const style=document.createElement("div").style;
style.setProperty("--observed",inspect);
export const observed={
  text:style.getPropertyValue("--observed"),
  value:inspect(),
  independent:independentValue
};
```

Compile with `obfuscateFiles` over **both declared files** in COO mode and `closedWorld:true`, `properties:true`, `identifiers:true`, `strings:false`. The compiler rewrites **two private properties in the producer** while leaving the consumer bytes unchanged.

## Grounded outcome

Both Ubuntu and Windows Node 22 emitted:

- Original `observed.text`: `function inspect(){return externalOwner.observedSecret;}`.
- Obfuscated `observed.text`: `function inspect(){return externalOwner._p92efdae919;}`.
- Original and emitted numeric values: 31 and 73 in both.
- Compiler metrics: **properties=2**, `producerBytesChanged=true`, `observerBytesChanged=false`, exact output parity **false**.
- Independent literal-valued positive: `style.setProperty("--observed","literal")`. The independent private record property **was renamed** (`properties=1`) and native/emitted output parity **passed**.

Each OS had one deliberately red source-parity assertion and one green transformed positive. The callsite in the supplied observer graph carries the host capability; the producer module has no lexical syntax indicating the implicit native conversion. Because this compiler was passed the entire ESM graph, the observed defect cannot be dismissed as a missing external consumer.

An initial test fixture incorrectly implemented `String(value)` **inside the consumer source**. The compiler's existing conservative explicit-source observer then refused all private rewrites and made both cases superficially pass with `properties=0`. That result was discarded; the model is now exclusively outside the compiled source graph, and the input uses the browser-shape `document.createElement(...).style` expression. This is the same critical test-harness confound seen during the 10-sink native matrix.

## Integration requirement

A source-preservation obligation generated by a proven host receiver in one module must reach imported functions and their source-spelled property/key dependency class in another. A safe fix preserves original function source, numeric outputs, and external owner-key spelling, while retaining renaming opportunity on independent private owners. Native browser verification, strict JSDoc and whole-program performance evaluation are separate gates. This file supplies source-pinned intermediate evidence and no production fix.

The design interacts with the [source-owner closure proposal](../workplace/agent1-source-observed-owner-closure-2026-11-23.md) and Agent 19's [Web IDL capability graph](../workplace/webidl-source-coercion-capability-graph-2026-11-22.md). Agent 3 remains canonical source-observer integration owner. The project release remains **RELEASE-BLOCKED**.

## Native Chromium independently confirms the full two-file failure

**The native-browser validation is now complete.** Exact isolated source
`c908c4afa4a224f295eb2cf6c9806bf69a59cf91`,
[Chrome Actions run 45100434323](https://github.com/FlareZ123/obfs/actions/runs/45100434323).
The specific `Audit native Chromium cross-file CSSOM imported callback source`
workflow step **passed**, as did the unified 12-sink Web IDL capability
diagnostic. The overall full-browser job is red at a **later, intentionally
failing direct CSSOM parity regression**, not from this audit.

The runner served four independent **two-file** ESM graphs over localhost:
native negative, emitted negative, native literal positive, and emitted
literal positive. In the native negative, `logic.mjs` exported `inspect`;
`observer.mjs` imported it and passed the live function directly into a
real browser `CSSStyleDeclaration.setProperty`; its subsequent
`getPropertyValue` exposed exact function text. The browser readback,
preserved in [raw JSON](cssom-cross-file-native-chromium-2026-11-23.json),
was:

| Browser graph | Native function source readback | Numeric `inspect` | Independent value | Actual compiled property rewrites |
| --- | --- | ---: | ---: | ---: |
| Original negative | `function inspect(){return externalOwner.observedSecret;}` | 31 | 73 | n/a |
| Emitted negative | `function inspect(){return externalOwner._pff6f317b03;}` | 31 | 73 | **2** |
| Native primitive positive | `literal` | 31 | 73 | n/a |
| Emitted primitive positive | `literal` | 31 | 73 | **1** |

The negative has exactly matching numeric outputs but differing source
strings. The positive has matching strings and numbers while the
transformed graph still contains one renamed private key. The
`closedWorld:true` emitter received the full two-file graph. This
eliminates the ambiguity of a test-only DOMString coercion stub from
the earlier Node ESM result, though only one browser engine and one
finite pair of input programs are covered.

**Cross-file owner/key propagation is a concrete correctness blocker**.
An observer in one file imposes a source-preservation requirement on
a producer in another file; the consumed callable's original source
text refers to an object property defined outside that function.
A guard that only recognizes the setter in the consumer file or
only freezes the callable body is insufficient when outer owner
keys are rewritten. Selective integration must retain its
independent private-key positive; the current source is not release-ready.

This evidence localizes the same missing implicit native-source dependency
to the shared cross-mode file-graph emitter. It does not establish SNO

equivalence under production launchers, or a unique weakness in an
obfuscation strategy compared with ordinary minification. The real
Chromium cross-file observation above establishes the browser-specific
coercion and is deliberately kept separate from this all-mode Node model.

## Controlled explicit-source conversion establishes the missing classifier

The same two-file graph with only the consumer changed from
`style.setProperty("--observed",inspect)` to
`style.setProperty("--observed",String(inspect))`
was tested at exact `0f6c753d210e8071a873260d2d5434e0ca433ffc`,
[two-platform focused run 45101144402](https://github.com/FlareZ123/obfs/actions/runs/45101144402).

For **all COO, SCO and SNO**, the explicit conversion preserved source
parity and the producer/consumer **source bytes were unchanged**:
`properties=0`, native and emitted source both
`function inspect(){return externalOwner.observedSecret;}`. In
the *implicit* host-coercion case of the exact same two-file template,
all three modes instead rewrote two private properties, changed visible
function source, and preserved numeric behavior. The literal-valued
positive in each mode successfully rewrote one independent private
field and remained equivalent.

The focused suite had **three intended red implicit negatives,
three green literal positives and three green explicit-source
controls**, consistently on Ubuntu and Windows. This is evidence
that a source-preservation mechanism for **explicit** stringification
already reaches across this supplied file graph, while recognizing
the **implicit native host receiver** remains missing. The explicit
fallback's zero private-field yield is measurable integration debt,
and a future receiver-aware closure must preserve source without
automatically suppressing unrelated owner renaming. This does not
prove completeness of explicit source-observer analysis for other
JS syntax or cross-file graph patterns.
