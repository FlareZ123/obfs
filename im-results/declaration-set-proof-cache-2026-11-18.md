# Parsed-AST declarator membership cache: reproducible private-owner build reduction

**Agent 4, 18 November 2026. Classification: bounded intermediate compiler engineering result.**

## Change and safety boundary

In `src/properties.js`, `proveLocalObject` constructed `new Set(declarations)` for every candidate private owner, even though `declarations` is already cached by parsed-AST identity in `collectProofInventory`. The same immutable `AstNode` declarator set is only queried through `.has` in the tuple/record holder checks. The candidate builds this set **once** in the existing `WeakMap` proof inventory and reuses it for every owner proof. The AST, declaration order, owner-specific aliases, scope gates, and rename decisions are unchanged. This follows Agent 2's previous root-independent AST inventory work and does not require a new runtime transformation.

The combined compiler source preserves all prior conservative refusal rules. `WeakMap` entries are keyed by the parsed AST, with no persistent global key cache across separate parses. This optimization assumes the proof uses immutable parsed ASTs; manually mutating and reusing internal AST objects is outside the existing cache contract.

The existing [manual workflow](../.github/workflows/manual-private-in-cold.yml) exposes these optional inputs. Each child compiles a real one-file CommonJS app, checks the exact number of renamed private keys, and executes native and emitted code. The script atomically swaps one locked compiler source file in an isolated CI checkout, then restores it. Every pair must have **exactly the same SHA-256 output digest** and the same nonvacuous execution checksum. The benchmark separately records compiler CPU and wall time, excluding generated application runtime.

## Controls, caveats and acceptance criteria

The 512-owner corpus also preserved exactly 512 rewrites and exact emitted bytes, with CPU control/cached ratios of 1.085× Ubuntu and 1.048× Windows. The mixed alias/tuple/record/reader/reflective corpus retained 28 rewrites and identical source. The 4,096 ordinary-binding *sparse* control, with only **two** private owners, emitted identical bytes and showed CPU ratios 1.008× Ubuntu and 0.990× Windows. These small/noisy cases prevent a claim of universal throughput improvement or no possible regression.

The same-run A/B reduces independent machine-load confounds but uses only four large-case samples, no randomized runner allocation and no confidence interval. Compiler-build improvement is valuable for handling large code bases; it is **outside** the user's 2.5× runtime budget and makes no source secrecy, anti-debugger or environment-locking claim. The [full Node 22 Ubuntu/Windows and Ubuntu Chromium integration 44313266699](https://github.com/FlareZ123/obfs/actions/runs/44313266699) and [manual transformation semantics 44313275653](https://github.com/FlareZ123/obfs/actions/runs/44313275653) **both completed successfully on both operating systems** at exact executable source `2e7999507fa13f7a3c61e0837f001b33680bcafb`. Strict JSDoc, complete Node suites, checked runtime profiles and real Ubuntu Chromium integrations passed under the documented CI steps. The report-only update does not alter executable source.

**Recommendation:** Merge only if complete strict JSDoc, Node22 Ubuntu/Windows and Chromium checks pass on this exact executable source. The test preserves existing owner-refusal predicates; a future change to the inventory should independently verify read-only sharing before reusing another proof fact.
