# Executable source-reader escapes from opt-in ESM observer islands

**Date:** 2026-11-17. **Status:** Reproduced red/green engineering evidence; intermediate correctness result. **Agent:** Agent 8.

## Scope and architecture

The experimental `experimentalSourceObserverIslands` option permits narrowly proven local object-property rewrites inside pure zero-argument primitive-returning ESM leaves, even when another declared file observes the source spelling of a different function. The legacy group-wide source-observer veto remains the default. The opt-in assumes selected source bytes cannot be reached by the rest of its supplied module graph. This report falsifies that assumption for three *dynamic code-loading* paths despite ordinary ESM source and import purity checks. It does not show a protected confidentiality boundary or independent anti-deobfuscation strength.

### Semantics of the red witnesses

The `Reflect` variant obtains a native Function constructor from an arrow function, constructs a dynamic `import('node:fs/promises')` factory, obtains `readFile`, and reads the selected module path using `process.argv[1]`. The destructuring variant reaches exactly the same capability through `{constructor:make}=()=>0` and computed `{'readFile':file}` destructuring, with no direct `Reflect` or `Object` identifier. Both read file text inside the *declared* ESM source group; they are counterexamples to the claimed selected-leaf isolation. The attacker has no need to modify generated bytecode.

The browser variant passes a source string to `setTimeout` that compiles when the timer fires. The string fetches `./independent.mjs` on the same host, reads text and sets a DOM value according to whether `privateB` remains in the module source. The importer's syntax contains no direct fetch identifier, filesystem import, or dynamic ESM import AST edge outside the timer string. The baseline browser document reports `true`, while selected-leaf output reports `false`. The test uses real Chromium and awaits DOM completion without treating virtual time as measured CPU time.

The HTML timer callback's string-evaluation semantics follow the [WHATWG HTML timers specification](https://html.spec.whatwg.org/multipage/timers-and-user-prompts.html). The two Node paths rely on documented JavaScript dynamic function compilation plus Node's built-in filesystem ESM module. All three are bounded native/generated observational-equivalence defects, not probes of the performance limit.

## Conservative fail-closed repairs

- Commit [`8f991753`](https://github.com/FlareZ123/obfs/commit/8f991753fa99160171a177d4845ddc8c0f0c91f9) refuses ambient `Reflect` and `Object` identifiers while proving source-observer islands.
- Commit [`cb84aec9`](https://github.com/FlareZ123/obfs/commit/cb84aec986f590e32f21a74845d0f2f8b2950a22) refuses unknown and prohibited object-destructuring keys, closing the second constructor path.
- Commit [`fcd44d1b`](https://github.com/FlareZ123/obfs/commit/fcd44d1b54e02a0fdd77c62e272e87e66f3b5316) refuses `setTimeout` and `setInterval` identifiers in this opt-in proof because browser string callback code is executable and the graph's AST does not contain its dynamic content.
- `test/source-observer-islands-reflection-gate.test.js` asserts refusal for both Node constructor paths and both browser timer families under COO and SNO. It retains a *positive control*: a safe selected ESM leaf still has at least one private property rewritten, and the separate watched file stays byte-identical. `test/source-observer-islands.test.js` separately verifies native/emitted ESM execution and source observation.

**Pinned green after repairs:** [focused workflow 44109248650](https://github.com/FlareZ123/obfs/actions/runs/44109248650), exact SHA `71d6df81384888fec92d7e2225cf42aac3383d64`, passed Ubuntu and Windows Node 22. The workflow ran **8 focused Node tests with zero failures per platform**, both direct file-read adversaries (each reported `status:rejected`), the Ubuntu real-browser timer adversary (`status:rejected`), `npm run typecheck`, and `npm run typecheck:external`. This is a focused gate, not full repository integration and not a general proof of all reflective capability safety. The green browser test rejects before launching Chromium by design, while the prior red control executed the browser and observed the difference.

## Remaining limitations and decision

Ambient reflection and string-capable timer functions are only a finite subset of JavaScript host-capability routes. Userland wrappers, shadowed bindings, new native APIs, nonstandard loaders, and tampered realms remain outside a syntactic closed-world proof. Further opt-in admission should require an explicitly documented capability/effect boundary before exposing a strong semantic-equivalence claim. Every future positive candidate should pair an actually transformed workload with an independently reconstructed attacker program and a 2.5× CPU budget measurement. Additional isolated fail-closed tests alone do not establish strong obfuscation.

Material belongs in `im-results/` under the repository evidence policy; no promotion to `results/README.md` is warranted.
