# Exact-source esbuild control for the expression-VM LLM benchmark (23 November 2026)

**Agent 44. Intermediate source-pinned control.** The conventional control is built and verified. A new paired blind LLM result was **not obtained**: the independent-worker service returned an unavailable/HTTP-404 error for both attempts. Do not interpret this report as an LLM security or attacker-cost comparison.

## Why the control is needed

The prior [LLM probe synthesis](llm-deobfuscation-probe-synthesis-2026-11-22.md) recorded a one-pass exact GPT-6 reconstruction of the experimental expression register-VM tape, but no ordinary-minification control under an identical task. A security comparison requires the same original protected function and equal-trust, independently generated baseline. The earlier single-obfuscated-artifact probe remains valid only as a qualitative reconstruction observation.

## Source-paired files and build

The original is [examples/expression-vm/before.cjs](../examples/expression-vm/before.cjs). The actual obfuscator-produced artifact is [examples/expression-vm/after.cjs](../examples/expression-vm/after.cjs). The new [test/llm-expression-vm-minifier-control.test.js](../test/llm-expression-vm-minifier-control.test.js) invokes the **declared esbuild 0.28.2** dependency on the original source with:

- minify=true;
- target=node22;
- format=cjs;
- legalComments=none.

This uses esbuild's documented [JavaScript transform and minification API](https://esbuild.github.io/api/) as a conventional equal-trust comparison. No manual substitution of the minified bytes is made in the generator.

The pinned artifact output is:

~~~js
"use strict";function r(t){return(t+7)*(t-5)^t+3&255}module.exports=r;
~~~

The compact operator spelling preserves the original numeric JavaScript semantics by the standard precedence of multiplication, addition, bitwise AND and bitwise XOR. This string is recorded as emitted esbuild output; it was not manually selected as the test control.

The byte counts do **not** measure attacker reconstruction difficulty. Ordinary minification and the expression VM also do not promise byte-identical Function#toString behavior; this specific experiment is restricted to the numeric function behavior.

## Exact CI result

Two-platform [focused run 45091020328](https://github.com/FlareZ123/obfs/actions/runs/45091020328), source SHA ff5e0de894b23dd98d39794c61a0af39ada06b47, **passed on Windows and Ubuntu**. Its named test loaded the original, the generated minified control and the checked-in expression-VM artifact into isolated Node VM contexts and compared **2,067 numeric inputs**, including signed integer boundaries, fractional and nonfinite values, and 2,048 deterministically generated Int32 inputs. Every comparison passed. The focused runner also passed project and strict-external JSDoc checks on both OSs.

The exact minified bytes and hashes were emitted in the source-pinned test logs under the marker SOURCE_MATCHED_LLM_MINIFIER_CONTROL. They can be regenerated by directly executing the named test with the pinned dependency tree.

## Blind-model attempt and limitations

Two independent, one-pass, source-only reconstruction questions were prepared with **the same prompt wording**: one containing only the esbuild output, one containing only the expression-VM output. Each requested equivalent CommonJS source for numeric inputs, forbidden external tools/source access, and self-reported model/tool provenance.

Both concurrent attempts failed **before an agent answer** because the Workers API returned an UNAVAILABLE error (SSE probe 404). Consequently this investigation has **zero new blind-model completions**, no measured reviewer time-to-solution, no same-prompt reconstruction accuracy comparison, and no justified claim that one artifact is easier or harder for GPT-6 or any other model. The previous unrelated one-pass VM reconstruction cannot be treated as a paired result.

A future independent comparison must isolate reviewers from the original source and from each other's challenge, freeze the exact artifact bytes and prompt, record model and time provenance, require one unassisted attempt each, and score source-only answers on held-out numeric behavior before correction. These conditions have not been met by this invocation.

## Release interpretation

The existing deterministic expression-VM static recoverer already reconstructs the distributed tape, and the hot-path VM can exceed the strict 2.5x compute limit as documented in [the backend's performance report](expression-vm-hot-path-call-density-2026-11-22.md). The new esbuild control closes a reproducibility gap for any future LLM comparison; it adds no evidence of a positive security advantage over minification. The multi-mode strong-protection decision remains **RELEASE-BLOCKED**.
