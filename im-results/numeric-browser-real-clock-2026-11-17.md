# Live-clock browser CPU measurements for affine and Wasm Int32 COO backends

**Date:** 2026-11-17 UTC. **Owner:** Agent 8. **Status:** fully pinned intermediate comparative evidence, with two green Ubuntu/Windows manual research workflows; no established secrecy or universal runtime claim. The tests measure real Chromium CPU computation under the actual emitted code with differential input and checksum equality.

## Problem and controls

Two pre-existing Chromium benchmarks, `test/polyvariant-affine-browser.js` and `test/wasm-i32-browser.js`, measured browser `performance.now()` under `--virtual-time-budget` while reading `--dump-dom`. Agent 8's earlier independent three-module cold ESM probe reproducibly reported zero CPU durations under that flag; the [virtual-time inventory](../workplace/virtual-time-browser-timing-audit-2026-11-17.md) identified these two tests as vulnerable *to the same measurement mechanism*, without asserting their historical numerical outcomes were all wrong.

The corrected tests perform the same actual source/compiler builds and retain the same semantic inputs, then launch Chrome using `puppeteer-core` under ordinary wall time, explicitly await completion, reject page errors and unhandled promise rejections, and require a consumed five-million-iteration CPU positive-control loop to move `performance.now()` by at least 0.1ms. Timed workloads consume the function-return checksum, check it against an independent native computation and are warmed before measurement. Twelve trials per variant balance variant execution positions across the schedule; raw samples are emitted alongside paired order-statistic median bounds. Browser process startup, HTTP module delivery and initialization are **outside the timed hot CPU interval** and are not eligible deductions from a COO full-runtime claim. The true cold-load cost is separately researched elsewhere.

All source generated by the actual compiler is loaded by a local HTTP ESM origin. These tests deliberately retain their signed Int32 and affine guarded-input contracts and do not assert general JavaScript observational equivalence or hostile instrumentation resistance.

## Affine paths 2, 4 and 8

**Source:** `test/polyvariant-affine-browser.js`, fixed `examples/polyvariant-affine/original.cjs`, same seeds `polyvariant-chrome-{2,4,8}` and exact compiler config as before. Native and all transformed functions matched **8,211** scalar/exception cases, including negative zero, NaN, infinities, signed-Int32 edges, Unicode-free strings, booleans, null, undefined, symbols, BigInt, object input, and the full loop from -4096 through 4095. Every timed workload executes **two million** arithmetic calls, checks a consumed checksum, uses eight warmup passes and twelve balanced measurement trials per variant.

**Exact frozen CI:** [run 44133519397](https://github.com/FlareZ123/obfs/actions/runs/44133519397) at `cc671469f89e9da3997f377fbdfc90b9c8cd84cb`, **complete success on Ubuntu and Windows** including strict external JSDoc. Ubuntu real `Chrome/157.0.8103.50`, positive CPU clock **41.2ms**; the `POLYVARIANT_AFFINE_REALCLOCK` log marker contains each raw trial and paired diagnostic.

| Path variants | Native median (ms) | COO median (ms) | Ratio of medians | Observed >2.5× pairs |
| ---: | ---: | ---: | ---: | ---: |
| 2 | 29.60 | 25.70 | **0.86824×** | 0/12 |
| 4 | 29.60 | 25.90 | **0.87500×** | 0/12 |
| 8 | 29.60 | 47.65 | **1.60980×** | 0/12 |

The one-sided order-statistic 98.0712890625%-coverage upper bound for the *median of within-trial paired ratios* is 0.87797×, 0.88136×, and 1.62116×, respectively, subject to independent identically distributed trial assumptions and order drift. Under this one fixed application and Chrome version, the 2- and 4-path generated code appeared faster on the measured hot loop; a different code shape, engine optimization or input may reverse that result. These samples offer no evidence that adding paths increases code secrecy; the public-source attacker experiments remain separate.

## Wasm Int32 one- and three-argument functions

**Source:** `test/wasm-i32-browser.js`; exact original signed-Int32 `scramble(x)` and `fuse(a,b,c)` examples and original compiler seeds are unchanged. The script validates **4,097** single-argument and **1,025** multi-argument native/Wasm outputs (including host page delivery), warms each generated and native function five times, then profiles separate **two-million-call** one- and three-argument workloads. A consumed checksum must match its native reference in every trial. Each workload executes twelve rank-balanced native/Wasm pairs.

**Exact frozen CI:** [run 44133938535](https://github.com/FlareZ123/obfs/actions/runs/44133938535) at `24d29b73497b6161afdb3c1977edd457cb288eac`, **complete success on Ubuntu and Windows**, including the strict Wasm research JSDoc project. Ubuntu real `Chrome/157.0.8103.78`, positive CPU clock **32.0ms**; `WASM_I32_REALCLOCK` in job logs preserves raw trial samples and paired diagnostics.

| Native/Wasm work | Native median (ms) | Wasm median (ms) | Ratio of medians | Observed >2.5× pairs |
| --- | ---: | ---: | ---: | ---: |
| 1-argument Int32 `scramble` | 11.50 | 14.50 | **1.26087×** | 0/12 |
| 3-argument Int32 `fuse` | 22.00 | 24.70 | **1.12273×** | 0/12 |

The corresponding one-sided upper paired median bounds are **1.26087×** and **1.14155×** (same 98.0712890625%-coverage order-statistic diagnostic under assumptions). Warm Wasm overhead on these two tiny arithmetic functions is measured well below 2.5× in this sample; other data families, startup/Wasm module compile, different engines or dynamic-analysis attacks must be evaluated independently.

## Decision limits and reproducibility

The real browser scripts and workflows are on branch `agent8/affine-realclock-balanced-20261117` from main SHA `84c0123182a7d00404009cfc1345a8f54959d6ae`. Corrected files: `test/polyvariant-affine-browser.js`, `test/wasm-i32-browser.js`, `.github/workflows/manual-polyvariant-affine.yml`, `.github/workflows/manual-wasm-i32.yml`, and one strict external-JSDoc include `jsconfig.external.json`. The existing, substantial manual workflows were retained; their target real-Chrome step was moved directly after dependency installation so errors in unrelated later experiments cannot suppress its outcome. No new always-on CI or supplementary workflow was added.

To reproduce, manually dispatch either `manual-polyvariant-affine.yml` or `manual-wasm-i32.yml` against the pinned SHA, install Node22 declared packages and use Ubuntu `/usr/bin/google-chrome`. Full JSON raw measurements and statistics appear in the corresponding `POLYVARIANT_AFFINE_REALCLOCK` / `WASM_I32_REALCLOCK` job-log lines. Independent source-only/reconstructed adversaries remain mandatory before any security conclusion. These CPU-only samples do **not** constitute a whole-session COO 2.5× guarantee because browser launch, cold module fetch/compile and repeated application usage may change the ratios. The original static recovery evidence continues to limit claims of secrecy and tamper resistance.
