## Rebase method and reason

New direct compiler proof [PR #410](https://github.com/FlareZ123/obfs/pull/410) makes owner-valued immutable **record** fields a `Set<string>` rather than a single static key; stacked [PR #411](https://github.com/FlareZ123/obfs/pull/411) makes owner-valued immutable **tuple** indices a `Set<number>` rather than a single number. This is a concrete increase in conservative object-property rename coverage across repeated aliases and closed ESM imports. But draft PR #384 also modifies `src/properties.js` substantially and introduces thousands of lines of source-observer hardening in `src/ast.js`; compatibility must not be assumed from isolated #410/#411 green CI.

I fetched `src/properties.js` at current main, frozen PR #384 head and #411 child, and compared byte-for-byte the **two exact proof regions** from `const holderIdentifierUses=identifierUses` up to `const unusableFunctions`, and `function resolvingDependency` up to `function resolves`. Both PR #384 regions were **byte-identical to main**, despite unrelated additions elsewhere in PR #384. I therefore transplanted only #411's admitted Set-of-owner-slots proof regions into the PR #384 source (retaining all other PR #384 observer and cross-file code), plus clarified one tuple proof comment. This is a traceable minimal *source-level integration*, not a blind replacement of PR #384's modified file.

The standalone test files from #410 and #411 were copied unchanged into branch `agent6/pr384-multicarrier-integration-20261128`: record proof + 256-seed fuzz + real Chrome, tuple proof + 128-seed fuzz + real Chrome, and optional experimental `Symbol()` key lowering. The two historical tests drop only their now-proven duplicate-owner negatives. A **branch-only** copy of the registered `manual-imported-identity-alias.yml` targeted workflow from #411 is used to run both Node platforms, strict JSDoc, both native/minified/obfuscated real Chromium ESM proofs and the optional Symbol backend; four unrelated known-failing frozen-main browser positive-yield steps are temporarily skipped. These skipped gates remain red elsewhere and are not included in any GO claim.
