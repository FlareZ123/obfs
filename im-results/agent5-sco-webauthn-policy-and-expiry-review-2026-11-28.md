## Bounded expiry-housekeeping performance direction

The default memory state has `purge(now)` which independently scans **all** outstanding challenge and session map entries on every challenge insert and every session mint. With N live rows and N insert/mint operations this performs quadratic scan work, not an inherent cost of WebAuthn cryptographic assertion. An isolated optional donor branch `agent5/webauthn-memory-expiry-index-20261128` at source `8ba1bcec65d25d11174b458c7d424ab93d9b0c98` preserves Map insertion order and tracks whether each map's expiries remain monotonically ordered. On ordered input it purges expired prefixes only; on out-of-order or nonfinite expiries it falls back to the original complete scan until empty. Deletion preserves any nondecreasing subsequence, so a prefix scan stops safely at the first unexpired row. A 6,000-transition seeded differential against the original linear-scan model plus a five-pair equal-work process-CPU receipt are in `test/sco-webauthn-memory-expiry-index.test.js`; focused CI [46145708467](https://github.com/FlareZ123/obfs/actions/runs/46145708467) was queued as of this checkpoint.

An **independent local simplified** Node 22.16 model (not exact production source, and not a release benchmark) ran 50,000 deterministic transitions without difference and measured median linear/ordered housekeeping CPU ratios about 30.4x at 512 live rows, 59.0x at 1,536, and 162.7x at 4,096, each five alternating-order CPU samples. Do not transfer those local ratios to the real SCO HTTP+ECDSA full-session path or treat an optimized-vs-unoptimized speedup as a security advantage versus equally trusted conventional authenticated code. The actual GitHub-runner exact-source result supersedes this model if it differs. Out-of-order expiry disables the fast path and retains old worst-case work.

### Expiry fast-path correctness condition and first CPU receipt

For each map, let `e1,...,en` be expiry times in insertion order. The implementation's `ordered` flag remains true only if **all** insertions since the map last emptied were finite and nondecreasing in expiration; any out-of-order or nonfinite value permanently forces original linear-scan fallback until empty. Map deletion preserves nondecreasing order. When ordered, for finite `now`, a scan may delete the maximal prefix with `ei<=now`; if it encounters `ej>now`, every subsequent `ek>=ej>now`, so no later rows are expired. Thus prefix-only and original full-map scans yield the **same surviving keys and values**, including when rows are consumed, revoked, and later added. The fallback is literally the original scan and cannot produce a new expiry outcome. This is a simple algorithmic invariant, not a claim of novel mathematical obfuscation research.
