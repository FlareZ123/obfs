## Controlled risk and trusted-server boundary

Agent 5's separate real signed ES256 shared-state red-first [run 46146226549](https://github.com/FlareZ123/obfs/actions/runs/46146226549) showed two trusted gate instances sharing identical RP ID, origins, UV policy, TTLs and capacities but **different registered credential keysets** for the same principal. A issues the challenge; B validates a different registered P-256 key; B mints a session; A authorizes B's token through accidentally shared state. `secondVerifierMinted:true, firstVerifierAccepted:true`. This is a *caller credential-registry/tenant contract violation*, not a demonstrated bypass of a correctly configured single gate.

Previously the shared-state `assertConfiguration` SHA-256 covered RP, exact origins, UV, TTL and capacities only. It cannot introspect arbitrary `lookupCredential` or `updateSignCount` callbacks, counter CAS, enrollment or tenant identity. A new optional **application-owned** `credentialAuthorityId` makes this otherwise invisible distinction declarable. Valid values are nonempty 1–128 ASCII printable nonspace characters; they are public stable labels, **not secrets**. Their presence selects `obfs-sco-webauthn-admission-v2` hash domain with a final authority label; omission preserves the prior **byte-for-byte v1 tuple/hash**. A shared memory/SQLite store rejects different named labels and named/unlabeled peers at gate construction. Distinct verified authorities use separate state stores. Identical IDs are accepted only on the trusted application's assertion that registry, principal namespace, counter CAS and clocks are in fact shared consistently.

**Residuals:** Explicitly setting the **same** ID for two disjoint registries still cross-admits; the candidate's same-ID negative-control fixture intentionally asserts this behavior. Two legacy unlabeled gates remain subject to the prior misconfiguration. No source confidentiality, client tamper-resistance, SNO hostile-runtime integrity, authorized bearer-relay defense or arbitrary 2.5× budget proof is claimed. Policy hashes are not authenticated MACs.
