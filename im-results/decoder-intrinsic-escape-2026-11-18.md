# Decoder intrinsic-escape evidence: function parameters, lexical shadows, and literal containers

**18 November 2026.** Source-visible, multi-file COO/SNO **compiler correctness** research. No confidentiality or full-control integrity advance is claimed. Every numerical observation below is conditional on its exact source and two-platform CI gate.

## The actual target and adversary

The opt-in `strings:true` backend emits an eager XOR decoder using `raw.charCodeAt`, `String.fromCharCode`, and for long strings, an array of decoded code units with spread. A supplied CommonJS mutator is required before a separate target CommonJS module containing an ordinary 2,049-unit literal. Each test invokes `obfuscateFiles` on the complete supplied three-file group, writes native and generated files separately, executes both with new Node child processes, and compares exit status and **full stdout** (or SHA-256 of full stdout) before inspecting the emitted target's `metrics.literals`. The protected target's original literal output does not depend on mutating these methods.

Mode-specific tests independently check COO and SNO with identifiers/properties disabled to isolate the decoder. For unsafe graph cases the minimum correct result is `metrics.literals === 0` with exact original output. Separate eligible examples require `metrics.literals === 1` and native/generated parity, preventing a vacuous all-refusal success.

## Interprocedural escape into function parameters

The supplied graph can call a local function with `String.prototype`, `String`, or `Object.getPrototypeOf(owner())`. A parameter-local write such as `p.charCodeAt = () => 0` or `C.fromCharCode = () => '?'` changes the ambient decoder after the original target would still return its unchanged string literal. The earlier syntactic may-alias analysis did not model argument-to-formal flow, so all six SNO/COO cases emitted a decoder and changed output.

- **Red:** [Ubuntu/Windows 44276752179](https://github.com/FlareZ123/obfs/actions/runs/44276752179), test-only exact `485f4882ef9e0d24429a97a1220ffcb973a28d25`: 6/6 actual emitted/native mismatches per operating system, 2/2 Number-prototype positive controls passed.
- **Scoped green:** [Ubuntu/Windows 44277937072](https://github.com/FlareZ123/obfs/actions/runs/44277937072), exact `ad00b89ee59417602c23f0e1dc75fe02e6c3d202`: fixed-arity decoder test lane, source-visible prototype parity, JSDoc and Chromium neighbor all green. The guard refuses when a decoder-sensitive intrinsic is passed to an opaque CallExpression/NewExpression, while existing modeled Object/Reflect API calls retain their key-specific proof.
- **Precision correction:** Initial guard caused eight preexisting unrelated `Object.defineProperty`/`Reflect.set` positive writes across modes to refuse encoding; refining the guard to accept recognized Object/Reflect methods and delegate their key checks restored them. Another intermediate compile failed strict TS7006 for an untyped `.some` callback, repaired with an explicit JSDoc `AstNode` annotation.
- **Integration:** [PR #100](https://github.com/FlareZ123/obfs/pull/100) merged the source, differential tests, and targeted workflow through squash `c25965534fe51447b43aa0639dfeed55f0104b77`.

## Lexically shadowed Object, Reflect and Array

A syntactic expression spelled `Object.getPrototypeOf(7)` is not guaranteed to resolve the intrinsic if the supplied source declares a local `Object`. In three separate graphs, locally shadowed `Object` and `Reflect` methods return `String.prototype` despite a numeric argument, or a local `Array.prototype` field holds `String.prototype`. Mutating `P.charCodeAt` then corrupts the emitted decoder. The original target remains unaffected.

- **Red:** [Ubuntu/Windows 44278035305](https://github.com/FlareZ123/obfs/actions/runs/44278035305), exact `c3454c17848fe43504aa19db2ad783bb3bf46ad0`: 6/6 real generated-output mismatches per OS, and 6/6 transformed-literal Number-prototype controls passed.
- **Scoped green:** [Ubuntu/Windows 44278398804](https://github.com/FlareZ123/obfs/actions/runs/44278398804), exact `d0bd5242831a03407c974fe36e8dfae9ef406886`, and the subsequently re-integrated [Ubuntu/Windows 44278731882](https://github.com/FlareZ123/obfs/actions/runs/44278731882), exact `2bf6443a0ef0ef1f0117b21767705f2c3f8825a1`. Both targeted gates succeeded. `collectBindings(ast)` now invalidates prototype provenance shortcuts for locally bound `Object`/`Reflect`, and `isPossiblePrototype` treats local Array/Object/Reflect `.prototype` reads as uncertain when they may refer to decoder-sensitive objects. Unrelated named fields retain positive rewrite yield.
- **Integration:** [PR #103](https://github.com/FlareZ123/obfs/pull/103) squash merged at `84e4b8d3c2273b7e9a91275148a91eda7af81861`.

## Nested literal, argument spread and tagged-template follow-up

An independently maintained [test matrix](../test/decoder-wrapped-escape.test.js) passes `String.prototype` to an opaque function through `...[String.prototype]`, `{inner:{ref:String.prototype}}`, or `[String.prototype]`, then patches `charCodeAt` within a function parameter. These paths are not direct sensitive argument expressions. An additional tagged-template test checks the existing compiler's conservative refusal behavior, which occurs before any new fix; it must not be counted as a new red counterexample.

- **Initial red:** [Ubuntu/Windows 44279216530](https://github.com/FlareZ123/obfs/actions/runs/44279216530), exact `c7e01b900d9bacd6195a876570280cd97a34e5bc`: six (three shapes × COO/SNO) actual output mismatches. Counting those as new successes or treating their zero-yield result as a regression of the new patch would be misleading.
- **Scoped green and integration:** recursive array/object/spread argument containment checks, with modeled Object/Reflect methods delegated to existing method-specific proofs. [Ubuntu/Windows 44279570568](https://github.com/FlareZ123/obfs/actions/runs/44279570568), exact `c37542c2e0f4ecbabcb0df62deb02361fde0a674`, and current-main-integrated [Ubuntu/Windows 44280209929](https://github.com/FlareZ123/obfs/actions/runs/44280209929), exact `dafdad12d7832dcd9e2c151b03f691a852d02ce9`, passed all targeted tests, strict JSDoc and browser-neighbor checks. ## Returned aliases of local synchronous functions

A no-argument call to `function factory(){return String.prototype}` can return a mutable decoder dependency. Even if the caller neither passes a String prototype as a literal argument nor writes the prototype directly by name, a later `factory().charCodeAt=...` is a real mutation. Arrow functions, functions returning the `String` constructor, and object-returning functions with a named sensitive data field exhibit the same risk. Existing syntactic alias tracking already refused some same-spelling local-variable examples and must not be credited as new failures.

- **Red:** [Ubuntu/Windows 44280902996](https://github.com/FlareZ123/obfs/actions/runs/44280902996), exact `5490f7afd8b5bf539adee0f66bad10700fdd9dc6`: 8/10 unsafe forms (four shapes × COO/SNO) were genuine generated/native mismatches; 2/10 already safely refused. The 10 unrelated Number-prototype return controls preserved encoding and runtime parity.
- **Scoped green:** [Ubuntu/Windows 44281454370](https://github.com/FlareZ123/obfs/actions/runs/44281454370), exact `e1990b60844d0dc4c2a166382bbf3f88d7c129fa`, and additional [Ubuntu/Windows 44281749160](https://github.com/FlareZ123/obfs/actions/runs/44281749160), exact `ba3fcf91e65ff647eaf4573df0994c67122fe657`, passed the targeted lane with eight **read-only String return** positive controls retained as encoded work. The prototype/constructor may-return summary uses a finite monotone set of local function-name aliases plus named returned data fields. Function-body syntax analysis is bounded, with no claim of complete dynamic call graph proof.
- **Nested return follow-up:** return statements inside `if`, `try/finally`, `switch` and arrow-function blocks can evade direct top-level ReturnStatement summaries. [Red 44282568749](https://github.com/FlareZ123/obfs/actions/runs/44282568749), exact `5dbad928f50df4b57981ce54f30013ddad269dd2`, recorded eight true generated/native mismatches in those forms. Four intended positives containing a separate fallback `return String` were already conservatively refused before the branch fix; the corrected positive controls use strictly Number-only returned data. The current integrated source is now covered by focused two-platform run [44395252349](https://github.com/FlareZ123/obfs/actions/runs/44395252349) at exact branch source `45722a856d848d713081f3b2c871074692057582`: the dedicated nested-return step, strict JSDoc, and neighboring decoder gates all passed. The earlier red remains the proof that the recursive return walk is required.

## Local finite-container field aliases

A local object or array can hold a decoder-sensitive reference and expose it later through a member read. Examples include `const box={ref:String.prototype}; poison(box.ref)`, `const box=[String.prototype]; poison(box[0])`, and the same object copied through a second local alias. The earlier call-site containment scanner only inspected literal containers when the literal itself appeared as an argument, so these stored references lost provenance before the opaque call.

- **Red:** [Ubuntu/Windows 44394920851](https://github.com/FlareZ123/obfs/actions/runs/44394920851), exact `9c0da748bd1e313aafa326e5b93fdc6901550369`. Each operating system recorded **8/8 unsafe generated/native mismatches** across object-field, array-slot, String-constructor, and simple object-alias forms. The separate **8/8 Number-only controls passed and retained encoded target literals**, so the witness does not depend on a blanket refusal.
- **Scoped green:** [Ubuntu/Windows 44395252349](https://github.com/FlareZ123/obfs/actions/runs/44395252349), exact branch source `45722a856d848d713081f3b2c871074692057582`, passed the new 16-case gate, strict production and research JSDoc, and all neighboring decoder regressions. The squash-merged mainline source `b5d29853261201e875d2cf6d4c21f55552ea8179` independently passed the same two-platform workflow in [44395703412](https://github.com/FlareZ123/obfs/actions/runs/44395703412). The fixed-point analysis now records statically named sensitive fields in finite local object and array literals, propagates those summaries through simple identifier aliases, and feeds later field reads into the existing possible-prototype/constructor checks.
- **Boundary:** nested container paths, destructuring from such containers, spreads, imported container values, and dynamically computed storage remain separate proof obligations. This is a finite source-visible provenance repair, not a general heap analysis.

## CommonJS export boundary

A supplied CommonJS module can export a decoder-sensitive reference while a second supplied module imports and mutates it. Per-file mutation scans lose the reference between the exporting assignment and the importing `require`, so the group-level OR does not help unless the export edge itself is recognized.

- **Clean red:** [Ubuntu/Windows 44397141328](https://github.com/FlareZ123/obfs/actions/runs/44397141328), exact `dc6b76b58902a668ba295fa2e2d4cf57ba21c0e3`. Both jobs failed the dedicated gate. Ubuntu recorded **8/8 unsafe generated/native mismatches** across `module.exports={ref:String.prototype}`, `exports.ref=String.prototype`, a stored `String` constructor, and direct `module.exports=String.prototype`, while all **8/8 matched Number controls passed and retained one encoded target literal**. An earlier exploratory run included an array-export control already refused by preexisting logic; that confounded path was removed before the clean red.
- **Scoped green:** [Ubuntu/Windows 44397543968](https://github.com/FlareZ123/obfs/actions/runs/44397543968), exact branch source `b0349d7b085525bd8f0bec5732144e97756267fd`, passed both OS jobs, strict JSDoc, the new 16-case CommonJS gate, and neighboring browser/decoder checks. The squash-merged mainline source `6458c2b61d72f4529dd145f4b017054ef9a7ac20` independently passed the same two-platform workflow in [44398012846](https://github.com/FlareZ123/obfs/actions/runs/44398012846). The group scan now resolves static relative `require` edges to supplied CommonJS files and treats decoder-sensitive assignments to the actually imported module's `module.exports` or `exports.*` surface as an external escape. Unrequired CommonJS export surfaces are not blanket-refused by this repair.
- **Boundary:** dynamic/nonrelative `require`, mutator calls such as `Object.assign(module.exports,...)`, ESM exports/imports, and reexports require separate evidence.

## Sensitive writes through pre-existing local aliases

A simple identifier alias copied existing path summaries only in the assignment direction. If the sensitive field was added later through the alias, the original name retained no summary and a later read through that original name could still reach a poisoned decoder intrinsic.

- **Red:** [Ubuntu/Windows 44401847180](https://github.com/FlareZ123/obfs/actions/runs/44401847180), exact `182169611a8ed6df0317a530e0c26c820f13f30c`. Both jobs failed the dedicated gate; Ubuntu recorded **12/12 unsafe generated/native mismatches** and **12/12 matched Number controls passed with one encoded target literal**, including declaration aliases, assignment aliases, array/nested paths, alias chains, and a stored `String` constructor.
- **Scoped green:** [Ubuntu/Windows 44402190664](https://github.com/FlareZ123/obfs/actions/runs/44402190664), exact `18d728b90caf5337967e3d5fdb6ea1d5320fde97`, completed successfully on both OSes, including strict JSDoc and all neighboring decoder/browser checks. Simple identifier aliases now exchange proven field/path summaries bidirectionally during the monotonic fixed point, so later writes through either alias converge across chains. Number-only and mixed safe-sibling controls retain encoding.
- **Boundary:** aliasing through object fields, arrays of containers, function parameters/returns that carry whole containers, and dynamic heap mutation remain separate proof obligations.

## Structural conclusion and remaining proof gap

Across these families the precise compatibility issue is loss of *value provenance*: decoder-sensitive intrinsic references flow through function parameters, lexically shadowed names, literal containers, expressions and function-return boundaries. The conservative admission rule is to disable eager decoding only when that may-alias fact can reach an unproved write or opaque call, while retaining encoding on unrelated named properties and read-only consumers. The paired tests establish narrower finite patterns, not a general interprocedural soundness theorem. Future researchers should challenge computed property keys, `Reflect.apply`, `.call/.apply`, returns hidden in callbacks, mutable aliases from imported modules, and source observers, with matched native/generated execution.

## Limits

These are bounded static source-admission repairs for the supplied multi-file graph. They do not establish complete cross-file, interprocedural effects or lexical scope-sensitive alias proof. Arbitrary host preloads, dynamic-code execution, external modules and hostile runtime patching can still defeat assumptions. Under the stated COO/SNO full-control adversary, independently source-only recovery of published XOR string tables remains feasible. Source-level guards and passing integration therefore do not establish strong obfuscation, authorization, tamper resistance or a universal 2.5x compute bound. This report belongs in `im-results/`; keep the release decision in `results/README.md` unchanged until matched adversarial and runtime evidence materially changes it.
