# SCO literal spelling: a 32-bit effective per-response selector

**Status:** intermediate result, 16 November 2026. Reproducer: [source-only mask extractor and 24-request HTTP challenge](../sims/sco-spelling-mask-attack.js), [automatic regression](../test/sco-spelling-mask-attack.test.js). This concerns SCO's *literal-spelling pass alone*, independently of the earlier hashed-identifier attack and of server-private RPC methods.

## Exact scoped claim

In [src/sco.js](../src/sco.js), `varyLiteralSpellings` computes `entropy = SHA256(nonce)` from a random 24-byte request seed. Every candidate printable ASCII code unit chooses between a literal character and a `\\uXXXX` escape solely according to:

```js
entropy[(characterIndex + originalLiteralStart) % 32] & 1
```

Therefore **at most 32 independent bits** of the nominal 192-bit nonce can affect this spelling pass for a fixed pre-variation source. The rest of the nonce may still influence other, separately executed obfuscator transformations (including hashed names). The 32-bit bound makes no claim about the entropy of the **entire HTTP response**, seed recovery, or server-side secrets. It also does not imply 2^32 equally probable spellings.

For any eligible unescaped 32-code-unit printable ASCII literal, the byte spelling reveals one occurrence of each index of this rotating 32-bit selector. Each direct ASCII character supplies a 1 and each `\\uXXXX` supplies a 0. After recovering the selector and reconstructing pre-variation literal start offsets, the attacker can reproduce spelling choices for every other eligible literal in the same response without knowing the nonce.

## Reproduction and isolation

The extended fixture supplies two originally canonical double-quoted 32-unit ASCII literal assignments and a third mixed UTF-16 literal (quotes, backslash, NUL, a non-BMP character, and an unpaired surrogate) in a single public script and serves it through the actual `createScoHandler` using fresh request entropy. The attacker receives only each served JavaScript response and uses AST values and byte spellings to infer the mask. It normalizes eligible literals to canonical double quotes, obtains the pre-variation positions, and predicts all three literal spellings. The test demands byte-for-byte equality against each complete observed variant across 24 separate HTTP GET responses, verifies native-versus-emitted string equality including every UTF-16 unit, and ensures the response hashes are not all identical.

Only the served bytes are passed to a separate source-only attacker subprocess. That process uses its own Acorn parser and has no dependency on the obfuscator package. It neither calls the compiler nor requests its seed; the surrounding test harness uses the ordinary SCO handler to prepare a genuine challenge. This is a controlled known-source-syntax observation: when the pre-variation literals contain single-quote forms or other noncanonical spelling, raw positions reconstructed by the current attacker may be wrong. The 32-bit theoretical bound holds regardless of that limitation.

A separate local harness replaying the same spelling rule with Node's bundled Acorn parsed and predicted **128/128** synthetic variants on 16 November 2026. The first real Node 22 Linux/Windows gate [43913673735](https://github.com/FlareZ123/obfs/actions/runs/43913673735) failed the attack's distinct-response assertion: the initially offered fixture concatenated two immutable `const` strings, which the existing source-observation guard refused. That refusal exposed a precision limit in the compiler, rather than a protected response. The new [positive/negative source-observer tests](../test/primitive-addition-source-observer.test.js) support a narrow repair in `src/ast.js`: prove the concatenation of immutable primitives cannot coerce a function, while preserving refusal for opaque or mutable operands.

**The original two-literal variant passed full validation** at immutable commit `5c70af17697ba77c6f7ce33b77bdaae430a865b7`: [run 43916154523](https://github.com/FlareZ123/obfs/actions/runs/43916154523) on Node 22 Ubuntu (**1,756 passed, one skipped, zero failures**) and Windows, including the 24-request HTTP mask-extractor regression and paired primitive-coercion regressions, both strict JSDoc suites, sampled benchmark, and Ubuntu Chromium integrations. The exact run also contains an independently contributed Node inspector source-observation safeguard. The subsequent three-literal mixed-UTF-16 and native/emitted VM-parity extension also **passed** the full Node 22 Linux/Windows, strict JSDoc, benchmark and Chromium gate at exact source `ec6b6c9e49777327c8e7367ea9aedaf630a79e44`, [CI 43917568528](https://github.com/FlareZ123/obfs/actions/runs/43917568528). These are bounded fixture and integration results, not a general proof of JavaScript behavior or whole-application attacker cost.

## Browser target and host-owned API parity

The dedicated [real Chromium differential](../test/sco-spelling-mask-browser.js) serves the same three literal families through two local HTTP paths: an untouched native script and a fresh SCO response. It preserves the host-owned `document.getElementById` method and compares every UTF-16 code unit as a JSON array in the DOM, avoiding browser text-normalization of the unpaired surrogate. The script also checks independent SCO GETs yield distinct source. The [manual real-browser workflow](../.github/workflows/manual-browser.yml) runs the script on Linux with Google Chrome.

At immutable source `39f47f2b4a7c074fd11fe432a386241b65692233`, [Chromium validation 43919003239](https://github.com/FlareZ123/obfs/actions/runs/43919003239) **passed** with 73 native/emitted code units equal, an unpaired surrogate retained in the input, and two distinct returned source variants. A further positively transformed browser fixture with function-local `const` strings, a private literal-owned field, and an unchanged host `document.getElementById` call passed at source `190cff7d02982545c498b8704966251dc5355e9f`, [browser CI 43920125069](https://github.com/FlareZ123/obfs/actions/runs/43920125069). Its logged metrics were **one private field transformed and six bindings renamed**, **73/73 UTF-16 units identical** between native and emitted browser modules, and distinct SCO source variants. An Acorn-only subprocess that received each independently served, actually renamed module recovered the spelling selector and reproduced the complete source spelling digest. This **does not recover the generated property names to their original identifiers**. The source-only extractor still demonstrates the narrow formatting bound.

A final source-only normalization check was added to the browser harness. It uses the public AST-based [`normalizeScoVariant`](../sims/sco-variant-normalize.js) attack to normalize two different SCO response sources, including randomized private property and binding names as well as literal escape choices. The independently served sources became **byte-identical canonical JavaScript** and that reconstructed program executed under a separate Node VM with the host `document` callback substituted, matching every observed numeric code unit. At exact source `ad5bf9b19df35630d5f87984ea74fe2df3d31cda`, the [manual browser CI 43921504653](https://github.com/FlareZ123/obfs/actions/runs/43921504653) passed with **74/74** native/emitted values, including private field `7`, one private property transformed, six bindings transformed, exact independent mask recovery, canonicalized-code equality across two fresh responses, and behaviorally equivalent execution of the canonical reconstruction. Both browser pages enforced `Content-Security-Policy: default-src 'none'; script-src 'self'`, excluding inline script and unsafe eval. This is a bounded example of public client program reconstruction; it does **not** recover erased original private names, server-private implementations, or all arbitrary SCO modules.

The stronger fixture first failed at [browser CI 43919701173](https://github.com/FlareZ123/obfs/actions/runs/43919701173) when the supposedly private field was initialized from a function parameter, which the compiler conservatively refused. The final fixture uses a literal-valued private field to meet the existing ownership proof. This gap was sent to Agent 6 as a possible bounded positive-proof research question. These are concrete browser parity and transformation-yield measurements for the tested case, rather than a general browser equivalence proof or 2.5× session measurement.

## Security interpretation

The attack demonstrates a compact, efficiently observable equivalence class for this request-time formatting mechanism. It neither reconstructs an arbitrary program nor undermines cryptographic server-side source separation. The existing stronger [AST literal canonicalizer](../sims/sco-variant-normalize.js) already removes tested spelling variations without even recovering the mask. Therefore increasing the private nonce alone cannot make public literal spelling into an effective confidentiality or host-integrity mechanism. Future candidate defenses should be measured against independent end-to-end reconstruction and functional cloning, with the 2.5× runtime bound reported separately.

## Two-file public-graph extension (23 November 2026)

A separate focused test extends the per-request reconstruction result from one script to a small two-file classic-script graph:

- `test/sco-multifile-per-request-reconstruction.test.js` starts the production `createScoHandler` and a matched ordinary HTTP server over `index.js` and `lib/helper.js`.
- The attacker captures two fresh response rounds for both public files (two GETs are sufficient to obtain one complete graph). Both SCO file bodies differ across rounds; the ordinary HTTP control serves stable original bodies.
- The captured bodies alone are passed to `sims/sco-multifile-response-normalizer.js` in a separate child process. It uses the public AST normalizer, receives no original source, server state, or per-request nonce, and emits canonical scripts that are byte-identical across both rounds.
- The reconstructed two-script graph is executed in a fresh Node VM and produces the same `finalValue` (`65`) as the native graph and the ordinary-service control.

Current-main focused validation [45131206729](https://github.com/FlareZ123/obfs/actions/runs/45131206729), exact SHA `51e26a09ad5a0e42516b293c352cb9c0dc96c3bb`, **passed Ubuntu and Windows**, including project, external, and paired-budget strict JSDoc. The full `node22` job was skipped.

**Scope:** this is one small two-file classic-script graph with block-scoped local bindings and a shared `globalThis` value, not arbitrary JavaScript or a general multi-module reconstruction theorem. It does not exercise ESM imports/re-exports, dynamic imports, cross-file object-property aliasing, a real browser loader, or private server files. An earlier ESM-import/re-export fixture did not yield differing per-request bodies and was not used as evidence; the cause was not instrumented. The matched ordinary service is a simple same-route HTTP source server. This result adds a bounded multi-file example to the existing single-file response-reconstruction evidence, not a universal claim.
