## Concrete compiler improvement

The source-observation gate in [`src/ast.js`](../src/ast.js) previously declined *every* nonliteral argument to known native source-coercing calls (`String`, `RegExp`, `Symbol`, `Error`, `BigInt` and related APIs), even when a unique immutable const binding held a proven primitive. It also declined all reads of a syntactic `.toString` property, including known numeric primitives. Since `obfuscateFiles` is conservative and disables unrelated property/identifier obfuscation upon source-observer detection, these false positives reduced the actual transformed private-code fraction.

The updated guard uses the existing bounded `isDefinitelyPrimitive` proof, recognizing unique immutable const aliases and primitive expressions in supported syntax. It admits a nonliteral coercer argument only when it is proven primitive, and allows `.toString` / `.toSource` on similarly proven primitive receivers. Unknown values, mutable bindings, function-valued inputs, and other source-observing contexts continue to refuse. The proof has explicit conservative syntax restrictions and does not claim full program analysis.

[`test/primitive-coercer-source-precision.test.js`](../test/primitive-coercer-source-precision.test.js) covers 11 named coercer-positive cases and 4 negative cases, plus a direct AST observer boundary. [`test/primitive-method-source-precision.test.js`](../test/primitive-method-source-precision.test.js) covers 9 positive primitive receivers, 4 negative opaque/function receivers and direct AST checks. These tests execute actual transformed CommonJS source using Node `vm`, compare native outputs and require at least one renamed private own field for positives. [`test/primitive-coercer-sample.test.js`](../test/primitive-coercer-sample.test.js) confirms exact generated bytes, two private property renames, preserved exported `calculate` and heterogeneous runtime semantics, including errors on Symbol and BigInt values.

## Compatibility and performance evidence

The focused [run 43767778584](https://github.com/FlareZ123/obfs/actions/runs/43767778584) completed green on both platforms at the immutable SHA above. [`sims/primitive-coercer-profile.js`](../sims/primitive-coercer-profile.js) runs six warmups, 12 alternating warm comparisons at 300,000 calls per trial, using the exact shipped before/after modules and checking identical integer checksums. Median times:

| Platform | Native median (ms) | Compiled median (ms) | Ratio |
| --- | ---: | ---: | ---: |
| Ubuntu Node 22 | 601.734721 | 605.077072 | 1.00555× |
| Windows Node 22 | 959.048450 | 964.251900 | 1.00543× |

The paired workload repeatedly allocates a RangeError and formats strings per call. These measurements are **hot-kernel samples**, not a whole-application timing proof, browser benchmark or universal 2.5× bound.

During development, [run 43767532333](https://github.com/FlareZ123/obfs/actions/runs/43767532333) and [run 43767670447](https://github.com/FlareZ123/obfs/actions/runs/43767670447) failed one Windows snapshot test. Default checkout CRLF line endings altered source offsets and hash-derived names while Linux remained green. Explicit `text eol=lf` for the sample fixed it, and the succeeding pinned run verifies the resolution. The failing runs remain part of reproducibility evidence.

## Attacker and deployment limits

This change is a precision/coverage improvement for the conservative AST compiler. Public hashed field labels remain statically visible and reconstructable by the repository's existing normalizers. No new private server boundary, tamper resistance, integrity bypass prevention, host locking, or public-code confidentiality has been established. Runtime interception and whole-app cost remain distinct open questions.

Candidate future work: extend immutable, uniquely bound constant-computed own field access (such as `owner[key]` where `const key='field'`) without changing unrelated external API keys, and maintain explicit fail-closed behavior for shadowing, dynamic scope and cross-file escape.
