# Diversified public-step SCO synchronizing-word attack (15 November 2026)

**Status:** intermediate, locally reproduced Node.js 22 experiment. This is an attacker improvement, not an obfuscation-strength result. The cross-platform validation gate is [manual SCO oracle run 43753784319](https://github.com/FlareZ123/obfs/actions/runs/43753784319), pinned to source SHA `b34d7f02d8c4116f28b1ec5f4f0f34d6427025a6`; consult the run for its eventual verdict.

## Research question

The earlier [stateful step-only SCO study](sco-synchronizing-oracle-2026-11-15.md) searched for a short synchronizing input sequence using repeated runs of input symbol 1 before each probe. Its [falsification report](sco-sync-search-falsification-2026-11-15.md) found that **156/189** returned candidates did not physically merge all four hidden states in a 250-machine seeded corpus. That metric is useful, but it conflates physical state convergence with a weaker condition sufficient for functional output prediction: *observational equivalence*.

For a four-state deterministic binary Mealy machine, two states are observationally equivalent if every future binary input string produces identical output traces. Testing suffixes of lengths 1 through 3 suffices to distinguish inequivalent states for this finite-state bound. All classification happens in the evaluator **after** the public-query attack finishes; the attack does not inspect state IDs, transition tables, or output tables.

We report four separate predicates for an attacker-selected word: physical convergence over all four states, observational convergence over all four states, observational convergence over states reachable from the original hidden state 0, and observational convergence over states reachable from the private state **at the end of the discovery transcript**. The last predicate is relevant to an attacker continuing on the same nonresettable instance. It is distinct from behavior at the original unrepeatable initial state.

## Mechanism

The new `sims/sco-sync-diversified.js` remains a pure step-only chosen-input attack. It enumerates all 14 candidate binary words of lengths 1 to 3 in breadth-first order. For each candidate, it compares each of 14 nonempty suffix traces of lengths 1 to 3 over 12 probes, after cycling through binary **scramble sequences containing both symbols** of lengths 1 to 4. The scramble schedule is public and deterministic; the attacker has no private model data.

This costs more chosen-input calls than the original restricted symbol-1 schedule. No defender code or SCO server authorization is weakened, and attack computation is outside the protected program's 2.5× runtime budget.

Run `node sims/sco-sync-diversified-report.js` for a deterministic, model-by-model comparison. Run `node --test test/sco-sync-diversified.test.js` for the algorithm, the observable-versus-physical counterexample, and the real generated authenticated SCO facade. The finite corpus uses four-state, binary-input, binary-output deterministic Mealy fixtures generated by `makeGeneralMachine`; two independently seeded 250-machine sets use `(seedBase + Math.imul(index,seedStride)) >>> 0`.

**Interpretation:** this is a deterministic 500-fixture empirical reduction in *post-discovery observable* false candidates. The attacker uses approximately 2.195× and 2.260× as many public oracle calls in the respective corpora. It does not guarantee a short global physically synchronizing word, and it makes no production-wide performance or anti-cloning claim.

A concrete limitation is a four-state permutation automaton with all-zero outputs: no nonempty word physically synchronizes it, yet all states are observationally equivalent, so a word is suitable for predicting its output behavior. Conversely, a public step API cannot reveal transitions of unreachable private states. More probing cannot certify their physical convergence.

## Real emitted SCO artifact and authorization

The live differential uses `sims/sco-synchronizing-oracle.js`: `partitionScoAsyncModule` generates a public client ESM facade for a private four-state machine; only the client facade is served. An authenticated loopback RPC service executes the private original. The test verifies HTTP 403 on unauthorized calls, absence of a public reset method, absence of a private model/canary in served source, discovered `000`, and comparison of reconstructed outputs with 2,046 binary input words per scenario. The private model is available exclusively for post-attack verification. Public query cost, discovery tape, and strictly unseen test words are accounted for separately.

## Limits and future adversarial tests

The tested state bound, alphabet, deterministic transition assumption, and two seeded distributions are narrow. A nonresettable public interface may irreversibly leave transient states during exploration. If the resulting state is later made resettable or a second initial instance is exposed, post-discovery observational convergence alone is insufficient. Additional distributions, adaptive distinguishing sequences, malicious state layout, longer alphabets, and real network transport remain open. A client with unlimited authorized access can also relay the server's behavior; this study addresses oracle learning rather than server code disclosure or unauthorized authentication bypass.

The result remains in `im-results/` and should not be promoted to a security guarantee.
