# Selective SCO interprocedural local-helper partition, 2026-11-15

## Status and directly reproducible implementation

Intermediate implementation result. The trusted-server SCO module partitioner now accepts
unexported, parameter-simple non-generator function declarations (including async) and immutable
function/arrow `const` declarations. It has an explicit
`publicHelperNames` allowlist for helpers retained on the client; unlisted
helpers and the selected asynchronous private export implementation stay on
the server. Original ESM source is preserved on the trusted server for runtime
binding through `bindScoModuleExports`.

## Concrete source boundary

The original `examples/sco-public-helpers/before/mixed.mjs` declares the
private `PRIVATE_KEY` literal and `privateFold` function. The public client
retains the exact `normalizeInput` and `formatCount` helper definitions,
and has three ordinary public named exports. The private `secret` async export
becomes a same-origin RPC wrapper. The private key, private helper body, and
original private export implementation are absent from the emitted browser file.
The comparison is literal source-string inspection of the generated bytes, not
a theorem about extraction resistance. Source separation depends entirely on
keeping the original file outside the served public root.

The compiler rejects private helper function values escaping their direct call
sites; public reads of private helpers or private constants; private references
to exported public functions or explicit public helpers; dynamic public source
inspection; globally shared ambient roots; duplicate/unresolved helper
selections; and parameter defaults, rest, and destructuring in private
helpers. The proof is intentionally conservative and may refuse safe programs.
The public-helper list is an explicit author-reviewed declaration: including a
secret-bearing helper in that list would publish its source by design.

## Independent authenticated attacker

The separate [attacker module](../sims/sco-public-helper-attacker.js)
imports no source from the obfuscator or private server. It downloads only
the served client and extracts the public RPC method identifier, then uses
the legitimate session to query `secret('')` and `secret('x')`. Its explicitly
hypothesized model is `intercept + slope * value.length`, with JavaScript
UTF-16 string length. The independent [server and evaluation
harness](../sims/sco-public-helper-oracle.js) validates this offline clone
against 64 held-out strings of varying lengths and Unicode contents, with
no further authorized RPC calls. The test checks unauthenticated 403
rejection and that the private key and helper source remain absent from the
served JavaScript. All 64 held-out outputs matched, while the key literal
itself was never reconstructed. This is a finite, workload-specific negative
result for black-box functional secrecy. It does not imply similar learning
complexity for a cryptographic private function.

The independent attacker/harness split passed focused Ubuntu and Windows
[SCO authorization run 43767565961](https://github.com/FlareZ123/obfs/actions/runs/43767565961)
at source `9c59ba812842ef711ce4b80bef776d42cc64bb9e`.

## Differential mixed-helper coverage

The deterministic [36-graph differential test](../test/sco-public-helper-grid.test.js)
runs three private function forms against three public forms across four
source-order and name variants each. It checks 180 original-versus-generated
public and protected outputs, rejects exposure of each graph's private
key/helper identifiers, and uses bound private RPC methods for generated
public modules. The focused Linux/Windows
[run 43767717951](https://github.com/FlareZ123/obfs/actions/runs/43767717951)
passed at source `7e43e2335e5d319f881aa27f7d6c518684f91026`.
These graphs contain simple scalar local helpers; their count is useful
transformation-coverage evidence, not a broad proof for dynamic property
aliases, unusual effects, or every legal ESM construct.

benchmark, and Ubuntu Chromium integration. The generated fixture is covered
by these tests. Scoped passes do not establish a general security theorem.

The existing authenticated relay reproduces all 20 out of 20 held-out outputs.
The same trusted server still performs those private operations; with an
unlimited legitimate credential, an attacker may expose its oracle through
their own server. No effective anti-relay protection is claimed.

Neither test establishes tamper resistance in the fully controlled COO/SNO
threat models. The public source and RPC responses can be inspected or
instrumented. The sample heavy-loop SCO session has previously passed the
2.5x warm-localhost budget on selected workloads, but thin remote calls can
exceed that cap substantially. This new helper-graph work does not include a
new independently sampled WAN/TLS or cold-start 2.5x measurement. It must
not be promoted as an unconditional runtime or source-confidentiality result.
