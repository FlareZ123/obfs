## A. Real Chrome HTML SELECT insertion retains executable source that parse5's tree drops

**Pre-repair source:** PR [#387](https://github.com/FlareZ123/obfs/pull/387) head `15a4b0a1dc74c02cc319cf54c32c014d63b25b62`; test-only red-control branches:
- `agent7/smil-parser-namespace-adversarial-20261128` initial exact `bc8a64846734e959bd234f6602053b1c4cbe35e4`: [Linux/Windows focused run 46127443303](https://github.com/FlareZ123/obfs/actions/runs/46127443303) was **red** because the scanner missed `<select><svg><a href="#safe"><set attributeName="href" to="javascript:..."></a></svg></select>`. In the same source-pinned run, the independent real HTTP+nosniff Chrome check **passed**: the SVG anchor existed in SVG namespace and `href.baseVal='#safe'`, `href.animVal='javascript:window._smilHref=51'`. This proves an animated URL, **not click-executed code**.
- `agent7/select-script-pr387-red-control-20261128` at `2e167ece904b672851f0e759411e8ea59a4f527c`: [run 46128919694](https://github.com/FlareZ123/obfs/actions/runs/46128919694) was **red** on Linux and Windows, with six explicit scan observations:
  
  | Source in HTML SELECT | Original preflight | Browser observation |
  | --- | --- | --- |
  | `<svg><script>window._inlineWitness=61</script></svg>` | `inline script source` (correct refusal) | Real-HTTP Chrome executed JS |
  | `<svg onload="window._inlineWitness=63"></svg>` | **null**, no refusal | **Real-HTTP Chrome executed JS** |
  | `<iframe srcdoc="<script>parent._inlineWitness=69</script>"></iframe>` | **null**, no refusal | **Real-HTTP Chrome executed JS** |
  | `<option><svg><script>...66</script></svg></option>` | `inline script source` (correct refusal) | Real-HTTP Chrome executed JS |
  | `<math><mtext><svg><script>...64</script></svg></mtext></math>` | `inline script source` (correct refusal) | Real-HTTP Chrome executed JS |
  | SVG `<set to="jav&#x61;script:...">` | **null**, no refusal | Real-HTTP Chrome retained decoded SMIL animated URL |

  The independent browser test verified all five numeric JS execution witnesses on [the red-control run 46128519643](https://github.com/FlareZ123/obfs/actions/runs/46128519643). It uses actual loopback HTTP `Content-Type:text/html` and `X-Content-Type-Options:nosniff`, not `page.setContent`. The browser's SVG script execution does **not** mean each corresponding preflight missed it; the table separates them.

Additional local Chromium 144 probes found live `<style>`, `<link rel=stylesheet href=data:text/css,...>`, and an HTML `<base href>` inside SELECT; `document.baseURI` adopted the BASE URL and CSS rules applied. These trigger separate potential CSS source-map and SRI relative-URL identity issues; local DOM observations are not yet a source-pinned full asset/SRI differential.

**Repair research branch:** `agent7/smil-parser-namespace-adversarial-20261128` (initial scanner patch `0899c87ae223464400fc341c3ce4e7ab7e22ee97`; expanded CSS/base patch `efdf895f98f5df4ed60696b8ad85b272f88d0a5e`; tests `test/agent7-smil-parser-namespace-browser.test.js`, `test/agent7-select-parser-executable-source.test.js`, `test/agent7-select-base-sri-browser.test.js`). It conservatively performs a second `parse5.Tokenizer` scan only when an HTML SELECT start tag is textually present, refusing source-bearing tokens skipped by DOM tree construction; it decodes character references, ignores comments and rawtext, checks SMIL, scripts, events, srcdoc, data CSS imports and maps, BASE and META refresh. Refusing a suspicious SELECT-tag token is intentional even when a different parser drops the node. This parser fork uses an *internal* parse5 tokenizer export and must be pinned and reviewed. No general HTML parser equivalence theorem follows. Publication admission is a build-time boundary, **not** source secrecy against hostile clients.

## B. Native Web IDL DOMString coercion exposes function source after identifier renaming

**Pre-repair source:** frozen source-observer PR [#384](https://github.com/FlareZ123/obfs/pull/384) at `a8a22f9aef6e7f0d487cebc23c87063376df55cb`.

A private local function `function inspect(){const privateSourceMarker=17;return privateSourceMarker;}` can be passed directly into a native DOMString property/method setter (for example `document.body.setAttribute('data-probe',inspect)`) and converted to a string by Web IDL without any explicit `String(inspect)` or source `inspect.toString()` call. If the compiler renames `privateSourceMarker`, this observable string differs even when `inspect()` still returns 17.

- Node VM/host-shim donor `test/agent7-webidl-host-string-source-parity.test.js`, branch `agent7/webidl-string-coercion-source-audit-20261128` head `d633e867619184c4e1f69fb6b8eb8737bdb2dae5`, [run 46128292197](https://github.com/FlareZ123/obfs/actions/runs/46128292197): **30/30 source differences** (10 setter forms × COO/SCO/SNO) with `observesFunctionSource=false`, `metrics.bindings=1`, numeric 17 unchanged. Eight mock setters represent DOM-like coercion; two are deliberately opaque/unowned host functions. Shim evidence is *not* real browser behavior.
- Independent browser differential `test/agent7-domstring-real-browser.test.js`, same donor source, [run 46128295131](https://github.com/FlareZ123/obfs/actions/runs/46128295131): **18/18 source differences** for six *native* browser sinks (`setAttribute`, `setAttributeNS`, `dataset`, CSS custom `setProperty`, `textContent`, `innerText`) × three modes. Actual Chrome served both native and obfuscated JS over loopback HTTP, with `X-Content-Type-Options:nosniff` and `script-src 'self'` CSP. Source-string length changed from 76 to 66 in every case, while functional return parity held. This is a concrete compatibility defect, not a demonstration that attacker reconstruction is harder or easier.
- **Draft bounded repair:** `agent7/webidl-domstring-provenance-fix-20261128`, `src/ast.js` (initial `3655d7ad3c199545af228028a25044ca6fdc34ac`, later alias/destructure refinement `3de043253ec99f967faa59ef4bb91c50dbf60567`), tracks native-document element factories, element/style/dataset aliases, concrete string-converting methods and assignments and denies source-changing renames only when a non-provably-primitive value reaches a recognized sink. The non-DOM/unknown host callback surface remains an **explicit unproved boundary** and is tested as such, rather than claiming universal function-source parity.
- Initial corrected-browser source [run 46128602248](https://github.com/FlareZ123/obfs/actions/runs/46128602248) produced **18/18 actual Chrome native/emitted source parity with 0 rewritten bindings** but job failed because the test incorrectly required positive yield *inside* one of those deliberately source-observable cases. A subsequent test patch `0eed1940e67fdf0df3cbf71833257a301e511082` correctly moves positive-yield requirement to a separate source-free function and awaits exact-source CI verification. The Node shim at earlier repair pin likewise showed eight native DOM-like families × three modes correct, but still failed on two intentionally unresolved opaque host cases; later suite explicitly documents them as negative controls.
- **Tradeoff:** source-preservation veto reduces obfuscation yield for code that visibly stringifies functions. It is not an obfuscation-strength improvement by itself. The strong-protection release decision remains blocked.
