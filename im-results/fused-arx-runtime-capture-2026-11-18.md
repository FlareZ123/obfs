# Independent runtime capture and byte-exact clone of fused ARX Wasm pilot

**Agent 25, 18 November 2026 UTC. Intermediate attacker result.** This independently implements one **dynamic extraction** lane of the [stateful fused-Wasm charter](../workplace/batched-wasm-stateful-arx-candidate-charter-2026-11-18.md), applied only to Agent 43's [fixed kernel feasibility artifact](fused-stateful-arx-wasm-feasibility-2026-11-18.md). It is neither a complete blinded attack nor a release verdict.

## Executed attack and exact boundary

The hostile runtime preloads `sims/wasm-runtime-capture.js` **before** instantiating the candidate. It proxies real `WebAssembly.Module`, `Instance`, `Memory`, and compile/instantiate streaming and nonstreaming APIs, recording every actually consumed `BufferSource` under a SHA-256 digest. It observes real export names, snapshots exported or instrumented memory, then restores the global binding. It does not import the target's compiler while reconstructing a module; the API tests directly replay captured bytes from a fresh `WebAssembly.Module` and `Instance`.

The fixed pilot uses a public six-i32 `mix` export and a `memory` export, with input UTF-16 units placed at byte offset 16 and four return state words at offsets 0–15. The independent `sims/fused-arx-runtime-clone.js` replays that **public ABI** using a completely fresh module constructed from only the captured binary. It refuses an unexpected import/export topology and accepts the declared four input state words plus code units.

The observed module is **196 exact bytes**, SHA-256 `c2e9f1fbf85505a43681f0a09da9c0ebe9b7eeb9f067b69cd8320b703d8df88d`. Its recorded export names are `mix` and `memory`; one actual memory snapshot is captured. `test/fused-arx-runtime-extraction.test.js` compares the actual original, independent byte-copied attacker instance and separate JS reference across **10 input block lengths**, **8 deterministic state seeds per length**, and **320 signed 32-bit result-word comparisons**, including 12,288-code-unit and 102,400-code-unit blocks with memory growth. It also checks exact replayed binary equality and separate memory identities. A second five-test regression covers ordinary synchronous ESM, `compile`, `instantiate`, streaming WebAssembly methods, capture restoration, and writable memory cloning.

It neither recovers readable JavaScript source nor quantifies how long a blinded human attacker would take compared with minified JS. A known-public-ABI byte clone is not an incremental comparative advantage.

Agent 43's independent warm throughput evidence remains valid only for the fixed kernel, separate from this extraction result. ## Real Chromium attacker-origin replay (additional independent runtime witness)

The same public 196-byte binary was captured in an actual Chromium renderer with `page.evaluateOnNewDocument` inserted **before** the ESM application script. The injected page-global `WebAssembly.Module` Proxy received the real constructor argument and recorded the full byte array. The source page produced the native reference output; the capture matched the fixed digest above.

The attacker then closed the original document and the original HTTP source server. A second HTTP server on a **different port and web origin**, serving no original application code, constructed a new Wasm instance from the intercepted bytes. The clone replayed **17 input configurations and 68 exact signed state words** from the independent JS reference, including a 12,288-UTF-16-code-unit block. The browser was **Chrome/157.0.8103.78**.

This Chromium attack runs in `test/fused-arx-browser-runtime-clone.js` using public Puppeteer `evaluateOnNewDocument` interception; it does not depend on server compromise or read source from the closed origin during clone execution. It demonstrates a **port-separated execution environment**, which does not prove bypass of any claimed hostname lock because this fixed pilot had no lock. The browser-specific hook covers its synchronous `WebAssembly.Module` constructor, while the separate Node capture harness also tests promise-based `compile`/`instantiate` and streaming forms.

[Source-pinned manual Wasm workflow 44300124767](https://github.com/FlareZ123/obfs/actions/runs/44300124767) completed **green on Ubuntu and Windows** at exact commit `e72323f05b2b7fa74a4d7c00189e69cdbd7136f8`, with browser attack executed on Ubuntu and strict JSDoc checking on both OSes.
