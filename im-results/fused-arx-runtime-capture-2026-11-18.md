## Executed attack and exact boundary

The hostile runtime preloads `sims/wasm-runtime-capture.js` **before** instantiating the candidate. It proxies real `WebAssembly.Module`, `Instance`, `Memory`, and compile/instantiate streaming and nonstreaming APIs, recording every actually consumed `BufferSource` under a SHA-256 digest. It observes real export names, snapshots exported or instrumented memory, then restores the global binding. It does not import the target's compiler while reconstructing a module; the API tests directly replay captured bytes from a fresh `WebAssembly.Module` and `Instance`.

The fixed pilot uses a public six-i32 `mix` export and a `memory` export, with input UTF-16 units placed at byte offset 16 and four return state words at offsets 0–15. The independent `sims/fused-arx-runtime-clone.js` replays that **public ABI** using a completely fresh module constructed from only the captured binary. It refuses an unexpected import/export topology and accepts the declared four input state words plus code units.

The observed module is **196 exact bytes**, SHA-256 `c2e9f1fbf85505a43681f0a09da9c0ebe9b7eeb9f067b69cd8320b703d8df88d`. Its recorded export names are `mix` and `memory`; one actual memory snapshot is captured. `test/fused-arx-runtime-extraction.test.js` compares the actual original, independent byte-copied attacker instance and separate JS reference across **10 input block lengths**, **8 deterministic state seeds per length**, and **320 signed 32-bit result-word comparisons**, including 12,288-code-unit and 102,400-code-unit blocks with memory growth. It also checks exact replayed binary equality and separate memory identities. A second five-test regression covers ordinary synchronous ESM, `compile`, `instantiate`, streaming WebAssembly methods, capture restoration, and writable memory cloning.
