# Evidence-based mode and threat-model scorecard

Date: 2026-11-15, Agent 2. This is a consolidation of reproducible intermediate observations, **not** a certification of the primary objective. All claims below are scoped to the current prototype and cited tests or published measurements. No peer-review standard has been reached.

## Baseline: what is actually implemented

The current project provides Node.js CommonJS entry points for SCO, COO and SNO. COO outputs browser JavaScript files, SNO outputs a Node file group with a guarded launcher, and SCO runs an obfuscator-controlled HTTP server. The AST pipeline applies conservative identifier/property renaming; eager string encoding is enabled by default only for SNO and is opt-in for COO/SCO client files. An SCO server may expose separately implemented, authenticated RPC methods. The compiler does not automatically convert arbitrary browser logic into server-only computation.

## Independent security dimensions

| Dimension | COO (client-only) | SCO (server-controlled) | SNO (server-only, no trusted control) |
|---|---|---|---|
| Static source reconstruction | A pattern-based offline AST attacker recovers XOR-protected literals when enabled; deterministic names can be normalized to neutral readable labels. With client strings disabled, original literals stay visible. | Distributed script code is inspectable; genuinely server-resident RPC source is withheld from the client. Unlimited oracle access still leaks function behavior. | Every file is available to the filesystem owner. The same local XOR and name-normalization attacks apply to bundled code. |
| Runtime instrumentation/extraction | A client can run in an instrumented JS realm, read decoded literals and replace host-environment properties. | Client-facing JS is instrumentable; server-resident code remains outside the assumed attacker-controlled client. Outputs can be intercepted. | The assumed attacker controls Node runtime and memory and can instrument or dump local execution. |
| Unauthorized code modification | No robust local secret or integrity authority exists once the client controls its script and runtime. | An authenticated, independent trusted server can reject privileged RPC calls; a `Host` filter alone is forgeable. Distributed JavaScript remains editable. | The launcher detects incidental changes while unchanged, yet an owner recomputes unkeyed hashes or patches the launcher. |
| Execution outside intended environment | Client-side `location.hostname` checks are demonstrated bypassable by a forged realm. | A trusted server-side authorization decision can restrict server-resident computation, but distributed JS and responses cannot be unobserved. | No host-level trust anchor remains when the adversary controls disk, process and memory. |
| Performance | Lightweight name renames are inexpensive in measured steady-state loops. Optional eager string decoding exceeds 2.5× in large short-lived COO start cases. | HTTP/network and RPC costs remain unmeasured in a realistic use-case; server computation is a separate budget boundary. | Six deterministic steady-state workloads measured ratios 0.806× to 1.012× with `strings:false`. SNO server initialization deduction may apply to one-time decoder setup. |
| Behavior and compatibility | Node-based ESM and external-API regressions are supplemented by five real Chrome headless HTTP integration cases, including .mjs/.js module graphs, cyclic imports and host guards. | HTTP mutation, authenticated RPC and static ESM host-lock refusal have named tests; full browser+real-network end-to-end validation remains incomplete. | Native Node ESM/CJS launch and manifest tests are part of the suite; Windows and Linux Node22 pass the broad regression matrix. |

### Reproducible evidence inventory

- **General behavior**: manual validation [43679636260](https://github.com/FlareZ123/obfs/actions/runs/43679636260) reported 202/202 tests passing on Ubuntu and Windows, successful JSDoc type checks, and bundled benchmarks. Test suite includes several thousand fixed-seed generated property/alias cases, native ESM graphs, output path protection and actual network handler tests. This demonstrates case coverage, not a proof of semantics for arbitrary JavaScript.
- **Static reconstruction**: `sims/static-string-recovery.js`, `test/static-string-recovery.test.js`, `im-results/static-string-reconstruction-2026-11-15.md`; six source-only recovery tests passed in [43677647105](https://github.com/FlareZ123/obfs/actions/runs/43677647105). `sims/offline-normalize.js` and `test/offline-reconstruction.test.js` additionally neutralize hashed names.
- **Dynamic trust boundaries**: `test/security-boundaries.test.js` covers client-origin forgery, SNO manifest recomputation and spoofing SCO HTTP Host. `test/adversary.test.js` reads plaintext strings from an initialized decoder.
- **Alias/property correctness**: `test/exported-alias.test.js`, `test/lexical-scope.test.js`, `test/cross-file-ambiguity.test.js`, `test/property-reflection.test.js`, `test/default-parameter-name.test.js`; property hash collisions in `im-results/property-hash-collision-2026-11-15.md` include 40- and 48-bit reproducible colliding key pairs; URL import proof issue in `im-results/esm-absolute-url-alias-2026-11-15.md`.
- **Real browser compatibility**: `test/browser-integration.js`, `im-results/chromium-live-integration-2026-11-15.md`, manual Chrome [43679934331](https://github.com/FlareZ123/obfs/actions/runs/43679934331): five headless HTTP/DOM cases passed on Google Chrome 157.0.8103.50. Firefox/Safari and adversarial browser instrumentation remain untested.
- **Runtime cold-start budget**: `sims/cold-start.js` and report `im-results/coo-cold-start-budget-2026-11-15.md`; historical eager client decoder measured 2.74× for one 4KiB string, 30.60× for one 64KiB string and 32.18× for 256 literals. The default has since changed to disable client eager strings. These numbers characterize the **explicitly enabled string decoder**, not current default COO.
- **Decoder improvement**: `sims/decoder-candidates.js`, `im-results/decoder-strategies-2026-11-15.md`, [CI 43677401260](https://github.com/FlareZ123/obfs/actions/runs/43677401260): 4096-unit chunked UTF-16 decoding was 3.73×–5.24× faster than concatenating each character for two 65K-unit scenarios. Short strings were slower. No universal decoder guarantee.
- **Steady-state runtime**: `sims/hotpath-mixed.js`, `im-results/sno-hotpath-mixed-2026-11-15.md`, [CI 43679371518](https://github.com/FlareZ123/obfs/actions/runs/43679371518): six repeated-use workloads returned identical results, observed median overhead 0.806×–1.012× under defined conditions.

## Combined conclusion

The strongest available protection for sensitive **server-resident** algorithms comes from keeping their source and secrets off the untrusted device and enforcing server-side authentication. The local SCO/COO/SNO JavaScript mangling layer currently provides limited friction against casual inspection, with clear automated static-recovery counterexamples. Within the SNO complete-owner model, source-only cryptographic hashes are not a meaningful owner-resistant integrity boundary.

The conservative AST proof is moving toward better semantic reliability: we have found and repaired exported-alias escapes, lexical collisions, dynamic wrappers, inherited-getter reflection, shortened-name hash collisions and alternate ESM resolver aliases. Refusing an unproved transform is preferable to publishing behavior-changing output. The incomplete property-flow and module resolution engine remains the main functional ceiling.

**Still unproven**: a general 2.5× runtime upper bound, resistance to determined instrumented clients, externally enforceable COO hostname locking, owner-resistant SNO tamper protection, broad browser compatibility, anti-LLM/agent-team resistance, and a transformation that preserves all observable JavaScript reflection (including source-code introspection). The main deliverable should describe these limits plainly.

## Next most valuable decisions

Before adding heavier VM/Wasm/control-flow machinery, establish whether a candidate's measurable static-reconstruction cost, instrumentation resistance and hot-path overhead justify the new semantic risk. Supply native runtime regression corpora and representative browser tests. For SCO, prioritize authenticated server-resident execution and measure request/granularity latency; for local modes, invest in whole-program ownership and sound import resolution. Promote results into `results/` only after independent reproduction and genuinely publishable synthesis.
