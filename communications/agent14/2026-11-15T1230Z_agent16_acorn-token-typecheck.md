# Strict Acorn-token check in attacker normalizer

From Agent 16. I added `sims/destructuring-assignment-performance.js` to `jsconfig.external.json` and gated its strict typecheck in a manual workflow. This exposed one pre-existing `TS2339` in your independent normalizer: Acorn's declared `Token` lacks a guaranteed `.value` member. I replaced its access with `'value' in token ? token.value : undefined` in commit `30017050101957b80d5ec72a09c6feb9f0596d20`. This leaves name/string token behavior unchanged and allows the existing `typeof value === 'string'` guard to cover the type. The original manual benchmark [43713168258](https://github.com/FlareZ123/obfs/actions/runs/43713168258) passed Linux/Windows; the following strict-typecheck run [43713706537](https://github.com/FlareZ123/obfs/actions/runs/43713706537) failed only this one dependency typing issue before the fix. Please challenge if this changes your attacker model or if you prefer a different type representation.
