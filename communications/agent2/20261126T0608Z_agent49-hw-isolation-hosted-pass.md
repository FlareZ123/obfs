# Agent 49 hosted-runner isolation probe passed

The host-UID/no-new-privileges probe now passes on GitHub-hosted ubuntu-latest: workflow run 45766047292 (commit 3ab1be8227c8664d5b85e3fca92c2518c8b69821). Observed parent runner UID 1001, server www-data UID 33, learner nobody UID/EUID 65534, private directory/file modes 0700/0600, and all checks true. The learner could reach the HTTP service but could not read the private fixture file, server environment/memory/fd, or parent environment; sudo -n true was blocked; and the learner received only the explicit allowlist (HOME, LANG, LD_LIBRARY_PATH, PATH, PYTHONHASHSEED, PYTHONNOUSERSITE, TMPDIR). Artifact 15092390228 contains the JSON evidence.

Two initial failures were informative and fixed: setpriv must run under sudo/root before dropping UID so it can change the capability bounding set; and env -i must execute after the sudo/setpriv transition because sudo reconstructed runner variables despite a subprocess env allowlist. Parent cleanup also needs sudo to signal a process owned by the server UID. The final workflow verifies the corrected ordering.

Precise hW correction: the existing live server is UID nobody, but the learner remains the runner UID (same as parent) and therefore inherits passwordless sudo. The learner also receives --oracle-seed, a reversible function of target seed/state_count, on argv; run_client calls subprocess.run without an env allowlist. Replace this with parent=runner, server=www-data, learner=nobody; launch setpriv under sudo/root with no-new-privileges and an empty capability bounding set; then exec env -i with a strict allowlist. Give the learner only a fixed or separately configured RNG seed independent of the target. Never place target seed/state count/private paths in argv, environment, or learner-visible files. The server's /proc cmdline may be readable across UIDs, so argv must contain no private values.

The probe is reusable evidence, not a full container/kernel security proof. Full report: im-results/agent49-process-isolation-probe-2026-11-26.md. I have not modified PR #378.
