## Narrow, safe may-flow closure

The current `observesDistributedSource(ast,importedStrings)` in `src/ast.js` already follows intra-file `scriptElementRoots` monotonically through identifiers and direct `document.createElement('script')` expressions. It does **not** track `CallExpression` values through an imported factory returning a DOM script. Your opaque string-token workaround is a good independent fallback; it is intentionally incomplete for hashes assembled from runtime components.

The existing `src/cross-properties.js` already implements the useful structural substrate: `resolveImport` for static relative ESM dependencies, export-name maps, `export {...}` / `export *` relays, and monotonic fixed-point propagation, exemplified by `collectImportedFunctionArrays`. A bounded new `collectImportedScriptFactoryReturns(files)` can be an analog returning `Map<filename, Set<localImportedFactoryIdentifier>>`. Compute per-producer *possible script return* facts in a may-analysis lattice; never use them to prove non-script for unknown calls:

1. Mark the return of any top-level function as `MayDOMScript` if any syntactically reachable `return document.createElement('script')` or `createElementNS(...,'script')` exists, including a simple local alias via `const s = ...; return s`. Treat a conditional branch with one such return as may-script. Reject/ignore unsupported nested dynamic scope as a proof of a safe non-script return; allow conservative source-byte refusal if opaque.
2. Propagate facts across top-level immutable function aliases and direct wrapper returns `return anotherKnownFactory()`, with a monotone fixed point. Export the public symbol through `export function ...`, `export {local as name}`, named `const` exports, default exports if supported, and source-known reexports. Import into the consumer via static ESM import specifiers using `resolveImport`; cycles converge to a fixed point of finite names.
3. Extend `isScriptElementTarget` and the initial `scriptElementRoots` pass to recognize `const candidate = importedFactory()`, assignments `candidate = importedFactory()`, and direct call receivers `importedFactory()[key] = expression`; include local transitive identifier aliases and direct wrapper expressions. An unknown computed property key on a possible DOM script is source-observing, even when `expression` is runtime-composed `'sha384-'+digest`. Proven fixed non-`integrity` key may retain transformations if no other observer.
4. Keep this as a **may-use guard** only, not a claim that an imported factory *always* returns the native element or that its return is definitely isolated. Reassignments, document.createElement monkey-patching, conditional returns, unexpected CORS and mutable imports may introduce false positive refusals; these cannot justify a source-changing rewrite.
5. Do not infer safety from absent `MayDOMScript` in the bounded grammar. Local `document.createElement` receiver roots and your literal hash-token fallback still apply independently. Dynamic `import()`, Reflect.apply, bound functions, spreads, promise callbacks, global aliasing or module loader rewriting remain either unproved or need dedicated conservative source-observer cases. The scope is a finite static ESM subset, not arbitrary JS call graph completeness.

## Concrete falsifiers and yield

**Red target without a contiguous SRI literal:** `factory.mjs` exports `build(){ return document.createElement('script') }`. `consumer.mjs` imports `build`, calls `const e=build()`, computes the digest through `crypto.subtle.digest('SHA-256', originalResponseBytes)` or concatenates an externally supplied digest into `e[globalThis.attrName || 'integrity']='sha256-'+digest`, sets `e.src='./client.js'`, and appends it. The digest literal fallback cannot catch this because the string is runtime assembled, yet the browser enforces SRI if the native fixture has a known original hash. Require native+guarded execution and byte-mutated SRI rejection via the existing Chrome harness.

**False positive control:** A similarly imported pure factory `buildPlain(){return {state: 1}}`, with the same unknown computed setter but no possible DOM script, should preserve nonzero private rewrite yield under `strings:true`/appropriate property selection. A second control sets a statically proved non-`integrity` key on a known script and verifies the unrelated source can still be transformed when no SRI is present. Both controls must run in an externally imported multi-file graph.

**Critical adversarial variant:** `const f = condition ? buildScript : buildPlain; const e=f(); e[key]=runtimeDigest`; the analysis must be conservative when one possible target returns script, and avoid claiming a single-target callee proof if branch alias resolution is unsupported. Reexport through `relay.mjs` and explicitly use `import {alias as make}` to test the fixed point. An imported mutable binding cannot be assumed permanent by name alone.
