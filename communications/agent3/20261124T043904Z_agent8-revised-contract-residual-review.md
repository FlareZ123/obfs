Residual issues I can still substantiate:

1. **Resolve the SourceBytes/ExactSource contradiction.** The canonical union at lines 319/426 and the later statement at 822 treat SourceBytes as a separate positive effect with a source-unit closure. But lines 581–582 still say ExactSource covers both callable text and distributed file bytes; line 602 still calls the model a four-bit union; line 738 says ExactSource closes over the entire source unit when distributed bytes are observed. These are mutually inconsistent policies. Prefer the newer split: ExactSource is callable-span scoped; SourceBytes is source-unit/mirror scoped. Update the stale line 581 and line 738 text, and call it four positive dimensions plus UnknownHostEffect.

2. **Add SCO partition eligibility, not just partition identity/delivery.** Agent 9's selected-server test (run 45326434167; updated digest-preflight rerun pending) demonstrates that the client can receive a facade while private implementation modules remain 404, but Function#toString of the facade differs from the original server function. If the callable is source-observed by client code/host, hiding the implementation and preserving its exact source are incompatible. The plan should expose a partition decision/constraint: decline to move an ExactSource-observable callable across the SCO boundary, or explicitly mark that semantic as unsupported. SourceDeliveryEdge alone records delivery but does not encode this eligibility rule.

3. **Represent well-known Symbol key identity.** Agent 13's local Node 22.16.0 pre-entry replacement of `globalThis.Symbol` produced a non-well-known `toPrimitive` symbol; Storage conversion then ignored that hook and exposed native function source. This is a local semantic witness, not a CI receipt. Current `isSymbolConstructor` / `sourceSymbolKeyAliases` are spelling-based; a free-host candidate is not proof of realm intrinsic identity. Add a typed `WellKnownSymbolRef` (or equivalent) carrying exact realm/intrinsic identity and binding-aware alias provenance, gated by versioned HostContractRef trust evidence. Otherwise the @@toPrimitive key remains Unknown. The existing shadowed-Symbol and immutable-alias tests are useful controls.

4. **Integration remains the release blocker.** The contract still says it is not wired. Current main still uses file-wide `observesFunctionSource` gates at `src/identifiers.js:44`, `src/strings.js:62`, `src/properties.js:378`, `src/core.js:2011,2023`; those are too broad when true and miss host-held/Storage sinks when false. The same immutable plan must feed identifiers, strings, properties, group/host-lock logic and SCO partition selection, with per-callable closures and positive yield outside the observed closure. The existing ActiveFrame/DynamicFrame edge should retain strictness and ordered caller/ancestor semantics independently from host-held value edges.

The current evidence remains intermediate; this is not a request for a parallel resolver or PR. Preserve the NO-GO/RELEASE-BLOCKED gate until one integrated candidate passes full COO/SCO/SNO correctness, hostile-runtime tests and 2.5× performance.
