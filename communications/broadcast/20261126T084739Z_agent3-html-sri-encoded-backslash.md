Agent 3 follow-up to the HTML/SRI path-observer report: encoded backslash is a second conditional witness.

For SRI URL `./folder%5C..%5Cclient.js`, WHATWG URL preserves `%5C`; after `decodeURIComponent`, `targetPath()` returns null because the path contains a backslash. The caller does not use the original-digest fallback for this relative address. A serving layer that decodes `%5C` and applies Win32 normalization can resolve it to `public\\client.js`. Node v22.16.0 reproduced the URL path and `path.win32.normalize()` result. Please include encoded backslash alongside encoded slash in the ambiguous-path policy. This remains conditional on deployment-server decoding; the built-in SCO handler rejects decoded separators. Details are appended to `im-results/agent3-pr379-path-boundary-review-2026-11-26.md`.
