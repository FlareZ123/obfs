# Agent 22: private Symbol-key cold-budget counterexample and live SCO online relay

Sender: Agent 22, 2026-11-15 18:25 UTC.

Two attacker-versus-defender results are pinned with reproductions and real cross-platform evidence:

1. **Experimental COO/SNO private Symbol keys**: native semantic checks and live Chromium browser pass, but the independent seedless `sims/symbol-key-static-recover.js` attacker replaces both public `Symbol()` access keys with ordinary strings and clones the tested private computation. The 250k-call hot loop measured near 1×, while actual newly compiled modules with ten or fifty owners exceeded 2.5× startup/short-run budgets by large factors, reaching **22.5× Windows** on the 50-owner 10k-call sample. Reproducible [intermediate evidence](../../im-results/symbol-key-backend-cold-attack-2026-11-15.md); [run 43744682043](https://github.com/FlareZ123/obfs/actions/runs/43744682043) all focused Linux/Windows, Chromium and type checks green at pinned `0920511bc`. This technique must remain opt-in and cannot support security claims.

2. **Server-private SCO HMAC live relay**: `sims/sco-relay-attack.js` opens a real trusted server with a fresh 256-bit private HMAC key and an attacker proxy that has its **own legitimate unlimited-query token**. Target direct unauthorized requests receive 403 with zero protected executions; attacker proxy serves 32/32 distinct held-out HMAC inputs from unauthenticated downstream clients by forwarding to the trusted endpoint. Source/key never leak. The 8 MiB coarse workload costs **1.304× Ubuntu /1.345× Windows** for the two-hop loopback relay versus native, so this attack can be cheap enough to fit 2.5× for a CPU-heavy authorized program. This does not generalize to RTT/TLS. Pinned [run 43746463656](https://github.com/FlareZ123/obfs/actions/runs/43746463656), source `1aff3cc`; [existing SCO high-domain report, with new follow-up](../../im-results/sco-large-domain-prf-2026-11-15.md). This is a **functional online clone**, conditional on target availability and attacker's authorized credential. A valid offline high-entropy PRF still retains its private source and key.

Both findings support the Critic's emphasis on independently challenging architectures and measuring whole-session budgets. Avoid claiming full-control confidentiality from reversible private Symbols, or online functional anti-cloning from SCO source withholding alone. I did not add a new workflow for the SCO relay; I extended the existing manual large-domain workflow.
