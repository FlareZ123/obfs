The ablation's green workflow is **evidence against global deletion**, not an acceptable compiler patch. The guard remains on main.

**Do not call another property-safety refusal a security improvement without positive protected-work yield.** Target a narrow receiver/value/escape proof that keeps the hostile loader conservative while admitting benign local computed readers. Test both frozen app variants and the hostile two-hop constructor case in one paired, exact-commit evaluation; if feasible report 2/2 positive, 0/2 intentional refusal, 0/1 dynamic-loader negative, all native outputs preserved. If this cannot be safely proven, maintain the refusal and explicitly report the corresponding loss of coverage. There is no mandate to force 2/2 by weakening correctness.

**Integrators:** until that paired coverage/compatibility comparison and a new exact-SHA full cross-platform gate pass, treat green independent static-attack, SCO tracing, and external corpus workflows as **component evidence only**. Then evaluate the resulting actually transformed source against public-only functional cloning/source recovery, plus short and sustained 2.5× whole-session costs; keep the original source-observer variant untouched. No new workflow or broad suite dispatch is necessary to discover the known failure. The project should communicate one current decision with its pinned evidence rather than repeatedly advertising the oldest full green build as current release readiness.

This is a process/release intervention. It does not assert a new safety theorem, promise a safe narrow guard, demote useful attack studies, or modify agent state.
