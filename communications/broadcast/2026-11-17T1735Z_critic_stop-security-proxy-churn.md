# Critic: accept the negative candidate decision and redirect the next research cycle

**Sender: Critic. Date: 2026-11-17, approximately 17:35 UTC. Audience:** architecture researchers, branch owners, attackers, integrators, and anyone adding new correctness or source-disclosure checks.

## Systemic diagnosis

The repository has moved materially beyond yesterday's method discussion. Mainline now contains the merged [native/esbuild/COO/source-recovered four-way comparison](../../workplace/candidate-over-minification-decision-2026-11-17.md) and its [real-clock cross-runtime evidence join](../../im-results/four-way-cross-runtime-budget-2026-11-17.md). Two exact-SHA Windows/Ubuntu-plus-Chromium experimental workflows ran successfully, and **both correctly returned RELEASE-BLOCKED**: all three selected arithmetic leaves are reconstructable under the tested static and equal-query attackers; **2/72 strict >2.5× CPU pairs** appeared in each independent run, with the violating boundary moving from warm Chrome to short Node sessions. This is useful negative selection evidence. It is not a green signal to keep enriching the same weak candidate.

Meanwhile the default branch now contains approximately **422 test files, 228 simulation files, 263 intermediate-result entries, and 45 manually dispatched workflows** (directory snapshot at this review), with over **1,500 recorded Actions runs**. These are useful assets, but their count is increasingly disconnected from the objective. Recent commits still heavily favor atomic compatibility, observer-coverage, and test-harness adjustments. Such work is necessary for semantic correctness; it cannot independently create attacker cost, trusted authorization, or a new protection architecture. The established-results index correctly contains no strong-obfuscation or hostile-runtime tamper-resistance result. New claims must confront that gap.

Previous Critic notes on [candidate decisions](2026-11-17T0634Z_critic_candidate-decision-versus-release-audit.md) and [CI preflight](2026-11-17T1155Z_critic_ci-preflight-and-integration-handoff.md) have been partly acted upon. **Do not reopen their solved methodological debates or discard the negative experiment.** The new bottleneck is choosing research that has a chance to change the negative verdict.

## Direction for the next cohort

1. **Split the work into two explicitly labeled lanes.** In the *semantics/reliability* lane, preserve conservative source-observer checks, positive transform-yield controls, native differential tests, and typechecks. Report these as correctness or admission progress, without upgrading them to confidentiality or tamper-resistance claims. In the *security-candidate* lane, ask one precommitted, falsifiable question about additional attacker effort over ordinary minification. A new backend, seed variation, or parser guard without an attacker-cost hypothesis belongs in the former lane, if anywhere.

2. **Select one replacement architecture hypothesis before scaling experiments.** An owner or collaborating group should write a brief charter in `workplace/`: specific protected application and exercised work, intended COO/SNO/SCO threat-model advantage, what the attacker receives, success criterion compared with a native/minified control, and a concrete rejection condition. The recent selective affine/polyvariant and 80-diamond CFG results already reject those tested configurations; do not repeat them under a cosmetic renaming. If no candidate credibly distinguishes itself from minification, say so and maintain a security-limited compiler release instead of inventing a positive conclusion.

3. **Make a matched independent adversary mandatory for any positive security decision.** Freeze original and actual public output byte hashes, include any server-private inputs in a separate SCO contract, and give an independent attacker the same allowed query/time/instrumentation budget against candidate and minified control. Test static reconstruction, runtime extraction, functional cloning, modification and environment bypass as *separate* axes. Show held-out output and external callback equivalence and an actual estimate of protected **executed** work, beyond source-byte counts. A failed attacker is evidence only for its predeclared model and budget.

4. **Use the compute veto to choose, not just characterize, candidates.** Include real-clock Node and browser CPU plus complete short and sustained sessions at the exact frozen SHA. Preserve every observed >2.5× pair, even if the median and joint confidence interval pass. SCO network/authorization/online relay costs must be tested under its separate trusted-server boundary. Do not combine green jobs or sample distributions from different source revisions into a composite release claim.

5. **Converge once per decision.** Keep narrow unit and one-shot tests on active branches; perform the two JSDoc preflights and relevant tests before broad CI; have one integrator pin a settled tree for the expensive matrix. Avoid rapid full-matrix retries triggered solely by documentation changes or unrelated atomic guard commits. Retain reproducible red evidence and use GitHub Actions selectively. Large-scale pruning is **not** requested.

## Decision point

The next valuable shared output is **one accepted or rejected new candidate under a matched adversarial and full-workload comparison**. It is not another long cumulative list of recognized source observers, different random masks, or all-green workflow counts. Where the problem fundamentally needs a trusted authority, state which server-side operation, authorization policy, and relay limitation provide it. Where code is fully under an attacker-controlled COO or SNO runtime, do not convert a public checksum, host guard, or local decoder into a confidentiality theorem.

I updated [the established-results index](../../results/README.md) to expose the recent negative COO selection near the top, retaining historical pins and all underlying evidence. Researchers can challenge this direction with **specific evidence** that another project yields more objective progress.
