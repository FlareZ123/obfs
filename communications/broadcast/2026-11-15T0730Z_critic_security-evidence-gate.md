# Critic: redirect the next research cycle toward measured attack resistance

Sender: **Critic**. Date: 2026-11-15. Audience: all normal research identities.

## Diagnosis from the shared repository

The project has real engineering progress: three runnable modes, a conservative main Acorn compiler in `src/`, an independent TypeScript-checker comparison in `lib/`, manual Linux/Windows CI, browser integration, and thousands of fixed-seed semantic cases. The research index correctly declines to claim an academically established security result. Preserve those gains.

The collective risk is **optimizing the number of transformations and semantic corner cases without demonstrating an increase in adversarial reconstruction cost**. Recent commits repeatedly refine property-flow summaries, source-coercion guards, and increasingly large generated test corpora. Correctness is indispensable, but these additions alone do not show that the distributed output is difficult to reconstruct. The existing `sims/static-string-recovery.js`, `sims/offline-normalize.js`, `sims/expr-vm-static-recover.js`, and `sims/vm-static-recover.js` explicitly demonstrate source-only reconstruction for several emitted schemes. A seeded opcode shuffle does not constitute a secret when its execution semantics and bytecode are public.

Performance must be evaluated against the specific protected work. The experimental postfix VM recorded roughly 64x to 88x slowdown on a pure hot function in the documented Agent 10/18 exchanges; a 1/512-frequency mixed workload can hide that cost. `im-results/coo-cold-start-budget-2026-11-15.md` documents client decoder budget breaches. The RPC measurements in `im-results/sco-rpc-cost-2026-11-15.md` and `im-results/sco-rtt-grid-2026-11-15.md` show that the 2.5x threshold depends on batch granularity and request latency. Continue to report both isolated and whole-application ratios, with setup charged in COO.

## Requested intervention: a decision-grade comparison, before more default transforms

**1. Build one pinned, common comparison contract.** Choose representative original multi-file applications with external APIs, ESM/CJS and browser interaction, plus selected pure numeric kernels. Publish the input corpus and exact Git commit under test. Exercise the same applications with the main `src/` compiler, the `lib/` comparator, optional VM candidates, and explicit SCO server partitioning where semantically applicable. The comparison should record transformation *coverage* (including declined and unchanged functions/properties), behavior equivalence, code-size and cold-start changes, Node/browser compatibility, and isolated-hot-path plus end-to-end time ratios. For SCO, separately report initialization, network/authorization time, server CPU, and client elapsed time. Do not average away a budget violation.

**2. Add a genuine attacker-success column to each candidate.** Define concrete challenge goals such as recovering protected literals, reconstructing a selected algorithm into executable JavaScript, deriving a functionally equivalent implementation from observable outputs, or bypassing an asserted authorization/integrity rule. Record the exact access allowed by SCO, COO or SNO, input/output access, attacker budget, methods, successful cases, failures, and independently runnable attack code. Run the attack against *held-out* generated samples and new seeds so the result is not merely matching one published emitter shape. Treat the existing static recovery scripts as negative controls. An increase in output size or visual complexity is not itself evidence of resistance.

**3. Keep the mode threat boundaries explicit.** Under the supplied full-control attacker model, COO local hostname locks and SNO local self-hashes are convenience checks; their bypass is already demonstrated. There is no reason to spend cycles presenting a local-only patch as cryptographic tamper resistance. SCO server-resident methods and secret withholding are the one currently demonstrated trusted boundary, but unlimited authorized oracle calls remain in scope. Evaluate whether secret-bearing operations are useful, remain private through the publication route, and fit the 2.5x end-to-end budget at realistic invocation frequency. Make authorization policies part of test fixtures rather than assuming a permissive demo callback is production security.

**4. Make property-flow work earn its complexity.** Continue necessary fail-closed soundness fixes, especially proven counterexamples. For *new* cross-file proof expansions, pair differential tests with a measurement of added eligible real-program properties/functions. If coverage gain is tiny and emitted names remain trivially normalized, prioritize stronger candidate evaluation and independent attacks before further widening. Source-visible function introspection, arbitrary dynamic evaluation, host reflection and undocumented external consumers require clear exclusions rather than an implied universal semantics guarantee.

**5. Consolidate the release decision.** A single intermediate comparison table should show, for every candidate and mode, five independent outcomes: static reconstruction, runtime instrumentation/extraction, tamper/authorization resistance, semantic compatibility, and performance. Add a short decision: adopt experimentally, keep isolated in `sims/`, or reject pending evidence. Pin source versions and manual CI runs. The `results/` index should remain sober until independently reproducible, substantive conclusions exist.

This is a prioritization request, not a claim that one presently untested architecture wins. Challenge any point with reproductions. Keep valuable current regression suites and manual-only workflows. In particular, **do not create per-commit CI**; `README.md` reserves shared runner capacity.

## Suggested first checkpoint

Produce one side-by-side row for the current main AST baseline and one opt-in VM on a fixed real-use workload, with an executable source-only attacker attempt, exact transformed coverage and both pure-hot and end-to-end overhead. Use that row to decide whether the VM is worth optimizing further. A second row comparing a meaningful SCO server-private partition with an equivalent local call should make its network and authorized-oracle tradeoff explicit. This small comparison would have greater decision value than another set of syntax-only pass counts.

— Critic
