# Agent 8: concrete hybrid LLM + compiler adversary for obfs5 anti-LLM acceptance

**28 Nov 2026 ~06:45 UTC. Research direction / untested hypothesis, NOT an established attack on our compiler.**

The repo's anti-LLM requirement should include a **hybrid semantic-recovery adversary**, not just a single LLM asked to explain minified JavaScript. The 2026 ICSE-SEIP [CASCADE: LLM-powered JavaScript Deobfuscator at Google](https://conf.researchr.org/details/icse-2026/icse-2026-software-engineering-in-practice/21/CASCADE-LLM-powered-JavaScript-Deobfuscator-at-Google) uses Gemini to *identify* encoding/string-fetch prelude functions and then a deterministic JavaScript IR compiler to propagate constants and inline residual operations. The corresponding [public Google JSIR](https://github.com/google/jsir) is available; **the full CASCADE Gemini pipeline is not verified here as a runnable published package**, so do not claim an off-the-shelf CASCADE benchmark pass/failure. This complements existing repository JSDeObsBench/JSIMPLIFIER and pinned Webcrack controls.

Falsifiable, source-pinned attack acceptance protocol to implement if valuable:

1. Freeze an **identical public-source input** from the PR384 head `a8a22f9aef6e7f0d487cebc23c87063376df55cb` and its **equal-trust ordinary-minifier control**. Provide neither original native source nor expected formula outputs to the attacker; hash the inputs. Keep model prompt, model snapshot/version, call counts/token limits, tool versions and total wall/compute budget identical between arms.
2. Give the LLM only **prelude detection/classification** or a bounded transformation plan. Apply a pinned deterministic parser/IR/constant-propagation engine; compare this against pure LLM direct deobfuscation, and against a pure Webcrack/unminifier pipeline. Record failure and parser-compatibility separately from semantic source restoration. If CASCADE source is unavailable, label any recreated hybrid as **an independent approximation**, not original CASCADE.
3. Require **semantic recovery above trivial copying of public executable code**: hidden original formula/operator/constant or API/decoded-string recovery with structural equivalence normalized for alpha-renaming, plus heldout native-vs-recovered functional cases under changed host callbacks. Running the downloaded obfuscated source, or a tool-generated pretty printer output, is **not** proof of original-source recovery. Independent source observer traps and exact typed return/host callbacks should gate false positive reconstructions.
4. Report separate failure rates for static understanding, dynamic extraction, tamper/domain bypass, and <=2.5× production CPU. This test's attack-time budget is *not* the obfuscated-program CPU budget. Never reinterpret successful hybrid recovery of the ordinary minifier as an attacker advantage against the protected candidate; use a matched delta.

Reference benchmark [JsDeObsBench](https://github.com/Ch3nYe/JsDeObsBench) scores syntax, behavior and simplification; [Google JSIR](https://github.com/google/jsir) provides a target for open-source IR-based reasoning. Recent [defuscator/deobfuscation-benchmark](https://github.com/defuscator/deobfuscation-benchmark) illustrates mutation/semantic caveats, including deobfuscated self-defending guard hanging despite original output executing; treat this as a separate compatibility/security classification rather than blindly making a green/recovery claim.
