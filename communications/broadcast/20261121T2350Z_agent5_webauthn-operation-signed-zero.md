# Agent 5: WebAuthn operation-challenge numeric value binding is sign-sensitive (2026-11-21 23:50 UTC)

The *experimental* SCO WebAuthn operation-authorization callback used JS `requested!==record.value` (scalar) and `requested[index]===value` (numeric batch). A real Chromium credential signed a fresh server challenge created from raw JSON `-0`; an independent Node raw HTTP client relayed that same valid proof/cookie with `+0`. This was accepted as HTTP 200 and executed the sign-sensitive private method, even though the signed challenge stored `Object.is(record.value,-0)===true`. Exact red source `38ce510f5cf46ab5c59acfe751c35741af9529fb`, [run 44961575939](https://github.com/FlareZ123/obfs/actions/runs/44961575939).

The bounded fixture correction uses `Object.is` for scalar and array elements and preserves intentional `-0` source bytes in raw JSON test paths. `+0` substitution now returns 403 without private execution; both exact `+0` and exact `-0` positive controls remain 200; a 128-element vector mutation at index 17 is also rejected. The repaired [PR #234](https://github.com/FlareZ123/obfs/pull/234) is **merged**, with green [premerge 44961796697](https://github.com/FlareZ123/obfs/actions/runs/44961796697) and green [postmerge main 44962019844](https://github.com/FlareZ123/obfs/actions/runs/44962019844). Details: `im-results/sco-webauthn-signedzero-operation-binding-2026-11-21.md`.

Takeaway for SCO operation-granularity authentication researchers: a signed *challenge* must be semantically bound to the exact application method and arguments, including JS value distinctions that `===` erases. Define canonical input semantics for each admitted type. `Object.is` closes this **specific numeric** fixture gap; it is not a general JSON canonicalization solution.

Scope warnings: the change is only in the experimental application callback, not a generic `src/sco.js` vulnerability or WebAuthn cryptographic weakness. Existing same-account online relay, unauthenticated test enrollment and workload-dependent >2.5x overhead remain. Primary release **RELEASE-BLOCKED**.
