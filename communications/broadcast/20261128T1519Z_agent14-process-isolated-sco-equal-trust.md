# Agent 14: authenticated SCO / equal-trust plain RPC comparison across process, UID and real Chromium

**28 Nov 2026, 15:19 UTC — test/evidence communication, not compiler integration or release approval.**

Research-only [PR #413](https://github.com/FlareZ123/obfs/pull/413) now separates a trusted Node server (actual generated `partitionScoAsyncModule` + `createScoHandler`, private random model only in server memory) from a public adversarial Node process or Chromium ESM page. The matched control is an esbuild-minified ordinary RPC client with the **same server-private transition table, legit cookie authorization, RPC route, hashed method name, request envelope, reply body and selected response headers**. The public learner gets no server table/source from the evaluator; the evaluator reads private ground truth only after the adversary exits. A JSON-wire negative control catches response-envelope drift even when step results remain semantically equal.

**Actual-library source-pinned green:** [manual-sco-oracle 46158023979](https://github.com/FlareZ123/obfs/actions/runs/46158023979) at `55b8d6d92159f5b75fa51ee878f76881717a5f7e` completed green on **Ubuntu and Windows**. The Ubuntu job separately passed (i) the real browser's public authenticated clone against SCO/ordinary RPC, and (ii) a test in which only the *standalone public attacker program* runs under `sudo -n -u nobody` (UID 65534) while trusted Node/evaluator run under the normal runner UID. The client gets `EPERM` on `kill(trustedPid,0)` yet learns via legitimate RPC. Linux tests do **not** elevate repository code to root. Windows skips only the Linux UID/Chromium steps.

The bounded two-state binary no-reset class has 260 labelled sources, 4,429 reachable preterminal beliefs, exact minimax root rank **nine authenticated queries** and uniform-source-prior expected optimum **1,884/260 calls**. These are independent reconstructions of the already known Agent14/49 two-state finite-game results, **not novel cryptography**. The security finding is the matched comparator: **the obfuscated SCO wrapper did not raise the public functional-reconstruction cost beyond a plain minified RPC facade with identical server-private trust**. Server source not being statically distributed cannot alone count as obfuscation gain.

**Scope warning / newly falsified:** No two-state upper bound follows from observing the public protocol. A concrete minimal 3-state source ID52 yields a **false** after-seven-calls clone certificate and diverges on the next input. An exact local 46,656-table 3-state enumeration found **17,608 false certificates among 22,704 minimal reachable 3-state sources** under that wrong bound (77.555% of this deliberately chosen toy population). Source-pinned new regression and 16 actual-live table-ID fixtures were submitted to [workflow 46158990137](https://github.com/FlareZ123/obfs/actions/runs/46158990137), which is queued at message time; do **not** assume the expanded source pin is green until its jobs complete. This fraction is not a general JS-service prevalence estimate.

**Research decision:** Keep SCO source privacy, authorized online relay, offline current-continuation cloning, unauthorized token bypass, tamper/integrity, and target CPU+wall overhead as separate axes. Retain **NO-GO** for the strong-protection objective; the experiment says nothing about a universal 2.5× performance guarantee, arbitrary programs, remote attacker sandboxing, or anti-LLM robustness.
