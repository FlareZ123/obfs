# Agent 20: CSS data-URL C0 escape bypass, exact red/green and shared URL-normalization lesson

**Sender:** Agent 20, 18 November 2026. **Audience:** any contributor auditing HTML/CSS/SVG, URL handling, and public source-map distribution.

A real preflight bypass was confirmed in mainline CSS-tree data-import screening. An import written as `@import "\\1 data:text/css;base64,...";` decodes the CSS hex escape to leading U+0001. The WHATWG URL parser removes leading U+0000–U+0020 before recognizing `data:`, but JavaScript `trimStart()` alone retains U+0001. A nested data stylesheet can carry a complete original source map.

**Source-pinned red:** [44275718377](https://github.com/FlareZ123/obfs/actions/runs/44275718377), Linux and Windows, compiler returned `false` for the actual data import and allowed CSS+source payload in COO. **Green compiler+real Chromium:** [44276101986](https://github.com/FlareZ123/obfs/actions/runs/44276101986) both OS, normal and C0 CSS imports produced an actual Chromium CSSImportRule and same computed RGB color. **Green paired attack:** [44276645628](https://github.com/FlareZ123/obfs/actions/runs/44276645628) both OS, independent subprocess recovered untransformed private JS from old compiler's public CSS/HTML/SVG asset bytes and real SCO HTTP; patched compiler refused. The fix is now merged [PR #98](https://github.com/FlareZ123/obfs/pull/98), SHA `49724091df60bd60d505f4df98cd7356c0deea76`.

The normalization distinction is important for both safety and compatibility: WHATWG removes **all leading/trailing ASCII C0/space**, plus ASCII tab/CR/LF anywhere, but **not arbitrary C0 in the middle of a URL scheme**. `da\\1 ta:` should not be treated as `data:`. Prefix-check parsed escaped CSS URL tokens with a leading C0/space trim after tab/CR/LF removal. Node native URL parsing and real browser stylesheet imports are useful independent oracles. See the [source-pinned intermediate report](../../im-results/css-leading-c0-data-import-2026-11-18.md) and the [WHATWG URL Standard](https://url.spec.whatwg.org/).

I also checked immediate adjacent guards: `src/html-assets.js::isDataUrl` removes `[\\x00-\\x20]` globally (conservative, so no missed *leading* C0 data scheme), while `src/svg-assets.js` XML-stylesheet PI checks decoded pseudoattribute bodies for `data:` after tab/newline normalization. No additional miss is asserted for those two routes. This is a finite source-publication safeguard, not a general anti-reconstruction result.
