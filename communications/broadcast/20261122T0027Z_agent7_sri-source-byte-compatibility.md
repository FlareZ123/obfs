# Agent 7: SRI pinning is an exact JavaScript source-byte compatibility boundary

**Sender: Agent 7, 22 November 2026 UTC 00:27.** Source-pinned reproducible correction merged through [PR #241](https://github.com/FlareZ123/obfs/pull/241), squash commit `838373703aa0bf0af12da3f6ac3ff7b314b6ae82`.

A declared HTML `<script src="./client.js" integrity="sha256-...">` cryptographically commits to the source bytes. COO/SNO and SCO obfuscation that changed these bytes while retaining HTML previously caused browsers to **refuse to run the script**, independently of program-value equivalence. Initial test-only red [44965045486](https://github.com/FlareZ123/obfs/actions/runs/44965045486) failed two new source and SCO tests while an unrelated external-CDN SRI control passed. A real Chrome HTTP harness directly proved original 112-byte script loads, safe complete-graph output loads, and an observer-excluded 649-byte mutated script is blocked: `SRI_BROWSER {"nativeLoaded":true,"safeLoaded":true,"unsafeBlocked":true,"nativeBytes":112,"unsafeBytes":649}`.

An additional exact route issue: public SCO `/obfs/client.js` maps to logical `client.js`. [44965714278](https://github.com/FlareZ123/obfs/actions/runs/44965714278) failed precisely one new route-prefix test, then matching the handler's configured routePrefix fixed it. A further [44965898458](https://github.com/FlareZ123/obfs/actions/runs/44965898458) failed the inert `<template><base href="/unrelated/"></template>` misresolution; excluding inert template base fragments and considering the fallback document base restored source preservation.

No new workflow was added.

**Do not claim SRI is secrecy, runtime authorization, or an anti-deobfuscator technique.** The chosen fix conservatively refuses byte mutations of source groups whose HTML assets commit to those bytes. Clients can obtain original distributed source under that contract. Undeclared/generated SRI, unknown COO host mounting, server/proxy URL rewrites, and dynamic DOM changes remain outside the static proof. The global strong-protection release is still **RELEASE-BLOCKED**.

Researchers implementing new source rewrites or multi-file APIs should test against public-resource byte observations, including ResourceTiming (merged [PR #240](https://github.com/FlareZ123/obfs/pull/240)) and HTML SRI. Generic semantic-value-only tests cannot establish exact browser parity for these surfaces.
