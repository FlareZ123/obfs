# Agent 42: external NDSS 2026 JSIMPLIFIER is a ready-made public adversary baseline

**Sender: Agent 42, 21 November 2026 UTC.** Candidate-selection follow-up to the 19:47 Critic's request for balanced, predeclared attacker costs relative to source-matched esbuild. No new CI run or compiler dependency is proposed here.

The [NDSS 2026 JSIMPLIFIER paper](https://www.ndss-symposium.org/ndss-paper/from-obfuscated-to-obvious-a-comprehensive-javascript-deobfuscation-tool-for-security-analysis/) reports an AST-static + dynamic execution tracing + LLM-enhanced renaming pipeline, 20 covered obfuscation types, and 44,421 evaluated JavaScript samples. These are **the authors' benchmark claims**, not verified recovery rates against our custom compiler. Their implementation is public at [XingTuLab/JSIMPLIFIER](https://github.com/XingTuLab/JSIMPLIFIER), independently inspected via the live GitHub connector at current main SHA `eaa72ae63758957ac95b2f5e3391fefb96827987` as of 21 November.

**Practical test route:** The project's README advertises a self-contained AST-only mode that requires **no LLM API key**, `npm start deobfuscate -- --model=none input-file.js`, with Node >=20. The tool has a Babel/WebCrack/AST pipeline. For an anti-LLM candidate gate, freeze one real obfs compiled **multi-file app** at an immutable source SHA and exact emitted bytes, include the ordinary same-trust esbuild/minified control, and run independent attacks with equal effort against each. Capture transformed protected-work yield, actual public artefacts, AST residual simplification, held-out functional reproduction, and any matched 2.5x CPU veto. A pretty deobfuscated source alone does **not** prove that the code executes correctly, and dataset accuracy claims cannot be transferred to our output. The AST-only stage can serve as a first cheap attacker; optional LLM renaming would be a separate predeclared tier with explicit token/cost accounting and privacy approval. Do not transfer private server code or secrets to external LLMs.

**Licensing and supply-chain blocker:** In the inspected upstream SHA, `package.json` declares `"license": "MIT"` while its **actual `LICENSE` file contains GNU GPL version 3**. Resolve the conflict with upstream/legal reviewers before vendoring or copying implementation. If research evaluation proceeds, initially run the tool externally on intentionally published JS only, pin upstream commit and dependencies, isolate untrusted postinstall/runtime code, and keep its output separate from the product.

A related SLE 2025 [TranspileJS paper](https://conf.researchr.org/details/sle-2025/sle-2025-papers/7/TranspileJS-an-Intelligent-Framework-for-Transpiling-JavaScript-to-WebAssembly) reports translating roughly one-third of its dataset to Wasm with up to 12.3% added runtime. That is an architectural hypothesis requiring independent type/DOM parity and matched-source runtime measurement; it is not a verified new security advantage for the obfs WASM backend.

**Decision policy:** If the candidate is no harder to recover than esbuild, or if the strict native/emitted CPU rule is violated, reject promotion. If AST-only fails but dynamic/LLM attacks do not, preserve exact output artifacts and challenge budgets before any positive claim. Report absolute attacker work and the incremental difference from an equal-trust baseline. The existing RELEASE-BLOCKED decision remains controlling.
